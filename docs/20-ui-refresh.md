# 20. モデル選択の整合・キュー管理の拡充・生成ページの再構成(v0.12)

> 注(2026-11-20): キュー画面(`/queue`)は 27 で廃止し、§3 の機能は生成ページの右サイドへ移した。§4.1 のヘッダのリンク先も生成ページ(`/`)になった。
> ステータス: 🟢 承認済み(2026-11-19。Q-89〜99 は推奨どおり確定。07 の Q-89〜99)。実装済み(M16。実機・画面の確認は 09 の検証ログ)。
> 経緯: モデルの種類が増えた(16・17)結果、(1) モデル種別とモデルの組み合わせがちぐはぐになりうる、(2) キュー画面が簡素で管理しにくい、(3) 生成画面の「実行状況・直近の結果」はキュー画面と重複している、という指摘を受けた。3 点をまとめて整理する。

## 1. 目的とスコープ

**やること**
- **M16-A モデル選択の整合**: 種別に合うモデル・テキストエンコーダ・VAE だけを選択肢に出す。合わない組み合わせは作れなくし、作られた場合(古いプリセット等)は投入時に断る。
- **M16-B キュー管理の拡充**: フィルタ・検索・サムネイル・詳細表示・一括操作・個別削除・一時停止・再生成・設定の読み込みを加える。
- **M16-C 生成画面の再構成**: 実行状況と直近の結果(`ResultPanel`)を外し、空いた領域を **生成の補助**(モデルの説明、参照画像の大きな表示、目安の時間、プロンプト履歴)に使う。実行状況は、画面共通の小さな表示(ヘッダ)で見られるようにし、詳細はキュー画面へ誘導する。

**やらないこと(v0.12)**
- ジョブのドラッグ&ドロップ並べ替え(ボタン操作のまま。先頭へ・末尾へを加える。Q-93)。
- 生成中のプレビュー画像、複数画像の同時生成の並列化、ComfyUI 側のキューの直接操作。
- ファイルの中身(safetensors のヘッダ)によるモデル種別の自動判別(Q-89。必要になれば別設計)。

## 2. M16-A モデル選択の整合

### 2.1 現状の問題

- `sd15` と `sdxl` は、同じ `checkpoints` 一覧を共有する(SDXL 用のファイルを SD 1.5 のまま選べる)。
- `flux` / `anima` / `qwen_image` / `krea2` は、同じ `unets` 一覧を共有する。テキストエンコーダ・VAE も共有で、組み合わせの間違いが起きやすい。
- 結果として、ComfyUI の実行時エラー(形状の不一致など)で初めて気づく。

### 2.2 方針: カタログから「ファイル → 使える種別」を決める

- カタログ(`catalog.json`)の各ファイル(`fileName`)は、所属ファミリーから使える種別が分かる(`familyKinds`。18 §3)。**同じファイルが複数ファミリーにあれば、種別の和集合**(例: `qwen_image_vae.safetensors` は Anima と Krea 2)。
- `lib/generation/compat.ts`(新規)に、次の純粋関数を置く。
  - `fileKinds(catalog)`: ファイル名(小文字)→ 使える種別の集合。
  - `modelsForKind(kind, models, catalog)`: 種別ごとの本体の選択肢。**カタログで他の種別のものと分かるファイルは除く**。カタログにないファイル(手動配置)は、同じ一覧を持つ種別すべてに出し、バッジ「カタログ外」(18 §5)を付ける(Q-89)。
  - `clipsForKind` / `vaesForKind`: テキストエンコーダ・VAE も同様に絞る。
- `autofill`(自動補完)・「推奨設定の適用」・AI のモデル提案の反映・プリセット/再現の復元は、**絞った一覧**を基準にする。復元した設定の本体・エンコーダ・VAE が絞った一覧に無ければ、一覧の先頭(推奨の導入済み)に差し替え、トーストで知らせる(これまでの「存在しない場合の差し替え」と同じ扱いに、理由を加える)。

### 2.3 種別の選択

- 種別のドロップダウンは、**導入済みのモデルがある種別だけ選べる**ようにする。無い種別は「(未導入)」と表示して選べなくし、モデル取得ページへの導線を出す(Q-90)。現在選択中の種別は、未導入でも表示する(復元した設定で壊れないように)。
- 本体を選ぶ側のドロップダウンは、種別ごとの絞った一覧(§2.2)。0 件のときは、従来どおりの案内(`generate.model.none`)と取得ページへの導線。

### 2.4 投入時の検証(Rust)

- `job_enqueue` で、**カタログで種別が分かるファイルが、選択した種別と合わない場合は `VALIDATION`**(`details.field` は `model` / `clip` / `vae`、メッセージは「このモデルは ○○ 用です」)で断る(Q-91)。カタログにないファイルは検証しない(従来どおり)。
- 既に `catalog()`(`services/assistant/capabilities.rs` の `OnceLock`)でカタログを持っているため、同じ読み込みを使う。

### 2.5 テスト

- Vitest: 同じファイルが複数ファミリーに属する場合の和集合、カタログ外ファイルの扱い、種別の切り替え時の再選択、未導入の種別が選べないこと。
- Rust: 不一致の拒否(SD 1.5 に SDXL のファイル等)、カタログ外ファイルの通過、共有 VAE の許可。

## 3. M16-B キュー管理の拡充

### 3.1 一覧

- **フィルタ**(タブ): すべて / 実行中・待機 / 完了 / 失敗・キャンセル。各タブに件数を表示する。
- **検索**: プロンプト・モデル名で絞り込む(クライアント側)。
- **上部サマリ**: 実行中ジョブの進捗(ステップ・経過時間・残り時間の目安)、待機件数、完了・失敗の件数。実行中の進捗はここで確認できる(生成画面からは外す。§4)。
- **履歴の追加読み込み**: 既存の `job_list` の `cursor` を使い、「さらに読み込む」で続きを取得する(現状は 200 件まで)。

### 3.2 行(ジョブ)

- **サムネイル**: 生成済みの画像(最大 4 枚)を小さく表示する。クリックでギャラリーの詳細を開く(`/gallery?id=`)。未生成・失敗のものは出さない。
- **詳細の展開**: 行を開くと、次を表示する。プロンプト・ネガティブ・モデル・サンプラー・スケジューラ・ステップ・CFG・シード・サイズ・枚数、有効な拡張(画像から生成・ControlNet・Inpaint・顔補正)、所要時間(`startedAt`〜`finishedAt`)、エラー。
- **操作**:
  - 待機中: 上へ・下へ・**先頭へ・末尾へ**、キャンセル。
  - 実行中: キャンセル。
  - 完了・失敗・キャンセル: **もう一度生成**(同じ設定を、新しいシードで投入。失敗・キャンセルは従来の「再試行」= 同じシード)、**この設定を生成画面に読み込む**(`loadParams`。「この設定で生成」と同じ)、**履歴から削除**。
- 複数選択(チェックボックス)で、**選択をキャンセル / 再試行 / 履歴から削除**を一括で行える。

### 3.3 一括・キュー全体の操作

- **待機中をすべてキャンセル**、**失敗をすべて再試行**(確認ダイアログあり)。既存の「履歴クリア」(`job_clear_finished`)は残す。
- **一時停止 / 再開**(Q-92): 実行中のジョブは完了まで続け、**次のジョブを始めない**。状態はアプリ起動中のみ保持(再起動で再開状態に戻る)。画面の上部に「一時停止中」を常に表示する。

### 3.4 IPC(04 に追記する内容)

| コマンド | 引数 | 戻り値 | 説明 |
|---|---|---|---|
| `job_remove` | `{ ids: string[] }` | `number` | 終了済み(完了・失敗・キャンセル)のジョブを、履歴から外す。画像を持たないジョブは削除、画像を持つジョブはキュー画面から隠す(`job_clear_finished` と同じ扱い。03)。実行中・待機中が含まれていたら `VALIDATION` |
| `queue_pause` / `queue_resume` | – | `void` | 次のジョブを始めるのを止める/再開する |
| `queue_state` | – | `{ paused: boolean }` | 現在の状態 |

- イベント `queue://state`(`{ paused }`)を追加する。DB スキーマの変更は不要(`job_remove` は既存の「隠す」仕組みを使う。実装時に 03 の列を確認する)。

### 3.5 テスト

- Rust: `job_remove` の対象検証・画像あり/なしの扱い、一時停止中は次のジョブを始めないこと、再開で続きが実行されること。
- Vitest: フィルタ・検索・一括選択のロジック、サムネイルの取得対象、経過・残り時間の計算。

## 4. M16-C 生成画面の再構成

### 4.1 外すもの

- `ResultPanel`(実行状況・直近の結果)を生成画面から外す。`job-store` の `recentImages` は、他に使われていなければ削除する(使用箇所は実装時に確認)。
- 実行状況の確認は、**画面共通のヘッダ(新規)**に出す小さな表示にする。実行中のとき「生成中 12/25 · 待機 2」と細い進捗バーを出し、クリックでキュー画面を開く(Q-97)。生成の投入時は、従来どおりトースト「キューに追加しました」(キュー画面への移動ボタン付き)。

### 4.2 右側のワークスペース(拡充)

生成画面を 2 カラムのままにし、右側を「生成の補助」にする(上から順に。Q-96)。

1. **モデルの説明**: 現在はフォーム内にある説明パネル(18)を、右側に常時表示する(要約・得意/不得意・対応機能・[推奨設定を適用]・[AI に相談])。フォームの縦の長さを短くする。
2. **参照画像ワークスペース**: 画像から生成・ControlNet・Inpaint の参照画像を **大きく**(右側の幅いっぱい)表示する。複数あるときはタブで切り替える。Inpaint のマスクは、ここでも確認でき、マスクエディタを開ける。縦横比と生成サイズ(丸め後)を重ねて表示する。
3. **この設定の目安**: 選択中のモデル・サイズ・ステップから、**過去の実績**(同じ種別・近いサイズのジョブの所要時間の中央値)を使って「1 枚あたり約 N 秒、投入分で合計約 M 分」を表示する。実績が無ければ、モデルの説明の `resources.speed` から「速い / ふつう / 遅い」の目安だけを出す(Q-98)。
4. **プロンプト履歴**: 過去に投入したプロンプトを、新しい順に一覧で表示する(ジョブの `params` から取得。重複は除く)。クリックで、プロンプト・ネガティブを入力欄へ入れる(「追加」「置き換え」を選べる)(Q-99)。

- フォーム(左)も、セクションを折りたためるようにして(基本・モデル・サイズ・拡張機能)、縦の長さを抑える。折りたたみの状態は、アプリ内に保存する(`localStorage` ではなく、設定の下書きと同じ保存先。実装時に決める)。
- 画面が狭い(`lg` 未満)ときは、右側のワークスペースをフォームの下に積む(現行の挙動と同じ)。

### 4.3 テスト

- Vitest: 目安時間の計算(実績の中央値・実績なしのフォールバック)、プロンプト履歴の重複除去・並び順。
- 手動(09 に追加): 生成の投入 → ヘッダの進捗 → キュー画面での確認、参照画像ワークスペースの表示と切り替え、狭い画面での配置。

## 4.4 実装時の判断(設計との差異)

- **フォームの折りたたみ**: 折りたためるのは「拡張機能」(画像から生成・Inpaint・ControlNet・顔補正)のグループだけ。基本・モデル・サイズは常に表示する。**折りたたみ状態は保存しない**(開いた状態で始まる)。
- **一時停止・再開のボタン**はキュー画面のみ。ヘッダは「一時停止中」の表示と、キューへの導線だけ。
- **Inpaint のマスク表示**: 参照画像ワークスペースでは、マスクの白い範囲を赤く重ねて表示する(CSS のマスク)。マスクの編集は既存のマスクエディタを使う。
- **検索**はクライアント側(読み込み済みの履歴が対象)。「さらに読み込む」で続きを取得してから検索する。
- **目安時間**の対象は、同じ種別で画面の面積が 0.7〜1.4 倍の完了ジョブ(1 ジョブの所要時間を枚数で割った値の中央値)。
- **モデルの絞り込み**は、カタログが未取得の間は行わない(取得後に自動で再適用する)。
- **ジョブ行の「もう一度生成」**は、同じ設定で `seedRandomize: true`(新しいシード)で 1 件投入する。

## 5. 実装の分割(マイルストーン M16)

1. M16-A: `compat.ts` と、フォーム・復元・AI 提案の絞り込み、Rust の投入時検証。
2. M16-B: `job_remove`・一時停止の Rust 実装と IPC、キュー画面の作り直し。
3. M16-C: ヘッダの進捗表示、`ResultPanel` の撤去、右側ワークスペース。
4. 09 のチェックリスト追加と、実機での検証ログ。

## 6. リスク

- 絞り込みで、手動配置のモデルが「カタログ外」として全種別に出る(誤選択の余地が残る)。→ バッジとプロフィールの「カタログ外」表示で補う。厳密な判別が必要なら、別設計でファイルの中身から種別を判定する(Q-89)。
- キュー画面の行が増えて、画面が重くなる。→ 履歴は 200 件ずつ読み込み、サムネイルは表示された行だけ取得する。
- 一時停止の状態が、アプリ再起動で失われる。→ 仕様として明記し、上部に常に表示する。
