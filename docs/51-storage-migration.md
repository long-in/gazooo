# 51. 保存先のデータ移行(画像・モデル)(v0.52)

> ステータス: 🟢 承認済み・実装済み(2026-11-26。07 Q-439〜444 は推奨どおり。**画面の目視確認・実機での移行・macOS は未実施**。差異は §10)。
> **追記(2026-11-26)**: 画像の移行の対象(§1・§3・§4.3)は、[52](52-global-and-user-settings.md)(承認済み・実装済み)で全体の移行へ改めた。
> **経緯**: ユーザー要望「保存先を変更できるが、変更先へデータを移行する機能が欲しい。移行先を設定して移行を実行し、そのあと移行先をデフォルトにする UI」(2026-11-26)。対象は **画像とモデルの両方**。

## 1. 現状と問題

| 対象 | 現状 | 足りないもの |
|---|---|---|
| 画像の保存先(ユーザーごと) | 設定 > 保存先で [変更] → フォルダ選択 →「移動する / 移動しない」(`storage_change_images_dir`) | 移行の流れが画面から分かりにくい。開始前の確認(件数・容量・空き)、進捗、中止がない |
| モデルの保存先(全ユーザー共通) | モデル画面の [変更](`models_set_dir`)。**設定を変えるだけでファイルは移らない** | 移行機能そのもの |

画像の移動には、コード上、次の弱点もある(実機では未再現)。移行の作り直しで合わせて直す。

- 移動の開始時に実行中のジョブがないことは確認するが、**移動中に待機ジョブが始まるのは止めていない**。対象の一覧は開始時点のものなので、移動中に生成された画像は旧フォルダに残り、表示できなくなるおそれがある。
- 同じフォルダかどうかをパスの文字列で比較している。大文字・小文字の違いやリンク経由で **同じ実体** を指定すると、自分自身へのコピーになり、ファイルが壊れるおそれがある。
- コピー先の同名ファイルは上書きし、失敗しても元に戻らない。

## 2. 目的とスコープ

**やること**
- 画像とモデルを、同じ流れ「**移行先を選ぶ → 内容を確認 → 移行を実行 → 移行先が以後の保存先になる**」で移行できるようにする。
- 開始前の確認、進捗表示、中止を付ける。

**やらないこと**
- 移行するファイルを選ぶこと(一部だけの移行)。
- 同じドライブ内の「名前の変更」による高速な移動(Q-441)。
- アプリを閉じたあとの自動再開。
- ローカル LLM・翻訳モデル・ComfyUI 本体・アプリの DB の移動。

## 3. 画面(05 への追記)

### 3.1 入口: 設定 >「保存先」タブ

2 枚のカードを並べる。

```
画像の保存先
  D:\...\images
  [データを移行…]  移行せずに保存先だけ変更  既定に戻す…

モデルの保存先(すべてのユーザーに共通)
  C:\...\ComfyUI\models   [自動検出]
  [データを移行…]  移行せずに保存先だけ変更
```

- [データを移行…] が主ボタン。
- 「移行せずに保存先だけ変更」は、すでに手でファイルを移した場合や、中身のある別のフォルダに切り替える場合のために残す。画像では「今の画像は表示されなくなる」という確認を挟む。
- 画像の「既定に戻す…」は、既定の場所を移行先にして §3.2 を開く(保存先だけ戻すことも、そこから選べる)。
- モデル画面の保存先欄はそのまま残し、[データを移行…](設定の保存先タブへ移動)を足す。
- モデルの保存先が特定できないとき(未接続の自動検出など)は、モデルの [データを移行…] を無効にして理由を示す。

### 3.2 移行ダイアログ(画像・モデル共通)

1. **移行先を選ぶ**: フォルダ選択。
2. **確認**: 移行元と移行先、ファイル数、合計サイズ、移行先の空き容量、注意と開始できない理由(§5)。[移行を開始] / [キャンセル]。
3. **実行中**: 進捗バー(バイト数)、処理中のファイル名、段階(コピー中 → 保存先を切り替え中 → 元のファイルを整理中)、[中止]。ダイアログは閉じられず、ほかの操作はできない。[中止] できるのはコピー中だけ。
4. **結果**: 「移行が完了しました。以後は移行先に保存します」。移したファイル数、見つからなかった数、ゴミ箱へ移せなかったファイルがあれば件数と旧フォルダのパス。モデルでは §6 の ComfyUI への反映結果も示す。

- 実行中にアプリを閉じようとしたら確認する。閉じた場合は §4.2 の扱いになる。

## 4. 移行の動作

### 4.1 手順

**事前確認 → コピー → 検証 → 保存先の切り替え → 元のファイルを OS のゴミ箱へ**(現在の画像の移動と同じ順)。

- コピーは一時名(`<ファイル名>.gazooo-migrating`)に書き、サイズの一致を確認してから正式な名前に変える。
- 検証は **サイズの一致** まで(Q-440)。
- 移行先の同名ファイル:
  - サイズが同じ → コピーしない。**中身が同じとは確かめていないので、元のファイルはゴミ箱へ移さず残す**。件数を結果に出す。
  - サイズが違う → **開始できない**(該当ファイルを一覧で示す)。上書きはしない。

### 4.2 中止・失敗・中断

- **中止・コピー失敗**: 今回作ったファイルと一時ファイルを消す。保存先の設定と元のファイルは変わらない。
- **切り替えの失敗**: 同上。
- **ゴミ箱への移動の失敗**: 移行は成功とする。残ったファイルを結果に出す。
- **強制終了・電源断**: 切り替え前なら保存先は元のままで、元のファイルもそろっている。もう一度実行すると、コピー済みのファイルは飛ばし(元も残る)、一時ファイルは上書きする。

### 4.3 移行対象

| 対象 | 移すもの |
|---|---|
| 画像 | ログイン中のユーザーの原寸・サムネイル(DB の記録)と `inputs/`(現在と同じ範囲)。保存先にあるそれ以外のファイルは移さない |
| モデル | 次のサブフォルダの中の **すべてのファイル**(手で置いたモデル、取得途中の `.part` を含む): `checkpoints` `clip` `text_encoders` `vae` `unet` `diffusion_models` `loras` `controlnet` `ultralytics`。相対パスは変えない |

- モデルで上記以外のフォルダ(`upscale_models`・`embeddings` など)は、アプリが ComfyUI に参照先を伝えていないので **移さない**。中身があれば確認画面で「移らないフォルダ」として示す(Q-442)。
- リンク(シンボリックリンク・ジャンクション)は、たどらず移さない。確認画面で件数を示す。

## 5. 開始できない条件と注意

**開始できない**
- 移行先が相対パス、書き込めない、空き容量が足りない(コピーする合計の 1.1 倍未満)。
- 移行先が移行元と同じ実体、または内側・外側の関係にある(**正規化した実体のパス**で判定し、Windows・macOS では大文字・小文字の違いも同じとみなす)。
- 移行先にサイズの違う同名ファイルがある。
- 画像: 移行先がアプリのデータ領域の中にある(自分の既定の保存先は除く。ほかのユーザーの領域との混在を防ぐ)。
- 生成ジョブが実行中。
- モデル: ダウンロードが実行中・待機中。
- バックアップ・復元・別の移行が実行中。

**移行中に止めるもの**
- ジョブのワーカーは、待機ジョブを始めない(待機のまま残し、移行後に再開)。
- 画像の取り込み・削除、モデルの取得、バックアップ・復元、ログアウト・ユーザー切り替え、ComfyUI の起動・導入は、Rust 側で `STORAGE_BUSY` として断る。ComfyUI の自動復旧(47)も止める。

## 6. モデル移行と ComfyUI

移行先を保存先にするだけでは ComfyUI はモデルを見つけられないため、次を行う。

1. **開始前**: 現在の ComfyUI の起動引数から、反映できるか(`can_apply` の判定。08 §6.2)を調べて保持する。
2. **停止**: アプリが起動管理している ComfyUI が稼働中なら、確認画面で知らせたうえで停止する。手動で起動した ComfyUI は、停止するよう注意を出す(稼働中はモデルのファイルが使われていて、ゴミ箱へ移せないことがある)。
3. **切り替え後**: `models_dir` を移行先にし、`extra_model_paths.yaml` を **自動で反映** する。停止した ComfyUI は再起動する。手動起動の場合は再起動を案内する。
4. **反映できない場合**(リモート、`main.py` を特定できない、ユーザー自身の yaml がある): 確認画面で理由を示す。移行はできるが、**元のファイルはゴミ箱へ移さず残し**、ComfyUI の設定を手で直す必要があることを示す(Q-443)。独自の `--extra-model-paths-config` を使っている場合も同じ扱いにする。

- 反映や再起動に失敗しても、移行は取り消さない。結果画面に失敗を示し、モデル画面の [ComfyUI に反映] でやり直せる。
- `extra_model_paths.yaml` の対応表を直す。今は `text_encoders` → `clip/`、`diffusion_models` → `unet/` だけなので、相対パスを変えずに移すと `text_encoders/`・`diffusion_models/` のファイルが読まれなくなる。両方のフォルダを複数行で指定する。旧形式で反映済みのファイルは、引き続き「反映済み」とみなす。

## 7. IPC(04 への追記)

| コマンド | 引数 | 戻り値 |
|---|---|---|
| `storage_migration_plan` | `{ target: "images" \| "models"; newDir: string \| null }`(null は画像の既定。モデルでは不可) | `MigrationPlan`(何も変更しない) |
| `storage_migration_start` | 同上 | `MigrationReport`(完了まで返らない) |
| `storage_migration_cancel` | – | – |
| `storage_change_images_dir` | `{ newDir: string \| null }`(**`moveExisting` を廃止**。保存先の切り替えだけ) | – |

```ts
interface MigrationPlan {
  sourceDir: string; destDir: string;
  fileCount: number; totalBytes: number; copyBytes: number; freeBytes: number | null;
  sameSizeCount: number;            // 移行先にあり、コピーしない数
  conflicts: string[];              // サイズ違いの同名(相対パス)
  skippedFolders: string[];         // モデル: 移らないフォルダ
  skippedLinks: number;
  blockers: string[];               // 開始できない理由のコード
  engine?: { managedRunning: boolean; canApply: boolean; reason?: string }; // モデルのみ
}
interface MigrationReport {
  moved: number; missing: number; keptSameSize: number;
  leftInSource: number;             // 元に残したファイル数
  engineApplied?: boolean; engineRestarted?: boolean; engineError?: string; // モデルのみ
}
```

- イベント `storage://migration-progress`: `{ phase: "copying" | "switching" | "cleaning"; doneBytes; totalBytes; doneFiles; totalFiles; currentFile? }`(コピー中は最大 4 回/秒)。大きいファイルの途中も進むように、分割してコピーする。
- `start` は事前確認をやり直す(確認後に状況が変わった場合に備える)。
- 追加エラーコード: `STORAGE_BUSY`、`STORAGE_CANCELLED`、`STORAGE_NO_SPACE`、`STORAGE_CONFLICT`。
- 画像の移行成功時は、移行先を asset プロトコルのスコープに追加する(現在と同じ)。
- DB スキーマの変更と、依存の追加はない(空き容量は既存の `fs4`)。

## 10. 実装時の差異・補足

- IPC: `MigrationPlan` に `missing` と `engine.externalRunning`(手動起動の ComfyUI の注意に使う)、`MigrationReport` に `sourceDir`・`destDir` を足した。`engine.reason` は `remote` / `engine_unknown` / `foreign` / `custom_config`。終了の確認のため、`storage_migration_quit` とイベント `storage://close-requested` を足した。
- 開始できない条件に「移行元のフォルダが見つからない」を足した(ドライブが外れた状態で、0 件のまま保存先が切り替わるのを防ぐ)。
- ComfyUI が置く目印の空ファイル(`put_…_here`)と、前回の中断で残った一時ファイルは移さない。
- ComfyUI が停止していても、起動管理が有効なら、設定の `main.py` の場所から反映先を決める。
- 移行中の拒否は、IPC の入口 1 か所で行う。`job_enqueue` は断らない(待機のまま残り、移行後に始まる)。
- Vitest は、ダイアログの段階の遷移をストア(`migration-store`)で試験した。DOM のテスト環境が無いため、コンポーネントテストは追加していない。
