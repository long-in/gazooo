# 24. Qwen-Image 2.1 の参照画像入力(画像編集、v0.16)

> ステータス: 🟢 承認済み・実装済み(2026-11-20。Q-116〜123 は推奨どおり。§2 の実機確認で確定してから実装。実装時の判断は §10)。
> **経緯**: 「Qwen-Image 2.1 は画像参照が使えるようなので確認してほしい」という要望(2026-11-20)。調査の結果、**使える**ことを確認した(§2)。17 §1 で「やらないこと」にしていた参照画像入力(画像編集)と、19 §1 で「別の設計とする」としていた方式 C(Q-82。画像編集モデルによる「指示だけの変換」)を、本資料でまとめて設計する。

## 1. 目的とスコープ

**やること**
- **F-19 参照画像つき生成(画像編集)**: `qwen_image` 種別で、参照画像を 1 枚以上与え、プロンプトで「参照画像をどうするか」を指示して生成する。
  - 例: 「`<image1>` の人物とポーズはそのまま、アニメ調のイラストにする」「`<image1>` の人物に `<image2>` の服を着せる」。
- 参照画像の枚数に応じた UI(サムネイルと番号の表示、プロンプトへの `<imageN>` の挿入)。
- ~~「指示だけでアニメ調に」のかんたん開始(§3.1)~~ → **廃止(07 Q-344)**。

**やらないこと(v0.16)**
- `qwen_image` 以外の種別(Anima・Krea 2・Flux 系・SD 系。Krea 2 の LoRA による参照も対象外のまま)。
- `QwenImage21Cache`(KV キャッシュ。experimental)の画面設定(§4.3。使わない)。
- プロンプトの自動書き換え(`TextGenerate`・`refine_prompt`。17 §1 のまま)。
- 色マーク(参照画像にペンで色を塗り、プロンプトで色名を指す領域指定)。専用のマスクエディタ(13)とは別物なので、まず対象外にする。
- Turbo・Lightning 系の LoRA、非公式の VAE(テクスチャ補正版)。
- 参照画像からのプロンプト自動生成(19 Q-86 のまま)。画像を外部へ送らない方針を維持する。

## 2. 調査結果(2026-11-20。ComfyUI の公式資料による)

出典: [TextEncodeQwenImage21(Comfy docs)](https://docs.comfy.org/built-in-nodes/TextEncodeQwenImage21)、[Qwen-Image 2.1 チュートリアル](https://docs.comfy.org/tutorials/image/qwen/qwen-image-2-1)、[ComfyUI Wiki](https://comfyui-wiki.com/en/news/2026-09-21-qwen-image-2-1)。いずれも **ComfyUI のコアノードのみ**(カスタムノード不要)。

**`TextEncodeQwenImage21`(txt2img で既に使っているノード)の参照画像まわり**

| 項目 | 内容 |
|---|---|
| 入力 `images` | 任意。`image_1`〜`image_16` のスロット(増やせる)。資料により最大が 10 / 16 と食い違う(実機で確認。§9 の確認項目) |
| 入力 `vae` | 任意。つなぐと参照画像が **参照 latent** としてもエンコードされ、条件(positive / negative)に載る。つながないと、テキストエンコーダ経由の条件づけだけになる |
| 入力 `resolution` | 既定 1024、0〜4096、刻み 32。参照画像を **総画素数がおよそ resolution × resolution** になるよう縦横比を保って縮小し、32 の倍数に丸める(幅や高さの上限ではない)。0 は各画像を元のサイズ(32 の倍数に丸め)のまま使う |
| 出力 `latent` | **1 枚目の参照画像のサイズ** の latent(参照が無いときは resolution 由来)。**この latent で KSampler を回す**(別のサイズにすると編集がずれる) |
| プロンプトでの指し方 | スロット順に `<image1>` `<image2>`…(例: 「`<image1>` の人物とポーズは変えず、`<image2>` の水色のデニムシャツを着せる」) |

**編集時の推奨値**: 25 ステップ・CFG 1・`euler` / `simple`(t2i と同じ)。単純な部分編集は 4〜8 ステップでも可、全面的な書き換えは 25、細部は 30 前後。CFG は 1 が公式の経路(1 ではネガティブは効かない。2 は指示に忠実だが過鮮鋭、5 以上は破綻)。

**注意点(公式資料・報告より)**
- 出力のサイズは **1 枚目の参照画像で決まる**。`resolution` を 0 にすると約 12MP(3000×4000 → 3008×4000)になり非常に重い。1024 で約 1MP(896×1184 程度)。モデルの学習サイズは 2K で、4K 級は指示への追従が落ちる。
- 参照を何枚も大きく与えると遅くなる。
- 標準の VAE は、写真調の出力に市松状の模様が出ることがある(非公式の補正 VAE があるが、本設計では扱わない)。
- VAE のデコードは 4 チャンネル(アルファ付き)を返す。`SaveImage` はそのまま保存できるはずだが、**実機で確認する**(§9)。
- 画風の指定を **参照画像で** 渡す方法は、テキストでの画風指示ほど安定しない(ComfyUI Wiki)。アニメ調への変換は、「アニメ調にする」とプロンプトで **言葉で指示する** 前提にする。

**実機で確定した事項(2026-11-20。開発機の ComfyUI 0.45.6・同梱テンプレート 0.11.11 による。§9 の 1〜3)**

| 項目 | 結果 |
|---|---|
| `/object_info` の `TextEncodeQwenImage21` | 必須: `clip`・`prompt`・`negative_prompt`・`resolution`(INT、既定 1024、0〜4096、刻み 32)・`images`(型 `COMFY_AUTOGROW_V3`、スロット名 `image_1`〜**`image_16`**、`min: 0`)。任意: `vae`。出力: `positive` / `negative` / **`latent`**(`output_name` の 3 つ目)。**スロットの最大は 16 で確定**(資料の 10 / 16 の食い違いは 16 が正) |
| API 形式での参照画像の渡し方 | 入力名は **`images.image_1`**、`images.image_2`…(値は `["<LoadImage の id>", 0]`) |
| 公式の編集テンプレート(`image_qwen_image_2_1_image_edit.json`)の構成 | `UNETLoader` → **`QwenImage21Cache`**(`device` auto・`dtype` default)→ `KSampler.model`。`TextEncodeQwenImage21`(`vae` 接続)の `positive` / `negative` を KSampler へ。**`latent_image` は `ComfySwitchNode` 経由で、既定は `TextEncodeQwenImage21` の `latent` 出力**(スイッチを入れたときだけ `EmptyLatentImage`。= 出力サイズを手動指定する経路)。KSampler は 25 ステップ・CFG 1・`euler` / `simple`・**`denoise` 1**。`TextGenerate`(プロンプトの書き換え)は既定でオフ |
| 最低限の ComfyUI バージョン | 公式資料に記載なし。**0.45.6 で動作を確認**した(これより古い版は未確認。`features.referenceEdit` はバージョンではなく、`/object_info` のノード定義で判定する。§4.2) |
| `QwenImage21Cache` の要否 | **不要**。キャッシュのノードを通さずに、INT8 版・参照 1 枚・1024・8 ステップで生成できた(Q-121 のとおり使わない) |
| 実機の生成(INT8・参照 1 枚・`resolution` 1024・8 ステップ・CFG 1) | バリデータに受理され、**87 秒で成功**(RTX 2060 12GB)。出力は 1024×1024 の PNG で、**1 枚目の参照画像と同じサイズ・同じ構図**(SaveImage でそのまま保存できた。アルファの問題なし) |

**まだ確認していないこと(実装中・実装後に確認する。09 の検証ログへ記録)**: 参照 2 枚以上での生成と時間・VRAM、縦長・横長の参照での出力サイズ、25 ステップでの時間、写真からアニメ調への変換の質(今回の試験画像は元からイラストのため、画風の変化は見ていない)、`resolution` 1536 での VRAM 不足の有無。

## 3. 利用者の体験

1. 生成画面でモデル種別に Qwen-Image 2.1 を選ぶと、「参照画像」セクション(スイッチ付き)が使える。他の種別では無効(「Qwen-Image 2.1 のみ対応」と表示)。
2. 参照画像を追加する(ファイル選択、またはギャラリー詳細の「参照画像に使う」)。サムネイルに **`<image1>` `<image2>`…** の番号が付く。並べ替え・削除ができ、1 枚目が編集される画像(出力サイズも 1 枚目で決まる)であることを表示する。
3. サムネイルの番号ボタンを押すと、プロンプトのカーソル位置に `<imageN>` が入る。
4. 「参照画像の大きさ」(`resolution`)を選ぶ: **小(768)/ 標準(1024、既定)/ 大(1536)**。0(元のサイズ)は **用意しない**(VRAM 不足の恐れ。Q-120)。選んだ値と 1 枚目の縦横比から、出力サイズの目安(例: 約 896×1184)を表示する。
5. 参照画像が有効な間は、幅・高さの欄は無効(1 枚目で決まる)。ステップ・CFG は t2i と同じ既定(25・CFG 1)。ネガティブ欄は CFG 1 では効かない旨を表示する(17 §3 と同じ)。
6. 「生成」で、通常の生成と同じようにギャラリーへ保存される。

### 3.1 かんたん開始(「指示だけでアニメ調に」)【廃止(07 Q-344)】

> **2026-11-23 の変更**: [指示でアニメ調に] ボタンは不要との指示により削除する。参照画像の機能本体と [Qwen の参照に使う] は残す。以下は旧仕様(履歴)。

- (旧)参照画像の欄に **[指示でアニメ調に]** を置く。押すと、①モデル種別を Qwen-Image 2.1(導入済みのとき。無ければ `/models?category=qwen_image` へ誘導)に、②参照画像を有効にして 1 枚目に画像を入れ、③プロンプトに雛形(例: 「参照画像(`<image1>`)は、成人の架空キャラクター(イラストや CG)である。`<image1>` を、顔立ち・髪型・体型・表情・ポーズ・服装・構図・背景はそのままで、アニメ調のイラスト(はっきりした輪郭線、フラットな塗り、整った陰影)に描き直す。それ以外は変更しない。」)を入れる。雛形は編集できる。
- 雛形は「参照画像が成人の架空キャラクターであること」を明記し、「保つもの」と「変えるもの」を言葉で分けて書く(Qwen-Image 系の公式・コミュニティの推奨に沿う)。サンプラー値は ComfyUI 公式テンプレートの既定(25 ステップ・CFG 1・euler・simple)のまま変えない。より丁寧に仕上げたいときは 40 ステップ程度に上げる。
- 19 の img2img(アニメ系 SDXL モデルを使う方式)とは **別の経路** で、どちらも残す。画像編集モデルのほうが人物や構図を保ちやすい一方、重い(§7)。ユーザーが選べるよう、両方のボタンを並べる。

## 4. パラメータとワークフロー

### 4.1 パラメータ(`GenerationParams.reference`)

```ts
interface ReferenceParams {
  enabled: boolean;
  images: string[];     // inputs/<uuid>.png(10 §6 と同じ保管)。1 枚目が編集対象
  resolution: number;   // 参照画像の総画素の基準。768 | 1024 | 1536(既定 1024)
}
```

- 枚数の上限は **アプリ側で 4 枚**(Q-119。ノードは 16 枚まで受けられる(実機で確認済み)が、VRAM と速度の都合)。最小は 1 枚。2 枚以上の実測のあとで必要なら見直す。
- スキーマ: `GenerationParams` に任意項目を足すだけ(`inpaint`・`img2img` と同じ)。DB のマイグレーションは不要。`schemaVersion` は据え置き(実装時に確認)。

### 4.2 検証(`job_enqueue`)

- `qwen_image` 以外で `reference.enabled` なら `VALIDATION`。
- `images` が 1〜4 枚であること(0 枚・5 枚以上は `VALIDATION`)。各画像が存在すること(無ければ `IMAGE_NOT_FOUND`)。`resolution` は 768 / 1024 / 1536 のいずれか。
- **排他**: `inpaint`・`img2img`・`controlnet`・`faceDetailer` のいずれかが有効なら `VALIDATION`(いずれも `sd15` / `sdxl` のみなので、種別の検証で先に弾かれるが、メッセージは「参照画像は他の画像入力機能と併用できません」とする)。
- 幅・高さは 1 枚目から決まるため、`width` / `height` は無視する(フォームは目安を表示するだけ)。枚数(`batchSize`)は 1 以上。2 以上のときは `RepeatLatentBatch` で latent を増やす。
- 必要ノード(`/object_info` の `TextEncodeQwenImage21` が、`images`(`COMFY_AUTOGROW_V3`)と任意の `vae` の入力、`latent` の出力を持つこと)が無い、古い ComfyUI では、`engine_status.features.referenceEdit` が false になりスイッチを無効にする(`ENGINE_NODE_MISSING`。「ComfyUI の更新」を案内)。

### 4.3 ワークフロー(17 §4 の Qwen-Image 2.1 の骨格を拡張。§2 の実機確認で確定済み)

```
LoadImage ×N ─ (images: image_1…image_N) ─┐
VAELoader ─────────── (vae) ─────────────┤
CLIPLoader ── (clip) ────────────────────→ TextEncodeQwenImage21(prompt, negative_prompt, resolution)
                                            ├ positive ─→ KSampler.positive
                                            ├ negative ─→ KSampler.negative
                                            └ latent ───→ [RepeatLatentBatch] ─→ KSampler.latent_image ─ VAEDecode ─ SaveImage
```

- t2i の `EmptyLatentImage` を、`TextEncodeQwenImage21` の **`latent` 出力** に置き換える(公式の説明どおり。KSampler の `denoise` は 1.0)。`vae` は必ずつなぐ(参照 latent を使うため)。
- `LoadImage` は画像の枚数ぶん。ノード ID は他の機能(20〜22 顔補正、30〜 ControlNet、60〜 Inpaint、80〜83 img2img)と重ならない範囲(実装で確定。案: 90〜 を使う)。
- **`QwenImage21Cache` は使わない**(Q-121)。experimental のノードで、無くても編集が成立することを実機で確認した(§2)。メモリ不足で必要と分かったときだけ、既定値(`auto` / `default`)のまま `UNETLoader` と `KSampler` の間に足す形で、本資料を先に更新する。
- 参照画像の入力名は `images.image_1`〜(§2)。`LoadImage` の ID は、既存の機能と重ならない範囲から振る。
- 画像のアップロード・保管は 10 §6 の `input_image_*` を流用(**新しい IPC は不要**)。実行時に ComfyUI へ `LoadImage` 用にアップロードする(img2img と同じ。画像ごとにアップロードする)。

## 5. 再現・履歴・ギャラリー

- 「この設定で生成」・プリセット・ギャラリー詳細は、`reference` を保存・復元する。画像が欠損していれば参照画像を無効にして復元し、トーストで知らせる(10 §8)。
- ギャラリー詳細に、参照画像の小さなサムネイルを番号つきで併記する(ControlNet の参照画像と同じ扱い)。
- 組み込みプリセット(16)は画像のパスを含められないため、§3.1 のかんたん開始はボタンの処理(フォームへの一括設定)とする。

## 7. メモリ・速度の注意(17 §8 の実機結果を踏まえる)

- 開発機(RTX 2060 12GB)で、INT8 版の t2i は 1024×1024・25 ステップが 104 秒だった。参照画像つきは **参照 latent が加わる分、メモリも時間も増える**(参照が増えるほど遅くなる)。
- そのため、既定は 1024(約 1MP)・上限 4 枚・0(元のサイズ)なしとした。実機で、1〜2 枚の参照で生成できるか・かかる時間・VRAM 不足(`ENGINE_OOM` 相当)になる条件を 09 の検証ログに記録する。生成できない場合の扱いは Q-123。

4. ✅ AI サポートの追記、09 のチェックリスト追加、検証ログ。

**実装時の判断(設計との差異・補足)**
- ギャラリーのボタン名を [Qwen の参照に使う] にした(§6.2。既存の [参照画像に使う] は ControlNet 用)。
- 生成画面右側の「参照画像」ワークスペース(20 §4.2)には、参照画像つき生成のタブを **足していない**(画像はセクション内のサムネイルで確認できる)。必要になれば追加する。
- モデルの説明パネルの「対応機能」(○ / ×)には、参照画像を **足していない**(img2img も載せていないため)。
- 参照 3〜4 枚・`resolution` 1536 の実機での動作は未確認(09 に記録)。

## 11. リスク

- **VRAM 不足**: 12GB の機で、参照つきが動かない可能性がある → 解像度の既定・枚数の上限・案内(§7)。動かない場合も機能は残し、エラーで案内する(Q-123)。
- **資料の食い違い**(スロットの最大数・`latent` の扱い)→ §9 の実機確認で確定してから実装する。
- **人物の保持は完全ではない**: 参照画像の画風・人物の転写は、言葉での指示に依存する。期待を UI の注記で示す(「保ちたいものをプロンプトに書く」)。
