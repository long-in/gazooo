# 42. 顔の入れ替え(複数画像の顔だけを指定の顔に書き換える、v0.37)

> ステータス: 🟢 承認済み・実装済み(2026-11-23。07 Q-328〜343・348。Rust 469・Vitest 367・clippy・ESLint・静的エクスポートのビルドまで確認。実機の ComfyUI(Windows・RTX 2060 12GB)で、アプリのエンジンコード経由の生成と後段合成を確認。**画面の目視確認・複数人・横顔・小さな顔・macOS は未実施**。実装時の差異は §14)。
> **経緯**: 「複数の画像を取り込み、顔以外はそのままで、顔だけ指定の顔に書き換えて生成したい」という要望(2026-11-23)。ComfyUI のモデル・拡張を調査した(§2)。**商用利用はしない**(ライセンスは選定基準にしない)。
> **前提の確認(ユーザー回答)**: 対象 GPU は開発機と同じ RTX 2060 12GB(24 §2 の実機)。「顔以外は厳密に元のまま」を必須とする(§5 の後段合成)。対象モデルは、既に参照画像入力(24)が実装済みの **Qwen-Image 2.1** から始める(§1。Qwen-Image-Edit-2511 などは別の変更)。

## 1. 目的とスコープ

**やること**
- **F-21 顔の入れ替え**: 「顔画像(1 枚)」と「対象画像(複数枚)」を指定し、対象画像ごとに **顔だけ** を指定の顔に書き換えた画像を生成する。
- **顔以外は元のまま**にする(§5 の後段合成。既定 ON)。
- 複数の対象画像は、1 枚ずつ別のジョブとしてキューに積む(§4.3)。

**やらないこと(v0.37)**
- `qwen_image` 以外の種別(Qwen-Image-Edit-2511、FLUX.2 Klein、SDXL + InstantID / PuLID、ReActor は **別の変更**。§2 の比較のとおり)。
- 汎用の LoRA 機能(LoRA 一覧・選択 UI・複数 LoRA の重ね掛け。01 の「LoRA は v0.2 候補」のまま)。本機能は **顔入れ替え専用の LoRA を内部で 1 つ適用するだけ**(§4.4)。
- 顔画像を複数枚から合成する、1 枚の対象画像で複数人の顔を別々に差し替える。
- 動画の顔入れ替え。
- 参照画像からのプロンプトの自動生成(24・19 Q-86 のまま。画像を外部へ送らない)。

## 2. 調査結果(2026-11-23。二次情報が中心。採用前に §9 で実機確認する)

方式は 3 系統ある。

| 方式 | 仕組み | 顔以外の保持 | 備考 |
|---|---|---|---|
| A. 後処理の顔置換(ReActor / InSwapper) | 完成画像の顔を置換 | 顔領域のみ変わる | 手軽だが顔の解像度が低い。InsightFace のビルド要件(Windows)に注意 |
| B. Inpaint + 顔 ID 注入(InstantID / PuLID / IP-Adapter FaceID) | 顔をマスクで再生成し、顔の特徴量を注入 | マスク外は元のまま(合成) | InstantID は SDXL 向け、PuLID は SDXL / FLUX 向け。依存ノードが多い |
| C. 編集系モデル + 顔・頭の入れ替え LoRA | 「画像 1 の頭を画像 2 の人物に置き換える」と指示 | モデルの出来次第(→ 後段合成で保証) | Qwen-Image 2.1 / Qwen-Image-Edit 2509・2511 / FLUX.2 Klein / FLUX.1 Kontext |

**C を採用する理由**: 本アプリには **Qwen-Image 2.1 の参照画像入力(24)が実装済み**(`TextEncodeQwenImage21` に `images` を渡す。実機の RTX 2060 12GB で参照 1 枚 87 秒・2 枚 68 秒を確認済み)。BFS(Best Face Swap)に **Qwen-Image 2.1 用の頭の入れ替え LoRA**(`bfs_head_v1_qwen_2.1.safetensors`。画像 1 = 対象、画像 2 = 入れ替える頭)が公開されており、既存の仕組みに LoRA を 1 つ足すだけで実現できる。ほかの案は、モデル・ノードの追加導入が必要(A・B)か、アプリにまだ無いモデル種別の追加が必要(Qwen-Image-Edit・Klein)。

## 3. 利用者の体験

1. 生成画面で、モデル種別に Qwen-Image 2.1 を選ぶと、**「顔の入れ替え」セクション**(スイッチ付き)が使える。他の種別では無効(「Qwen-Image 2.1 のみ対応」)。LoRA(§4.4)が未導入なら、スイッチを無効にして `/models` の取得ページへ誘導する。
2. **顔画像**(1 枚)を指定する。ファイル選択、またはギャラリーから選ぶ(39 のギャラリーピッカーと同じ)。
3. **対象画像**(複数枚)を追加する。ファイルの複数選択、ギャラリーでの複数選択に対応。サムネイル一覧で個別に削除できる。
4. 設定:
   - **「顔以外を元の画像のまま保つ」** スイッチ(既定 ON。§5)。
   - **入れ替える範囲**: **頭**(既定。髪を含む。実機で継ぎ目が目立たなかった。§9.1)/ **顔**(髪・首は元のまま。検出が長方形のため、継ぎ目が見えやすい)。ON のときのみ有効(§5.2)。
   - 参照画像の大きさ(24 と同じ 768 / 1024 / 1536。既定 1024)。
5. プロンプトには雛形(§4.2)が入る。編集できる(複数人が写る画像で「左の人物」と指定するなど)。
6. **[N 枚を生成]** を押すと、対象画像ごとにジョブが 1 つずつキューに入る(帯のカードに対象画像の名前を表示)。完了した画像は通常どおりギャラリーに入る。
7. 画面に **「本人の同意のある顔だけを使ってください」** の注記を置く(BFS の作者の利用条件。非商用でも同意は必要)。

## 4. パラメータとワークフロー

### 4.1 パラメータ(`GenerationParams.faceSwap`)

```ts
interface FaceSwapParams {
  enabled: boolean;
  target: string;          // inputs/<uuid>.png(対象画像。1 ジョブにつき 1 枚。24・10 §6 と同じ保管)
  face: string;            // inputs/<uuid>.png(入れ替える顔)
  keepOutside: boolean;    // 顔以外を元のまま保つ(後段合成)。既定 true
  region: "face" | "head"; // 合成する範囲。既定 "head"(§9.1。Q-332)
  resolution: number;      // 768 | 1024 | 1536(既定 1024。24 と同じ)
}
```

- スキーマ: `GenerationParams` に任意項目を足すだけ(`reference` と同じ)。**DB のマイグレーションは不要**。
- `faceSwap` が有効なとき、ワークフロー生成の内部では `reference.images = [target, face]` と同じ扱いにする(**1 枚目が編集対象、2 枚目が顔**。24 §4.3 の骨格を再利用)。ユーザーが `reference` を同時に設定することはできない(§4.2)。

### 4.2 検証(`job_enqueue`)と既定のプロンプト

- `qwen_image` 以外で `faceSwap.enabled` なら `VALIDATION`。
- `target`・`face` の画像が存在すること(無ければ `IMAGE_NOT_FOUND`)。`resolution` は 768 / 1024 / 1536。
- **排他**: `reference`・`inpaint`・`img2img`・`controlnet`・`faceDetailer` のいずれかが有効なら `VALIDATION`。
- LoRA が見つからない(導入されていない)場合は `MODEL_NOT_FOUND`(取得ページへ誘導)。LoRA を適用する core ノードが無い ComfyUI では `ENGINE_NODE_MISSING`。`engine_status.features.faceSwap` を、必要ノードの有無と LoRA の有無から判定する(§6)。
- 既定のプロンプト雛形(英語。**BFS の作者が配布する文面をそのまま使う。実機で動作を確認済み**。§9.1。当初案の「Replace the head of …」は試していないので採らない):
  `head_swap: start with <image1> as the base image, keeping its lighting, environment, and background. remove the head from <image1> completely and replace it with the head from <image2>, strictly preserving the hair, eye color, nose structure from <image2>. copy the direction of the eye, head rotation, micro expressions from <image1>, high quality, sharp details, 4k`
  - `<image1>` = 対象、`<image2>` = 顔(入れ替えるとどちらが対象か変わる)。`<imageN>` の表記は、本アプリの `TextEncodeQwenImage21` でそのまま通った。
  - プロンプトの言語はモデルの推奨(11 §14)に従い、雛形は英語で固定する。ユーザーが書き換えた内容は、そのジョブにだけ使う。
- **プロンプトは必須ではない(v0.38 で変更。Q-389)**: `faceSwap.enabled` のとき、`prompt` が空(空白のみを含む)なら、**雛形をそのまま使う**。`job_enqueue` の検証は、`faceSwap` 有効時に限り空のプロンプトを許す(それ以外の機能では従来どおり `VALIDATION`)。入力欄が空でも「生成」を押せる。雛形の文面は §4.2 のままで、ジョブには雛形を詰めた値を保存する(履歴・再実行で同じ結果になる)。

### 4.3 複数の対象画像(バッチ)

- 対象画像 N 枚 → **フロントが `job_enqueue` を N 回呼ぶ**(各ジョブは `faceSwap.target` を 1 枚ずつ持つ)。バックエンドに新しいバッチの仕組みは作らない。
- 既存のキュー機能(並べ替え・キャンセル・再試行・27・28 の帯)をそのまま使える。1 件の失敗は他の件に影響しない。
- 各ジョブのシードは独立(既定のランダム。固定したいときは通常のシード指定に従う)。

### 4.4 ワークフロー(ComfyUI のコアノード + 顔入れ替え LoRA)

```
24 の参照画像つきワークフロー(images = [target, face])
  UNETLoader ─→ [LoraLoaderModelOnly(顔入れ替え LoRA、strength 1.0)] ─→ KSampler.model
```

- 24 §4.3 のワークフローの `UNETLoader` と `KSampler` の間に、**LoRA の適用ノードを 1 つだけ** 挟む(`LoraLoaderModelOnly`。コアノード。**実機の `/object_info` で存在を確認済み**。§9.1)。入力は `model`・`lora_name`・`strength_model`。
- LoRA 名は固定(カタログの 1 件。§7)。**強さは 1.0 固定**(作者の推奨。画面には出さない)。汎用の LoRA 機能は作らない(§1)。
- **既定 8 ステップ**(約 90 秒)・CFG 1・`euler` / `simple`。「高品質」で 25 ステップ(約 290 秒)。**どちらも実機で入れ替えに成功した**(§9.1。Q-343)。
- 参照 2 枚の渡し方は 24 と同じ(`images.image_1` = 対象、`images.image_2` = 顔。`vae` を接続し、`latent` 出力で KSampler を回す)。**実機で受理され、生成に成功した**。
- ノード ID は既存の機能(20〜、30〜、60〜、80〜、90〜)と重ならない範囲(§5 の合成ノードも含め、実装で確定。案: 100〜)。

## 5. 顔以外を元のまま保つ(後段合成)

**目的**: モデルの出力は、顔以外もわずかに変わることがある(再エンコードによる色・質感の変化、サイズの丸め)。生成結果から **顔の領域だけ** を取り、元の対象画像に貼り戻して「顔以外は元のまま」を保証する(13 の Inpaint の `compositeBack` と同じ考え方)。

### 5.1 手順

1. **顔の検出**: 元の対象画像から顔を検出し、領域(マスク)を作る。検出には、**顔補正(10)で導入済みの顔検出ノード**(Impact Pack / Subpack の検出器。23 の追加コンポーネント)を使う。実機で通った構成: `UltralyticsDetectorProvider`(`bbox/face_yolov9c.pt`)→ `BboxDetectorSEGS`(`threshold` 0.5・`dilation` 10・`crop_factor` 1.0〜1.6・`drop_size` 10・`labels` all)→ `ImpactSEGSOrderedFilter`(`target` = area、`order` = 降順、`take_count` = 1。**最大の顔 1 つだけを選べる**)→ `SegsToCombinedMask`。
2. **マスクの加工**: 検出した領域を拡大(`GrowMask`。`region = face` は 8〜20 px、`head` は髪を含むよう 40〜50 px、`crop_factor` も大きく)し、境界をぼかす。**`FeatherMask` は画像の縁をぼかすノードで、マスクの輪郭には効かない**(実機のマスク画像で、`feather` 16 でも境界が硬いままだった)。輪郭のぼかしには `ImpactGaussianBlurMask`(Impact Pack。`kernel_size` 0〜100・`sigma`)を使う案だが、**実機の結果は未確認**(§9.1)。
3. **サイズ合わせ**: 生成画像(24 のとおり、参照 1 枚目の縮小サイズ。実測: 768×1024 の対象で 896×1184)を、元の対象画像のサイズに戻す(`ImageScale`、`lanczos`)。縦横比がわずかに違う(0.757 と 0.75)ため、顔の位置が数 px ずれる(許容範囲だった)。
4. **合成**: マスク内だけ生成画像、マスク外は元画像(`ImageCompositeMasked`)。これを `SaveImage` に渡す。
- 元画像が大きい(2048 超など)ときは、生成画像の拡大でぼやけるのは顔の領域だけで、顔以外は元のまま残る(これが合成の利点)。

### 5.2 制約・注意

- 合成の範囲は検出器の精度に依存する。検出される領域は **長方形**(輪郭に沿わない)。`face` は髪・首が元のままなので「顔だけ」に最も近いが、**実機では長方形の継ぎ目が見え、周りの元の髪と新しい髪が食い違った**(§9.1)。`head`(既定)は髪ごと貼り戻すため、継ぎ目がほとんど分からなかった。`face` はぼかし(上記 2)と楕円化で改善できる可能性があるが、**未検証**。「顔以外は元のまま」を厳密に求めるときは、髪が変わる(`head`)ことを注記で示す。**顔画像の髪が長いと、生成結果の髪が貼り戻す範囲(頭の検出領域 + 拡大)の外へ伸びる**(25 ステップのシード 2 で確認)。その部分は元の画像のままになるので、髪が途中で切れて見える可能性がある(1 回目のシード 1 では目立たなかった)。範囲を下方向へ広げる、または髪の長さを揃えるプロンプトの追記で対応する案があるが **未検証**。
- **検出器が導入されていない場合**(顔補正の追加コンポーネントなし): 合成のスイッチを無効にし、「導入すると顔以外を元のまま保てます」と案内する。無効のまま生成した場合の出力は、モデルの出力そのまま(顔以外も変わる可能性がある)で、画面にその旨を表示する。
- **複数人が写る画像**: 検出された顔のうち **最も大きい 1 つだけ** を合成の対象にする(Q-336)。モデル側の指示(「左の人物」など)はプロンプトで補う。
- 顔が検出できなかった画像: 合成せずに生成結果をそのまま保存し、トーストで知らせる(失敗にはしない)。

## 9. 実装前の確認(結果で本資料を先に更新する)

実装前に、開発機(RTX 2060 12GB)の ComfyUI で次を確認し、結果で §2・§4・§5・§7 を確定する。**確認が済むまで実装に入らない。** 各項目の結果は §9.1(✅ 確認済み / 🟡 一部 / ⚪ 未確認)。

6. **複数人・横顔・小さな顔・眼鏡・髪型の違う顔** での出来と合成の境界。
7. **ステップ数**: 25 で良いか、LoRA の推奨(少ステップ)に合わせるか。

## 10. テスト方針

- Rust: ワークフロー生成(参照画像 2 枚 + LoRA のノード、合成のノード、ノード ID の非衝突、リンク整合性、`keepOutside` / `region` の分岐)、検証ルール(種別・画像の欠損・排他・LoRA 未導入・`resolution` の値)、`features.faceSwap` の判定、AI のスナップショットにパスが含まれないこと。実機のテストは `#[ignore]`(既存方針)。
- フロント(Vitest): 対象画像の追加・削除・N 枚のジョブ投入(件数・各ジョブの `target`)、有効 / 無効条件(種別・LoRA・検出器)、「[N 枚を生成]」の表示、プリセット・プロジェクトの復元(欠損時の無効化)。
- 手動(09 に追加): 1 枚 / 3 枚の入れ替えの質、顔以外が元画像と一致すること(合成あり)と、合成なしの差、境界のなじみ、顔が検出できない画像、LoRA 未導入時の案内。

## 12. リスク

- **LoRA の効きが不安定**: 顔の似方・髪型・視線にばらつきが出る。→ `head` / `face` の使い分けと、シード違いでの再生成(通常のバッチ)で対応。期待値は UI の注記で示す。
- **速度**(12GB の RTX 2060): 参照 2 枚 + LoRA は 8 ステップで約 90 秒、25 ステップで約 290 秒。N 枚のバッチでは N 倍かかる(3 枚で 8 ステップなら約 4.5 分)。既定は 8 ステップ(Q-343)。進捗はキューの帯に出る。
- **VRAM 不足**: 3 回の実行で OOM は出なかった(使用は約 11GB で余裕は小さい)。他のアプリが GPU を使っていると不足しうる → 24 Q-123 と同じ扱い(機能は残し、解像度を下げる(768)案内とエラー表示、09 に動作条件を明記)。
- **ComfyUI の無応答**: アプリが起動した ComfyUI で、GPU が空いたまま HTTP が約 8 分応答しなくなる現象が 1 回あった(原因は未特定。ComfyUI を直接起動した再実行では再現しなかった)。アプリの起動管理(15)が無応答を検知して扱えるか(タイムアウト・再起動の案内)を、実装時に確認する。
- **合成の境界**: 検出器の誤り・顔の大きさの違いで境界が目立つ → `head`・マスクの拡大 / ぼかし量の調整(§9 の確認で既定値を決める)。
- **二次情報への依存**: LoRA・ノード名・推奨設定は第三者の記事が根拠 → §9 を実装の前提にした。
- **同意のない顔の使用**: 技術的には防げない。注記で示す(§3-7)。

## 14. 実装時の判断(設計との差異・補足。2026-11-23)

- **新しい IPC `input_image_pick_many`(§6.1 は「新しい IPC は不要」としていた)**: 対象画像を一度に複数選ぶため、Rust 側でファイル選択ダイアログ(複数選択)を開いて取り込む。パスはフロントから受け取らない(`input_image_pick` と同じ)。一度に取り込む上限は 50 枚(Q-348)。
- **`FaceSwapParams.detector` を追加**(§4.1 には無かった): 後段合成の顔検出モデル(既定 `bbox/face_yolov9c.pt`)。画面には出さない。検証は `bbox/` で始まる安全な名前だけ。
- **`engine_status.features` に `faceSwap` と `faceSwapComposite` を追加**(§6.1 は `faceSwap` のみ): `faceSwap` = 参照画像つき生成 + `LoraLoaderModelOnly` + 顔入れ替え LoRA の導入。`faceSwapComposite` = 後段合成の 9 ノード(検出・マスク・`GetImageSize`・`ImageScale`・`ImageCompositeMasked` など)がそろっていること。合成のノードが無い ComfyUI では、フロントが `keepOutside` を切って投入する(生成自体は可能。Q-331)。
- **後段合成のノード**: §5.1 のほか、元画像のサイズを得るために `GetImageSize`(コアノード)を使う(サイズをワークフローへ直接書かないため)。ノード ID は 110(LoRA)・111〜119(合成)。
- **顔が検出できなかった画像(§5.2 との差異)**: 検出が空のとき、後段合成の結果は **元の対象画像と同じもの(入れ替わらない)** になる。「合成せずに生成結果をそのまま保存する」にはなっていない(ワークフロー内で分岐させると複雑になるため)。画像が入れ替わっていないときは、合成を切って再生成するか、顔が大きく写る画像を使う。改善案は後続の変更で扱う。
- **1 ジョブ 1 枚**: `batchSize` が 1 以外なら `VALIDATION`(§4.2 の「枚数は投入数で増やす」)。フロントも各ジョブを `batchSize: 1` で投入する。
- **対象画像の一覧はフォームの一時状態**: 下書き・プリセット・プロジェクトの最後の設定には、ジョブと同じく **対象 1 枚だけ** が保存される(復元時はその 1 枚が一覧になる)。
- **有効にしたときの上書き**: プロンプトが雛形でなければ雛形に、ステップを 8、CFG を 1、枚数を 1 にする。直前の値は「元に戻す」(トースト)から戻せる。参照画像つき生成は自動で切る(排他)。
- **カタログ**: LoRA は `qwen_image` カテゴリの 1 ファミリー(`qwen-image-2-1-face-swap-lora`)として追加し、保存先の列挙に `loras`(`DestDir::Loras`)を加えた。取得元は HF の固定コミット(`2209ae53…`)。取得時にライセンスの同意画面が出る(`requiresConsent`)。
- **AI サポート**: 機能カタログに F-21 を追記。「LoRA」は「まだ無い機能」のまま(顔の入れ替えの内部利用を除く)。スナップショットの `faceSwap` は、画像のパス・枚数以外を送らない(`targetCount` は 1 固定)。
- **翻訳ボックス**: 顔の入れ替えが有効のときは、参照画像つき生成と同じく `<imageN>` を保つ設定で翻訳する。
- **実機の試験**: `generate.rs` に `real_comfyui_face_swap_with_lora_and_composite`(`#[ignore]`。`FACE_SWAP_TARGET`・`FACE_SWAP_FACE` に実在しない人物の PNG を指定)を追加した。133 秒で成功し、出力が元の画像と同じ大きさになることを確認した。
