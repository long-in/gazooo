# 49. ギャラリーのお気に入り以外の一括削除(v0.49)

> ステータス: 🟢 承認済み・実装済み(2026-11-25。07 Q-419〜426 は推奨どおり。Rust 510・Vitest 388・clippy・ESLint・tsc まで確認。**画面の目視確認・macOS は未実施**。差異は §8)。
> **経緯**: ユーザー要望「ギャラリーでお気に入り以外を一括削除する機能を作成してください」(2026-11-25)。

## 1. 目的とスコープ

**やること**
- ギャラリーで、**今開いている表示範囲(スコープ)のうち、お気に入りでない画像をすべて**まとめて削除する。
- 取り返しがつかない操作のため、**件数つきの確認ダイアログ**を必ず挟む。
- 削除の挙動は既存の `image_delete`(DB の記録を削除し、ファイルは OS のゴミ箱へ。04)と同じ。

**やらないこと**
- 選択した画像の削除(既存の一括操作バーの [削除]。変更しない)。
- お気に入りの削除(このボタンでは決して消えない)。
- 検索語・絞り込みに合わせた部分的な削除(§3。Q-420)。
- ゴミ箱を使わない完全削除、元に戻す機能(OS のゴミ箱から戻せる)。

## 2. 画面(05 への追記)

- `/gallery` のツールバー(検索・お気に入りフィルタの並び)に、**[お気に入り以外を削除…]** を追加する(破壊的操作のため、メニュー(⋯)の中に置き、強調しない)。
- 押すと確認ダイアログ:
  - 本文: 「〇〇(スコープ名)の、お気に入り以外の **N 枚** を削除します。お気に入りの M 枚は残ります。」
  - ファイルの扱い: 「ファイルは OS のゴミ箱へ移動します」(既存の削除ダイアログと同じ文言)。
  - [キャンセル](既定フォーカス)/ [N 枚を削除](破壊的スタイル)。
  - N は **ダイアログを開くときに Rust へ問い合わせて取得**(§4 `image_count_non_favorite`)。画面に読み込み済みの件数ではなく、DB の実数。
- N = 0 のとき: ボタンは無効(または「削除対象はありません」)。
- スコープが **お気に入り**(★のみ表示)のときは、対象が常に 0 のためボタンを無効にする。
- 実行中: ダイアログ内にスピナー。完了後に toast「N 枚を削除しました」、一覧を再読み込みし、選択状態・アンカー(44 §9)を解除する。失敗があれば件数を toast で示す。
- グリッド・ビューア(37)のどちらの表示でも使える(ツールバーは共通)。

## 3. 対象の範囲

- 対象 = **現在のスコープ(すべて / 未分類 / 各プロジェクト。40)に属し、`is_favorite = 0` の画像すべて**(読み込み済みでないものも含む)。
- **検索語・お気に入りフィルタは対象に含めない**(Q-420)。検索で絞った状態で押しても、スコープ全体のお気に入り以外が消えてしまい意図と食い違うため、検索語が入力されている間はボタンを無効にして理由を示す(「検索を解除してください」)。
- 他ユーザー(36)の画像には触れない(ユーザーごとの別 DB のため自然に分離される)。
- 実行中のジョブが書き込み中の画像は、DB に登録されたものだけが対象(これから生成される画像は対象外)。

## 4. IPC(04 への追記)

| コマンド | 引数 | 戻り値 | 説明 |
|---|---|---|---|
| `image_count_non_favorite` | `{ scope?: "all" \| "unassigned" \| { projectId } }` | `{ total: number; favorites: number }` | スコープ内の「お気に入り以外」の件数と「お気に入り」の件数。確認ダイアログ用 |
| `image_delete_non_favorite` | `{ scope?: …; expectedCount: number }` | `{ deleted: number; failed: number }` | スコープ内のお気に入り以外を削除する(ファイルはゴミ箱へ)。完了後に `image://deleted` を発火 |

- `expectedCount` は確認ダイアログで見せた件数。**実行時の実数が `expectedCount` を超えていたら、何も削除せず `STALE_COUNT` エラー**にする(ダイアログを開いている間に生成が進んで、見せていない画像まで消すのを防ぐ。Q-423)。フロントは件数を取り直して再確認を促す。
- 存在しないプロジェクトの指定は既存の `PROJECT_NOT_FOUND`。
- パス・ID 列はフロントから受け取らない(Rust 側が DB から対象を決める)。

## 5. 動作・実装方針

- Rust: `ImageService::delete_non_favorite(scope, expected)`。対象 ID の抽出は `image_list` と同じスコープ条件(40)を共通化して使い、`is_favorite = 0` を加える。削除処理は既存の `image_delete` の内部関数を **そのまま再利用**(重複実装しない)。
- 件数が多い場合に備え、`spawn_blocking` 上で **500 件ずつのバッチ**で DB 削除 → ゴミ箱移動する。1 バッチの失敗で全体を止めず、失敗は件数で報告する(ファイルが既に無い場合は成功扱い。04 の `image_delete` と同じ)。
- 削除は DB トランザクションをバッチ単位で確定する(途中で中断しても、消えた画像と DB の記録が食い違わない)。
- サムネイル・ジョブ設定: `image_delete` の既存挙動に従う(画像を失ったジョブの扱いは 03 のとおり)。新規ルールは作らない。
- フロント: `src/lib/tauri/` に薄いラッパー、ギャラリーのストアに `deleteNonFavorites()` とダイアログの状態を追加。コンポーネントから直接 `invoke` を呼ばない。i18n 文言を追加。
- **DB スキーマ変更なし**。バックアップ対象の変更なし。

## 6. テスト

- Rust: お気に入りが 1 枚も消えないこと、スコープ(all / unassigned / project)ごとに対象が正しいこと、他スコープの画像が消えないこと、`expectedCount` 超過で何も消えず `STALE_COUNT` になること、500 件超のバッチ、ファイルが既に無い画像でも続行すること、`image_count_non_favorite` の件数。
- Vitest: 件数 0 でボタン無効、検索中は無効、お気に入りスコープで無効、確認ダイアログの文言と件数、キャンセルで何も呼ばれないこと、完了後に一覧の再読み込みと選択解除。
- 09 に追加: お気に入りを数枚付けてから実行 → お気に入りだけが残る、ゴミ箱から復元できる、プロジェクトごとのスコープで他プロジェクトに影響しない、検索中は押せない。

**マイルストーン M40**: ① Rust(件数・削除・`STALE_COUNT`)→ ② ギャラリーの UI(メニュー・確認ダイアログ)→ ③ 04・05・09 の同期。

## 8. 実装時の差異

- 確認ダイアログのコンポーネントテスト(Vitest)は、プロジェクトにコンポーネントテスト基盤(`@testing-library`)が無いため作らなかった。ストア(`removeNonFavorites`)と Rust 側をテストしている。
- ボタンの置き場所は、メニュー部品が無いため Popover(⋯)で実装した。件数 0 のときはボタンを無効にせず、押すと「削除対象はありません」を toast で出す。
- `image_delete_non_favorite` は古い順に 500 件ずつ処理する。ゴミ箱へ移せなかったファイルは `failed` に数える。
