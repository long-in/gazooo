# 31. デバッグログ(調査用の詳細ログ)(v0.24)

> ステータス: 🟢 承認済み(2026-11-21。07 Q-170〜178 は推奨どおり)。02 §3.8 を拡張する。

## 1. 背景と目的

画像生成中に ComfyUI との接続が「切断」と表示されることがある。原因は手元で再現できず、現在のログ(INFO のみ。接続状態が変わった事実しか残らない)では特定できない。**問題が起きたときに後から調べられる詳細ログ** を、必要なときだけ有効にできるようにする。

**やること**
- 設定ページに **「その他」タブ** を新設し、**デバッグ機能の ON / OFF** を置く。
- ON のときだけ **詳細ログ(DEBUG)** を出力する。OFF のときは従来どおり INFO のみ。
- ログファイルを **UI から手動で取得**(保存)できる。
- ログの合計が **1GB を超えたら、古いものから自動で削除** する。

**やらないこと**
- 接続切断そのものの修正(別件。まずログで原因を確定してから、07 に分けて起こす)。
- ログの外部送信・自動アップロード(取得は利用者が手動で行う)。
- ログの閲覧画面(UI 内でのビューア)。取得したファイルをテキストエディタで読む。

## 2. 設定項目

| key | 型 | 既定値 | 内容 |
|---|---|---|---|
| `debug.enabled` | boolean | false | 詳細ログ(DEBUG)の出力 |

- **再起動なしで即時に反映** する(`tracing_subscriber::reload` でログレベルを切り替える。新規依存なし)。
- 設定は保存され、次回起動後も維持する(接続断が再発するまで ON にしたままにできるように)。
- ON のとき、DEBUG にするのは **gazooo 自身のログのみ**。依存クレート(`hyper`・`reqwest`・`tungstenite` 等)は INFO のまま(量が多すぎて本題が埋もれるため)。ただし接続の失敗理由は gazooo 側で原因の連鎖(`source()`)まで記録する(§3)。

## 3. 詳細ログの内容(DEBUG のみで出すもの)

接続断の調査に必要なものを中心にする。各行に時刻・ジョブ ID・リモート ID(`prompt_id`)・スレッド/タスクの区別を付ける。

| 区分 | 記録する内容 |
|---|---|
| ヘルスチェック(`services/engine.rs`・`engine/comfyui`) | 1 回ごとに、開始・所要時間、**どのリクエスト(`/system_stats`・`/object_info/<node>`)が失敗したか**、失敗の種別(タイムアウト / 接続拒否 / 接続リセット / HTTP ステータス / JSON 不正)、エラーの連鎖(`source()`)。前回から状態が変わったとき(接続 ↔ 切断)は、その直前の連続失敗回数も |
| HTTP 全般 | 各リクエストのメソッド・パス(クエリは除く)・所要時間・ステータス。**ボディは記録しない** |
| 履歴ポーリング(`generate.rs`) | 失敗した回の連続回数・経過時間・エラー種別。成功に戻った時点で「復帰」。上限(20 回)に達して諦めた事実 |
| WebSocket | 接続の成功・失敗(所要時間)、切断の理由(`Close` フレーム・エラー・ストリーム終了)、切断までに受信したメッセージ数、最後に進捗を受信してからの経過時間 |
| ジョブ | 状態遷移(`queued → running → succeeded / failed / canceled`)と各所要時間、投入(`/prompt`)の結果、画像の取得(`/view`)の所要時間・バイト数、エラーコード |
| エンジンのプロセス(管理モードのみ) | 状態遷移、**切断判定の時点で子プロセスが生きているか**(`try_wait` の結果。終了していれば終了コード)、ポート |
| 環境 | ON にした時点で、アプリのバージョン・OS・エンジンの URL・管理/外部モード・ComfyUI のバージョン(取得済みなら) |

**記録しないもの(プライバシー。02 §3.8 のとおり)**: プロンプト本文・ネガティブプロンプト・参照画像の内容・API キー・AI サポートの会話本文。必要なら **文字数・件数のみ** を出す。パスはユーザー名を含みうるが、ローカル保存のみで手動取得のため、そのまま記録する(取得ファイルを他人へ渡すときの注意を UI に書く。§5)。

## 4. ログファイルの管理

### 4.1 ファイルと保存先

- 保存先は従来どおり `app_log_dir`(Windows: `%LOCALAPPDATA%\<identifier>\logs`、macOS: `~/Library/Logs/<identifier>/`。06)。
- アプリのログ: `gazooo-YYYY-MM-DD.log`(日次)。**1 ファイルが 100MB を超えたら、同じ日付のまま `gazooo-YYYY-MM-DD.1.log`、`.2.log` … と続きに分ける**(1 日で 1GB を超えうるため。日次のみでは上限を守れない)。
- 既存の `tracing_appender::rolling::daily` は容量で分割できないため、**小さな自前の書き込み部品(`SizeRotatingWriter`)に置き換える**。`tracing_appender::non_blocking` は引き続き使う。新規依存なし。
- 既存の `comfyui.log`(15 §6)・ローカル LLM のログ(30)は、これまでどおり別管理(各々で上限あり)。取得時の ZIP には同梱し、合計サイズの計算にも **含める** が、自動削除の対象にはしない(各々が自分で上限を持つため)。

### 4.2 自動削除(合計 1GB)

- 対象は、ログフォルダの **アプリのログ(`gazooo-*.log`)**。合計(上記 §4.1 の同梱ログを含む)が **1GB(1,073,741,824 バイト)を超えたら、更新日時の古い `gazooo-*.log` から削除** し、1GB 以下になるまで繰り返す。
- **書き込み中の最新ファイルは削除しない**(それだけで 1GB を超える場合は、新しい分割へ移る時点で整理されるため、実質 100MB 単位の超過に収まる)。
- 実行のタイミング: ① アプリ起動時、② 新しいファイルを作る(日付・分割の切り替え)たび、③ DEBUG が ON の間は 10 分ごと。OFF の間は ①② のみ(INFO のみなら量が少ないため)。
- 削除した事実(ファイル名・サイズ)は INFO で 1 行記録する。削除の失敗(使用中など)は WARN にして続行する。
- OFF にしても、既存のログは削除しない(再発後に取得できるように)。**[ログを削除] ボタン** で手動削除できる(§5。確認ダイアログあり)。

## 5. UI(設定 > その他。25 のタブに追加)

タブは 5 つになる(エンジン / 保存先 / AI サポート / 表示 / **その他**)。`?tab=other` で開ける。**[保存] ボタンの対象にはしない**(トグルは操作した時点で即時反映・保存する。ログの取得などの操作ボタンを含むため)。

```
その他
┌ デバッグ ────────────────────────────────────────────┐
│ [ ○─ ] デバッグログを有効にする                        │
│   不具合の調査用に、接続や生成の詳細をログに残します。      │
│   プロンプトの本文は記録しません。通常は OFF のままにして    │
│   ください(ログが増え、わずかに動作が重くなります)。       │
│                                                        │
│ ログ: 12 ファイル / 238 MB(上限 1 GB。超えると古いものから │
│ 自動で削除)                                             │
│ 保存先: C:\Users\...\logs                              │
│ [ログを保存…]  [フォルダを開く]  [ログを削除…]            │
└────────────────────────────────────────────────────────┘
```

- **[ログを保存…]**: Rust 側で保存ダイアログを開き、ログフォルダのファイル(アプリのログ・`comfyui.log`・LLM のログ)を **1 つの ZIP**(`gazooo-logs-YYYYMMDD-HHMMSS.zip`)にして書き出す。キャンセルは何もしない。完了時にトースト。ZIP に **設定のスナップショット(エンジン URL・モード・デバッグの ON/OFF。API キーは含めない)** を `info.txt` として同梱する。
- **[フォルダを開く]**: OS のファイラでログフォルダを開く(`tauri-plugin-opener`。導入済み)。
- **[ログを削除…]**: 確認ダイアログのうえ、アプリのログ(書き込み中のファイルは空にする)を削除する。
- **[ログを保存…] の注意書き**: 「ログにはパス名(ユーザー名を含む場合があります)が含まれます。第三者へ渡すときは内容を確認してください。」
- ON の間は、ステータスバー(29)に小さな「DEBUG」表示を出し、付けっぱなしに気づけるようにする(Q-176)。
- ログの件数・サイズは、タブを開いたとき・ON/OFF の切り替え後・削除後に取得し直す(常時ポーリングはしない)。

## 6. IPC(04 に追記する内容)

| コマンド | 入力 | 出力 |
|---|---|---|
| `debug_status` | – | `{ enabled: boolean; logDir: string; fileCount: number; totalBytes: number; limitBytes: number }` |
| `debug_set_enabled` | `{ enabled: boolean }` | `DebugStatus`(設定を保存し、ログレベルを即時に切り替える) |
| `debug_export_logs` | – | `{ path: string } \| null`(Rust 側で保存ダイアログを開き ZIP を書く。キャンセル時は `null`) |
| `debug_open_log_dir` | – | `void` |
| `debug_clear_logs` | – | `DebugStatus` |

- エラーは既存の型に従う(`INTERNAL`・`VALIDATION` など)。ZIP の作成失敗は `INTERNAL`(詳細はログへ)。
- `settings_update` は `debug.enabled` を **受け付けない**(ログレベルの切り替えを伴うため専用コマンドで行う。`imagesDir` と同じ扱い)。`settings_get` の `Settings` には `debug: { enabled }` を含める(UI の初期表示用)。
- イベントの追加はなし。

## 7. 実装方針(承認後)

- Rust:
  - `services/debug_log/{mod.rs, rotate.rs, export.rs}` と `commands/debug.rs`。`lib.rs` の `tracing_subscriber::fmt()` を、`reload::Layer`(レベルのフィルタ)+ `SizeRotatingWriter` に置き換える。起動時に `debug.enabled` を読んで初期レベルを決める。
  - §3 の各ログ行の追加(`services/engine.rs`・`engine/comfyui/{mod,generate}.rs`・`services/jobs.rs`・`services/engine_process`)。**呼び出しのロジックは変えない**(ログの追加のみ)。DEBUG が OFF のときのコストを避けるため、重い整形は `tracing::enabled!` で囲む。
  - ZIP の作成は、既存の依存(23 の導入で使う `zip` 等)で書き込めるか実装時に確認する。**新しい依存や feature の追加が必要なら、依存更新として別途承認を得る**(AGENTS.md §2)。
- フロント: `components/settings/other-section.tsx`、`src/lib/tauri/debug.ts`(薄いラッパー)、`settings.tabs.other` ほかの i18n(ja / en)、ステータスバーの表示、`?tab=other`。
- 03: `settings` に `debug.enabled` を追加するのみ(スキーマ変更・マイグレーションなし)。

## 8. テスト

- Rust: ① `SizeRotatingWriter` が 100MB(テストでは小さな値に差し替え)で分割する・日付が変わると新しいファイルになる、② 自動削除が 1GB 超のとき更新日時の古い順に削除し、書き込み中のファイルと `comfyui.log`・LLM のログは残す、③ ON/OFF でログレベルが即時に切り替わり(DEBUG 行が出る / 出ない)、OFF では INFO のみ、④ プロンプト本文・API キーがログに出ない(サンプルの文字列で検証)、⑤ ZIP に期待するファイルと `info.txt` が入り、API キーが含まれない、⑥ ヘルスチェックの失敗(タイムアウト・接続拒否・HTTP 500・不正 JSON)で、失敗したリクエストと種別が DEBUG に出る。
- フロント(Vitest): 「その他」タブの表示・`?tab=other`、トグルで `debug_set_enabled` が呼ばれる、件数・サイズの表示、削除の確認ダイアログ、保存のキャンセル。
- 手動(09 に追加): Windows でトグル ON → 生成 → ログに DEBUG が出る → [ログを保存…] で ZIP を開いて内容を確認、OFF で DEBUG が止まる、小さな上限に差し替えた状態で自動削除を確認、ステータスバーの表示。

1. `SizeRotatingWriter`・自動削除・`reload` によるレベル切り替え・`debug.enabled`(`lib.rs` と `services/debug_log`)。
2. IPC(`debug_*`)と ZIP の書き出し。
3. §3 の詳細ログの追加(ヘルスチェック → ポーリング・WebSocket → ジョブ・プロセスの順)。
4. 「その他」タブ・ステータスバー表示・i18n。
5. テストと 09 のチェックリスト。

## 10. リスク

- **DEBUG のログ量** → 依存クレートは INFO のまま・HTTP ボディは記録しない・100MB 分割 + 1GB 上限で抑える。ヘルスチェックは 5 秒ごと(約 25 リクエスト)なので、成功時は **1 回 1 行の要約** にし、個々のリクエストの詳細は失敗時と遅い(3 秒以上)ときだけ出す。
- **ログに機微情報が混ざる** → §3 の「記録しないもの」を守る。テスト④で検証。
- **ログの書き込みが生成を遅くする** → `non_blocking` で別スレッド書き込み。OFF が既定。
- **自前のローテーションの不具合(ファイルの取りこぼし・削除しすぎ)** → 削除は `gazooo-*.log` のみ・書き込み中は対象外・単体テストで保証。
- **原因が別のところにある場合**(例: ComfyUI 自体が OOM で終了) → プロセスの生存確認と終了コードをログに残すので切り分けられる。ComfyUI 側のログは `comfyui.log` を同梱する。

## 11. 受け入れ基準

- 「その他」タブでデバッグを ON/OFF でき、**再起動なし** で DEBUG ログの出力が始まる / 止まる。再起動後も設定が維持される。
- ON の間、接続断が起きたときに「どのリクエストが・どの種別で・何回連続して失敗したか」「WebSocket の切断理由」「(管理モード)ComfyUI のプロセスが生きていたか」がログから分かる。
- [ログを保存…] で ZIP が得られ、API キー・プロンプト本文を含まない。
- ログの合計が 1GB を超えると、古い `gazooo-*.log` から自動で削除され、書き込み中のファイルは残る。
- OFF の既定状態では、これまでと同等のログ量(INFO のみ)で、動作が変わらない。

## 13. 実装時の判断(設計との差異)・検証(実装済み)

**差異(いずれも軽微。設計の趣旨は変えていない)**
- **`Settings` に `debug` を含めない。** 初期表示・ステータスバーの「DEBUG」表示は `debug_status`(起動時に 1 回取得)から行う。`settings_update` が `debug.enabled` を受け付けない点は、そもそも `SettingsPatch` に項目が無いことで満たしている(§6 の「`settings_get` に含める」は採らなかった)。
- **旧方式のログ(`gazooo.log.YYYY-MM-DD`)も自動削除・手動削除の対象に含める**(`gazooo-*.log` と同じアプリのログとして扱う。移行直後の古いファイルが 1GB の計算から漏れないように)。
- **日付は UTC**(旧方式の日次ローテーションと同じ)。ZIP のファイル名の時刻も UTC。
- **[保存] ボタンは「その他」タブでは非表示**(§5 の「対象にしない」を、紛らわしくないよう表示ごと外した)。
- **ZIP の作成は既存の `zip`(`deflate` のみ)で書けた**ため、依存・feature の追加はなし(Q-178)。保存先がログフォルダ内でも、書き出し中の ZIP 自身は含めない。
- **ステータスバーの「DEBUG」はクリックで設定 > その他へ移動する。**

**実装の所在**: `src-tauri/src/services/debug_log/{mod,rotate,export}.rs`、`commands/debug.rs`。詳細ログの追加先は `engine/comfyui/{mod,generate}.rs`(HTTP の失敗・遅い GET・WebSocket の接続/切断・履歴ポーリングの失敗と復帰)、`services/engine.rs`(ヘルスチェックの所要時間と失敗、切断判定時のプロセス状態、連続失敗回数)、`services/jobs.rs`(開始・投入・画像受信・終了)。フロントは `lib/tauri/debug.ts`、`stores/debug-store.ts`、`components/settings/other-section.tsx`、`status-bar.tsx`。
