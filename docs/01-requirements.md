# 01. 要件定義

## 1. 目的

ローカル PC 上で Stable Diffusion 系 / Flux.1 モデルによる画像生成を行える、使いやすいデスクトップアプリを提供する。
生成した画像・プロンプト・パラメータをローカル DB で管理し、再現・再生成・整理を容易にする。

## 2. スコープ

### 2.1 MVP(v0.1)に含む

| ID | 機能 | 概要 |
|---|---|---|
| F-01 | エンジン接続 | ComfyUI のエンドポイント(既定 `http://127.0.0.1:8188`)へ接続し、状態を表示する |
| F-02 | txt2img 生成 | プロンプト・ネガティブ・モデル・サンプラー・ステップ・CFG・シード・解像度・枚数を指定して生成 |
| F-03 | モデル選択 | エンジンから取得したチェックポイント/Flux モデル一覧から選択 |
| F-04 | 進捗表示・キャンセル | ステップ進捗・プレビュー(取得可能なら)・キャンセル |
| F-05 | ジョブキュー | 複数ジョブを順次実行。待機中ジョブの並べ替え・削除 |
| F-06 | ギャラリー | 生成画像のグリッド表示、詳細表示、検索(プロンプト)、お気に入り、削除 |
| F-07 | 履歴・再現 | 画像からパラメータを復元して再生成(「この設定で生成」) |
| F-08 | プリセット | 生成パラメータの保存・呼び出し |
| F-09 | 設定 | エンジン接続先、画像保存先、テーマ(ライト/ダーク/システム)、言語 |
| F-10 | 画像出力 | 画像のエクスポート(名前を付けて保存)・フォルダを開く |

### 2.2 MVP に含まない(将来)

- LoRA(LoRA 適用は v0.2 候補)。inpaint は v0.5 の F-15(13)、img2img(画像からアニメ調へ)は v0.11 の F-18(19)で対応
- ComfyUI の自動インストール(MVP は「既に動いている ComfyUI に接続」)。起動管理は v0.7 の F-16(15)で対応(オプトイン)
- 組み込み推論エンジン(stable-diffusion.cpp 等)
- アップスケール、タグ補完、プロンプト生成支援
- クラウド同期、マルチユーザー、自動アップデート

### 2.2.1 v0.2 で追加する機能(設計: [10-assist-features.md](10-assist-features.md))

| ID | 機能 | 概要 |
|---|---|---|
| F-11 | 顔補正 | 生成画像の顔(選択により手)を自動検出し、その部分だけを再生成して仕上げる(ADetailer 相当)。SD1.5 / SDXL のみ |
| F-12 | ControlNet | 参照画像から輪郭・深度・ポーズを抽出し、構図の条件として生成に与える。SD1.5 / SDXL のみ、1 ユニット |

- いずれも ComfyUI 側のカスタムノード・モデルが必要で、アプリは導入の有無を検出して案内する。
- ワークフロー編集に慣れていないユーザーを想定し、**組み込みプリセット方式**(スイッチと少数のパラメータ)で提供する。ユーザー定義ワークフローのインポートは、この段階では対象外。

### 2.2.2 v0.3 で追加する機能(設計: [11-ai-assistant.md](11-ai-assistant.md)、承認済み)

| ID | 機能 | 概要 |
|---|---|---|

### 2.2.3 v0.4 で追加する機能(設計: [12-model-downloader.md](12-model-downloader.md)、レビュー待ち)

| ID | 機能 | 概要 |
|---|---|---|
| F-16 | ComfyUI の起動管理(15) | 設定で有効にすると、この PC の ComfyUI をアプリから起動・停止・再起動できる(オプトイン。既定は従来どおり別途起動した ComfyUI に接続)。アプリが起動したプロセスだけを対象にし、アプリ終了時に確実に停止する。保存先の反映(F-14)後の再起動にも使う |
| F-15 | Inpaint(13) | 参照画像にマスクを描き、マスク範囲だけを再生成する。マスク外は元画像と一致させる(合成あり)。SD1.5 / SDXL のみ。顔補正とは排他 |
| F-17 | アニメ特化モデル(16) | アニメ・イラスト特化チェックポイント(SDXL / SD1.5 派生)を取得ページのカタログに追加し、用途フィルタとアニメ向けの組み込みプリセットを提供する。新しいモデル種別は作らない |
| F-14 | モデル取得 | 専用ページ「モデル取得」から、同梱の厳選カタログ(チェックポイント・ControlNet・検出モデル)のモデルを、複数バージョン(ベースモデル・精度)から選んでダウンロードし、ComfyUI の `models/` へ配置する。取得はユーザーの明示操作時のみ。ハッシュで検証する |

| F-18 | 画像からアニメ調へ(19) | 元画像と変換の強さ(denoise)を指定し、元画像を出発点にアニメ系モデルで再生成する(img2img)。「構図を固定する」で ControlNet(輪郭)を自動設定する。SD1.5 / SDXL のみ。Inpaint とは排他。元画像からのプロンプト自動生成は対象外(画像編集モデルによる変換は F-19、タグの自動生成は F-20 で扱う) |
| F-20 | 画像からタグを作る(39) | 画像 1 枚を ComfyUI のカスタムノード(WD14 Tagger)で解析し、タグ列を得る。確認・編集のうえ、プロンプト欄へ「置き換え」「末尾に追加」で反映する。タグ列のみ(自然文は対象外)。画像は外部へ送らない(解析モデルの初回取得だけ ComfyUI 側が通信する)。ノードが無いときは機能を無効にして導入手順を案内。生成ジョブの実行中は使えない |
| F-19 | 参照画像つき生成(24) | Qwen-Image 2.1 で、参照画像を 1〜4 枚与え、プロンプト(`<image1>` などで参照画像を指す)の指示で編集・合成して生成する。出力サイズは 1 枚目で決まる。`qwen_image` のみ。Inpaint・img2img・ControlNet・顔補正とは併用しない。参照画像は外部へ送らない |
| F-21 | 顔の入れ替え(42) | Qwen-Image 2.1 で、顔画像 1 枚と対象画像(複数枚)を指定し、対象画像の顔(頭)だけを指定の顔に書き換える。参照画像つき生成(F-19)の上に、顔入れ替え専用の追加モデル(LoRA)を 1 つ適用する。「顔以外を元の画像のまま保つ」(既定オン)で、検出した頭・顔の範囲だけを元の画像へ貼り戻す(後段合成。顔補正と同じ検出ノードが必要)。対象画像ごとに 1 ジョブをキューに入れる。`qwen_image` のみ。他の画像入力機能とは併用しない。本人の同意のある顔だけに使う(画面に注記)。画像は外部へ送らない |

- アプリと同じ PC の ComfyUI が対象(リモートの ComfyUI のフォルダには配置できない)。
- 任意 URL・Civitai・認証が必要なモデルの取得、削除・移動は対象外。

### 2.3 非ゴール

- ComfyUI のノードエディタの再実装
- A1111 / Forge の拡張機構・拡張そのものとの互換、および Forge 独自の推論最適化の再現(推論は ComfyUI に任せる)
- 任意モデルの検索・配布マーケット(Civitai 連携は将来検討。F-14 の厳選カタログからの取得は対象)
- Linux の公式サポート

## 3. 想定ユーザー

画像生成に興味のあるデスクトップ PC ユーザー(Windows の NVIDIA GPU 環境、Apple Silicon Mac)。ComfyUI を自分で導入できる程度の技術リテラシーを MVP では想定する。

## 4. 非機能要件

| 区分 | 要件 |
|---|---|
| 対応 OS | Windows 10(22H2 以降)/ 11、macOS 13 以降(Apple Silicon)。両 OS で同一機能 |
| 性能 | UI は生成中もブロックしない。ギャラリー 1 万枚でもスクロールが滑らか(サムネイル+仮想化) |
| 信頼性 | アプリ強制終了後も DB が壊れない(SQLite WAL)。生成途中のジョブは再起動時に `interrupted` として復元可能 |
| プライバシー | 画像・プロンプトは外部送信しない。通信先は設定されたエンジン(既定はローカル)のみ。テレメトリなし。例外は、ユーザーが明示的に使う機能のみ: AI サポート(F-13、Anthropic)、モデル取得(F-14、押したときだけ許可リストのホストへ GET。ユーザー情報は送らない) |
| 保守性 | エンジンはトレイト(抽象)の裏に隠し、差し替え可能にする |
| i18n | UI 文言は辞書化。MVP は日本語・英語 |
| セキュリティ | Tauri の capability / CSP を最小権限で設定。WebView からの任意ファイル/コマンドアクセスを許可しない |
| 配布 | Windows: NSIS または MSI インストーラ、macOS: dmg(署名・公証は将来) |

## 5. 前提・依存

- 画像生成は ComfyUI の HTTP / WebSocket API に依存(MVP)。ComfyUI 自体と各モデルのライセンスはユーザー責任。Flux.1 dev は非商用ライセンスである旨を UI 内ヘルプで注意喚起する。
- 実行ハードウェアの推奨: Windows は VRAM 8GB 以上の NVIDIA GPU、Mac は 16GB 以上のユニファイドメモリ(Flux.1 は量子化モデル推奨)。

## 6. 受け入れ基準(MVP)

1. Windows 11 と macOS の両方でインストーラからインストール・起動できる。
2. 起動済み ComfyUI に接続し、SDXL と Flux.1(GGUF/FP8)の少なくとも 1 モデルずつで txt2img が完了する。
3. 生成画像がギャラリーに保存され、再起動後も残り、パラメータから再生成できる。
4. 生成中のキャンセルとキューの並べ替えが機能する。
5. ComfyUI 未起動・切断時に、分かりやすいエラーと再接続導線が表示される。

## 追記(v0.38・レビュー待ち): 画像の形式変換

| ID | 機能 | 内容 |
|---|---|---|
| F-22 | 画像の形式変換(43) | 専用ページ `/convert` で、画像ファイル(複数・フォルダ)をドラッグ&ドロップまたはダイアログで取り込み、PNG / JPEG / WebP へ一括変換する。入力の形式は中身で自動判断(**WebP 必須対応**・PNG・JPEG・GIF・BMP・TIFF)。出力の品質(JPEG・WebP は 1〜100、WebP はロスレスも可)と出力先フォルダを指定する。元ファイルは変更しない。ComfyUI に依存しない。参照画像の取り込み(F-12・F-19・F-21 など)でも WebP を受け付ける |
