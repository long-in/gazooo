# 25. 設定ページのタブ化(v0.17)

> ステータス: 🟢 承認済み・実装済み(2026-11-20。07 Q-124〜128 は推奨どおり。型チェック・ESLint・静的エクスポートのビルドまで確認。Vitest のコンポーネントテストと画面の目視確認は未実施)

## 1. 目的とスコープ

設定ページ(`/settings`)は、エンジン接続・ComfyUI のインストール・起動管理・保存先・AI サポート・表示の 6 ブロックが 1 本の縦スクロールに並び、見通しが悪くなっている。**カテゴリ別にまとめ、タブで切り替える UI** にする。

スコープ外: 各セクションの中身(項目・文言・動作)の変更、新しい設定項目の追加。バックエンド(Rust)・IPC・DB の変更は **なし**(フロントエンドのみ)。

## 2. カテゴリ分け

| タブ | 含めるセクション(現在のコンポーネント) | 備考 |
|---|---|---|
| エンジン | ComfyUI の URL、`EngineInstallSection`、`EngineProcessSection` | 「接続 → 導入 → 起動管理」の順を保つ |
| 保存先 | `StorageSection` | 画像・モデルの保存先 |
| AI サポート | `AssistantSection` | API キー・モデル・同意 |
| 表示 | テーマ・言語 | |

- 4 タブ。1 タブに入る量が偏りすぎる場合(エンジン)は、タブ内の見出し(`h2`)はそのまま残して区切る。
- タブの並び順は上表のとおり。既定で開くのは **エンジン**。

## 3. 振る舞い

- 部品は shadcn/ui の `Tabs`(`@base-ui/react/tabs` を使う `ui/tabs.tsx` を追加。`@base-ui/react` は導入済みで、新しい依存は増やさない)。キーボード(矢印キー)で切り替えられる。
- ページ幅は現状の `max-w-2xl` のまま。タブの見出しは `h1`「設定」の直下に置く。
- **[保存] ボタンはタブの外(ページ下部に固定せず、タブ領域の下)に 1 つだけ**置く。保存対象(URL・テーマ・言語)は複数タブにまたがるため、タブごとに分けない。未保存の入力(`draft`)は親コンポーネントが持つので、タブを切り替えても失われない。
- 各セクションは **非アクティブなタブでもマウントしたまま非表示**にする(`keepMounted`)。ComfyUI の起動ログの購読やインストール進捗のイベント購読が、タブ切り替えで途切れないようにするため。
- 保存の検証エラー(`comfyuiUrl` の不正など)が **別のタブの項目**に関するときは、保存ボタンの横にエラーを表示し、該当タブへ切り替える。
- 選択中のタブは URL の `?tab=engine|storage|assistant|display` で表す(静的エクスポートのため `useSearchParams` を `Suspense` で包む。ギャラリーの `?id=` と同じ方式)。他画面からの「設定を開く」(例: ComfyUI 未接続バナー、AI サポートの未設定案内)は、該当する `?tab=` を付けて遷移できる。不正な値は「エンジン」にする。

## 4. i18n

追加キー(`ja.ts` / `en.ts`):

- `settings.tabs.engine` = 「エンジン」/ Engine
- `settings.tabs.storage` = 「保存先」/ Storage
- `settings.tabs.assistant` = 「AI サポート」/ AI assistant
- `settings.tabs.display` = 「表示」/ Display

既存の `settings.*.title` 等はそのまま使う。

## 5. テスト

- Vitest(コンポーネント): 既定で「エンジン」が表示される、タブ切り替えで内容が切り替わる、`?tab=` の不正値でエンジンになる、タブを切り替えても `draft` の入力が残る、別タブの検証エラーで該当タブに切り替わる。
- 手動(09 に追加): 4 タブの切り替え・矢印キー操作、ComfyUI インストール中・起動中にタブを切り替えても進捗とログが途切れないこと、保存後の挙動、狭い画面での表示崩れが無いこと(Windows)。

## 6. 実装の分割(マイルストーン M21)

1. `ui/tabs.tsx` の追加と、`settings-form.tsx` のタブ化(`?tab=` を含む)。
2. i18n キー(ja / en)の追加。
3. 他画面の「設定を開く」リンクへの `?tab=` 付与。
4. Vitest と 09 のチェックリスト追加。

## 7. リスク

- 非表示のままマウントするため、初期表示のコストが増える。→ 各セクションは軽量で、起動ログ・進捗を途切れさせない利点を優先する。
- `?tab=` の導入で、既存のリンク(`/settings` のみ)が影響を受ける。→ 省略時は「エンジン」で従来と同等。
