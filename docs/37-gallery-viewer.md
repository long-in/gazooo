# 37. ギャラリーのビューア表示(v0.32、M32)

> ステータス: 🟢 承認済み・実装済み(2026-11-22。07 Q-263〜272 は推奨どおり。型チェック・ESLint・Vitest 290 まで確認。画面の目視確認は未実施。差異は §9)。フロントエンドのみの変更(Rust・IPC・DB の変更なし)。05 §4 への追記を伴う。

## 1. 目的

`/gallery` の画像一覧(グリッド)はそのまま残し、**表示方法を切り替えられる**ようにする。追加する表示方法は「ビューア」: 1 枚の画像を大きく表示し、ページ下部に他の画像を横一列に並べる。キーボードの ← → で下部の選択を動かし、選択中の画像が大きな画面に表示される。

スコープ外: 生成ページ下部のギャラリー帯(28)の変更。ビューアでの画像の編集・比較(2 枚並べなど)。スライドショーの自動送り。

## 2. 表示の切り替え

- 検索欄・お気に入りスイッチと同じ行(右端)に、**[グリッド] / [ビューア]** のセグメント切り替え(アイコン + ツールチップ。`role="radiogroup"`)を置く。
- 検索語・お気に入りの絞り込み・読み込み済みの一覧(`galleryStore`)は **両表示で共有** する。切り替えで読み込み直さない。
- 選択した表示方法はユーザーごとの設定として保存し、次回も復元する(Q-264)。
- URL は `/gallery/?view=viewer`(省略時はグリッド)。画像の詳細は従来どおり `?id=`(詳細シート)。

## 3. ビューアの画面

```
┌──────────────────────────────────────────────┐
│ 検索  ★お気に入りのみ                [▦][▣] │
├──────────────────────────────────────────────┤
│                                              │
│            (選択中の画像を大きく)            │
│                                              │
├──────────────────────────────────────────────┤
│ プロンプトの先頭 … · 1024×1024 · 3 / 120    │ ← 情報行
├──────────────────────────────────────────────┤
│ [▫][▫][■][▫][▫][▫][▫][▫]→ 横スクロール   │ ← ストリップ
└──────────────────────────────────────────────┘
```

- **メイン領域**: 選択中の画像を、領域に収まる最大サイズ(`object-contain`、縦横比を保つ)で表示する。原寸画像を使い、読み込み中はサムネイルを先に出す(ちらつき防止)。
- **情報行**: プロンプト先頭(1 行・省略)、実サイズ、「n / 件数」。右に **[詳細]**(詳細シートを開く)・**[★]**(お気に入りの切り替え)・**[削除]**。
- **ストリップ**: 下部に固定の高さ(サムネイル約 80px)で横一列。**選択中のサムネイルを枠で強調**し、常にストリップの可視範囲内(なるべく中央)へスクロールする。既存のサムネイル(遅延ロード)を使う。
- 右端に近づいたら続きを読み込む(`loadMore`)。ストリップが一杯になる前の件数でも動く。
- 一覧が空・検索結果なしのときは、グリッドと同じ空状態の文言を出す。

## 4. 操作

| 入力 | 動作 |
|---|---|
| `→` / `←` | 次 / 前の画像を選択(端で止まる。ループしない)。**キーを押しっぱなしで連続移動**できる |
| `Home` / `End` | 先頭 / 末尾へ(末尾は読み込み済みの最後) |
| `Enter` | 詳細シートを開く |
| `F` | お気に入りの切り替え |
| `Delete` | 削除の確認ダイアログ |
| ストリップのクリック | その画像を選択 |
| ストリップ上のホイール | 横スクロール(縦ホイールも横へ。28 と同じ) |
| メインの画像のダブルクリック | 詳細シートを開く |

- キー操作は、**入力欄(検索など)・詳細シート・ダイアログにフォーカスがあるときは無効**(IME 変換中も無視)。ビューアを開いた時点では、メイン領域にフォーカスを置く。
- 詳細シートを閉じたら、選択はそのまま。ビューアの選択を `?sel=<画像 ID>` ではなく **ストアの `viewerId`** で保持し、グリッドへ切り替えて戻っても維持する。
- 画像を削除したら、**次の画像(なければ前)を選択**する。一覧が 0 件になったら空状態。
- 検索語・絞り込みの変更で、選択中の画像が一覧から消える場合は先頭を選択する。
- 複数選択(グリッドの Shift/Ctrl)はビューアでは使わない。グリッドで選択中に切り替えた場合、選択は保持するがビューアでは表示しない。

## 5. アクセシビリティ・見た目

- ストリップは `role="listbox"`、各サムネイルは `role="option"` + `aria-selected`。選択は `aria-activedescendant` で通知する。メイン画像の `alt` はプロンプトの先頭。
- フォーカスリング・コントラストは 29(プロの見た目)のトークンに従う。ダーク背景の上で画像を見やすくするため、メイン領域の背景は中間色の無地。
- `prefers-reduced-motion` ではストリップのスクロールを即時にする(アニメーションなし)。
- 最小ウィンドウ(960×640)でも、メインが十分な高さを持つ(ストリップ + 情報行は合計 約 140px)。

## 6. 実装方針(承認後)

- 新規: `src/components/gallery/gallery-viewer.tsx`(メイン + 情報行 + ストリップ)。`gallery-view.tsx` に切り替え UI と表示の分岐を追加する。
- ストアに `viewerId`(選択中の画像 ID)を追加。移動・削除後の補正はストア内の純関数にして Vitest で試験する(端の挙動・削除後の選択・絞り込みで消えた場合)。
- キーボード処理は専用フック(`useViewerKeys`)に分け、無効にする条件(入力欄・ダイアログ・IME)を試験する。
- 画像の取得は既存の経路(`convertFileSrc` など、`gallery-grid.tsx` / `image-detail-sheet.tsx` と同じ)を使う。新しい IPC は追加しない。
- i18n(ja / en)に文言を追加する。
- 09 に手動確認項目を追加する(連続移動の滑らかさ・1 万枚規模でのストリップの描画・キーの無効条件)。

## 7. 性能

- ストリップは **仮想化**(`@tanstack/react-virtual` の横方向。グリッドと同じ依存)。1 万枚でも描画するサムネイルは可視範囲 + 余白のみ。
- メインの原寸画像は、選択が変わるたびに差し替える。**前後 1 枚ずつを先読み**する(`Image` のプリロード)。素早い連続移動では、止まった時点の画像だけを読み込む(約 80ms のデバウンス。サムネイルは即時に出す)。

## 9. 実装との差異

- 表示方法の保存は、`settings.uiState.panels["gallery.viewer"]`(29 §6 の画面状態。ユーザーごと)を使う。`?view=` の URL パラメータは設けない(保存値が正)。
- 情報行のプロンプトは一覧の項目に含まれないため、選択が止まってから `image_get`(既存)で取得して表示する。
- 純関数(移動・削除後の選択・キー対応・入力欄の判定)は `src/lib/viewer-nav.ts`(Vitest あり)。キー処理は専用フックでなく `GalleryViewer` 内の `onKeyDown`。
- お気に入り絞り込み中に解除した場合も、削除と同じ規則で次の画像へ選択を送る。
