# 40. プロジェクト(作業フォルダ)機能(v0.35、M35)

> ステータス: 🟢 承認済み・実装済み(2026-11-23。07 Q-301〜318 は推奨どおり。Rust 459・Vitest 337・clippy・ESLint・静的エクスポートのビルドまで確認。画面の目視確認・Windows 実機・macOS は未実施。差異は §10。03・04・05・35・09 への追記を反映済み)。

## 1. 目的

画像生成は「特定の対象(キャラ・案件・テーマ)に対して、条件を変えながら繰り返し試す」作業が中心である。そこで **プロジェクト** を導入する。プロジェクトは画像の入れ物であると同時に、**その対象で最後に使った生成設定の入れ物** でもある。

- プロジェクトを開く = その対象の続きから生成できる(前回のモデル・サイズ・プロンプト等がフォームに入る)。
- 生成した画像は自動でそのプロジェクトに入る(手動の仕分けは不要)。
- ギャラリーでは、プロジェクトの垣根を越えて **すべての画像を階層なし(フラット)** に見られる。**お気に入りも、プロジェクトをまたいでフラットに** 見られる。

スコープ外: プロジェクトの入れ子(階層)・共有/エクスポート単位としてのプロジェクト・タグ・生成履歴の派生ツリー・プロジェクトごとの画像保存先(物理フォルダは分けない)。

## 2. 用語と基本方針

- **プロジェクト**: ユーザーごとの作業単位。名前・色(任意)・並び順・最後に使った生成設定を持つ。**1 階層のみ**(入れ子にしない)。
- **未分類**: どのプロジェクトにも属さない画像。既存の画像はすべて未分類になる(移行時に何も動かさない)。
- **現在のプロジェクト**: 生成ページで選んでいるプロジェクト(なし = 未分類)。ユーザーごとの画面状態として保存し、次回起動でも復元する。
- 1 枚の画像は **高々 1 つのプロジェクト** に属する。横断的な見方はプロジェクトではなく、ギャラリーの「すべて」「お気に入り」で行う(§5)。
- **物理ファイルは動かさない**。プロジェクトとの紐づけは DB のみ(画像の保存先・`images_dir` の構成・サムネイルは 03 のまま)。移動・削除でファイル操作が発生せず、バックアップ(35)のファイル構成にも影響しない。
- プロジェクトはユーザーごとの DB(`users/<id>/gazooo.db`。36)に置く。ユーザーをまたいで共有しない。

## 3. データモデル

マイグレーション `0004_projects.sql`(前方互換のみ。03 の方針どおり、適用前に DB のバックアップを作る)。

```sql
CREATE TABLE projects (
  id           TEXT PRIMARY KEY,
  name         TEXT NOT NULL UNIQUE,         -- 1〜60 文字(前後の空白は除去)
  color        TEXT,                         -- パレット名(red / orange / amber / green / teal / blue / violet / pink)または NULL
  sort_order   INTEGER NOT NULL,             -- 小さいほど上
  last_params_json TEXT,                     -- 最後にこのプロジェクトで投入した GenerationParams(無ければ NULL)
  created_at   INTEGER NOT NULL,
  updated_at   INTEGER NOT NULL
);

ALTER TABLE jobs   ADD COLUMN project_id TEXT REFERENCES projects(id) ON DELETE SET NULL;
ALTER TABLE images ADD COLUMN project_id TEXT REFERENCES projects(id) ON DELETE SET NULL;

CREATE INDEX idx_images_project ON images(project_id, created_at DESC, id DESC);
CREATE INDEX idx_jobs_project   ON jobs(project_id);
```

- `jobs.project_id`: ジョブ投入時に確定する出力先。キューの表示・再試行(`job_retry`)で引き継ぐ。
- `images.project_id`: 画像の保存時に `jobs.project_id` を写す。**画像の移動はこちらだけを更新** する(ジョブは変えない)。ギャラリーの絞り込みはこの列を使う。
- プロジェクトを削除すると、`ON DELETE SET NULL` により画像・ジョブは **未分類へ戻る(画像は消えない)**。
- `last_params_json` は `job_enqueue` の成功時に Rust 側が更新する(フロントからは書かない)。`seed` を含め丸ごと保存し、復元側で `seedRandomize` に従って扱う。
- ギャラリーの「すべて」「お気に入り」は既存の `idx_images_created_at` / `idx_images_favorite` をそのまま使う(性能の変更なし)。

## 4. 生成ページ

### 4.1 プロジェクトの切り替え

- 生成ページのコンテキストバー(29)に **プロジェクト選択**(ドロップダウン)を置く。項目は「未分類」+ 各プロジェクト + 末尾の [+ 新規プロジェクト…](名前入力のダイアログ)。
- 選択を切り替えると:
  1. そのプロジェクトの `lastParams` があれば、**フォームへ適用する**(プリセット適用(21)と同じ規則。存在しないモデル等は既存の「見つからない」扱い)。無ければ **現在のフォームをそのまま使う**(新規プロジェクトで、直前の設定から作り始められる)。
  2. 適用でフォームが上書きされる場合、**「元に戻す」付きのトースト** を出す(確認ダイアログは出さない)。
- 切り替えは「現在のプロジェクト」を保存するだけで、キュー・ギャラリー帯の既存の項目は消さない。
- かんたん / 詳細モード(38)・下書きモード(33)・フォームの初期化(21)には影響しない。[すべて初期化] はプロジェクトの `lastParams` を消さない(次回の生成で上書きされる)。

### 4.2 生成と保存先

- `job_enqueue` に `projectId` を渡す。そのジョブが作る画像は、そのプロジェクトへ入る(未分類のときは `null`)。
- ジョブ投入が成功したら、そのプロジェクトの `lastParams` を更新する(手動の「保存」操作は不要)。
- 待機中のジョブは **投入時点のプロジェクト** に入る(後でプロジェクトを切り替えても、既に投入済みのジョブの行き先は変わらない)。
- 「この設定で生成」(ギャラリーから設定を読み込む)・「ベースにする」(27)は、**読み込んだ画像の所属に関わらず、現在のプロジェクトに生成結果が入る**。

### 4.3 ギャラリー帯(28)

- 帯に出す画像は **現在のプロジェクトの画像** を既定とし、帯の右端に **[このプロジェクト / すべて]** の切り替えを置く(状態はユーザーごとに保存)。「すべて」は未分類・他のプロジェクトも含む。
- キュー(帯の左側)は常にすべてのジョブを出す(プロジェクトで絞らない)。各カードにはプロジェクト名の小さなチップを付ける(切り替えで追跡しやすくするため。現在のプロジェクト以外のときのみ表示)。

## 5. ギャラリーページ

### 5.1 スコープ(見る範囲)

`/gallery` の左に、折りたたみ可能な **スコープパネル** を置く(幅・開閉は 29 §6 の画面状態に保存)。

```
┌ スコープ ────────┐
│ ▦ すべて      1,240 │ ← プロジェクトの垣根なし・階層なし
│ ★ お気に入り     86 │ ← 同上。お気に入りのみ
│ ◌ 未分類        312 │
│ ─────────────── │
│ ● キャラA        210 │
│ ● 背景テスト      95 │
│ ● …                 │
│ [+ 新規プロジェクト]  │
└───────────────┘
```

- **すべて**: 全画像を、プロジェクトに関係なく 1 本の新しい順の一覧で見る(階層なし)。
- **お気に入り**: 全プロジェクトのお気に入りのみを、1 本の新しい順の一覧で見る(階層なし)。
- **未分類**: どのプロジェクトにも属さない画像。
- **各プロジェクト**: そのプロジェクトの画像のみ。
- 件数は各項目に表示する(`project_list` で一括取得。画像の追加・削除・移動・お気に入り変更のイベントで更新)。
- 既存の検索欄・[★お気に入りのみ] スイッチは **どのスコープでも併用できる**(スコープ内の絞り込み)。**[お気に入り] スコープ = 「すべて」+ スイッチ ON のショートカット** で、スイッチと常に同期する(スコープを [すべて] に切り替えるとスイッチも解除、スイッチを ON にしても選択はスコープに反映されて [お気に入り] が強調される。プロジェクト内でスイッチを ON にした場合は、そのプロジェクトのお気に入りのみ)。
- 選択中のスコープは URL `/gallery/?scope=all|favorites|unassigned|project&p=<id>` で表し、ユーザーごとに保存して次回も復元する。初回の既定は **すべて**。
- ビューア表示(37)・グリッド表示は **スコープを共有** する(切り替えで読み込み直さない既存の規則は、スコープ変更時のみ再読み込み)。

### 5.2 一覧上の表示

- **すべて / お気に入り** のスコープでは、各画像(グリッドのカード・ビューアの情報行)に、所属プロジェクトを **色付きの小さなチップ** で表示する(未分類は表示しない)。クリックでそのプロジェクトのスコープへ移動する。プロジェクト内のスコープではチップを出さない。
- 詳細シート(`?id=`)に「プロジェクト」欄(現在の所属とその変更)を追加する。

### 5.3 画像の移動

- グリッドの複数選択(Shift / Ctrl)から **[プロジェクトへ移動]**(プロジェクト一覧 + 「未分類」+ 「新規プロジェクト…」の選択メニュー)。ビューアの情報行・詳細シートからも 1 枚を移動できる。ドラッグ & ドロップでスコープパネルのプロジェクトへ移すのも可(グリッドの選択をドラッグ)。
- 移動は DB の更新のみで、ファイルは動かさない。取り消しは「元に戻す」トースト(直前の所属へ戻す)。
- お気に入りの切り替え・削除は、プロジェクトに関係なく従来どおり。

### 5.4 プロジェクトの管理

スコープパネルのプロジェクトの右クリック(または ⋯ メニュー)で次を行う。

| 操作 | 内容 |
|---|---|
| 名前の変更 | 1〜60 文字。重複は不可(`VALIDATION`) |
| 色の変更 | 8 色程度のパレット + なし |
| 並べ替え | ドラッグ & ドロップ。キーボードは上へ / 下へ(アクセシビリティ) |
| 削除 | 確認ダイアログ(「画像は削除されず、未分類へ戻ります」と明示)。画像は **消えない** |

## 6. 既存機能との関係

- **プリセット(`presets`)**: 変更なし。プリセットは **プロジェクトをまたいで使い回す雛形**、プロジェクトの `lastParams` は **その対象の続き** で、役割が異なる。プロジェクトに紐づくプリセットは作らない。
- **ユーザー(36)**: プロジェクトはユーザーごとの DB に入る。ユーザーの削除でそのユーザーのプロジェクトも消える(既存の規則)。
- **バックアップ(35)**: `projects` テーブルは **ギャラリー区分** に含める(`images.project_id` の参照先のため)。取得は `projects` も含め、OFF のときは `projects` を空にする。復元は `jobs`・`images` と一緒に `projects` も置き換える(`DELETE` → `INSERT … SELECT`、両方に存在する列のみ)ため、**`project_id` 列を持たない旧バックアップの復元では、すべて未分類になる**(エラーにしない)。復元の順序は `projects` → `jobs` / `images`。`counts` に `projects` を追加する。
- **画像からタグ(39)・Inpaint・ControlNet の参照画像**: `inputs/` の画像はギャラリー(`images`)に載せない既存の方針のため、プロジェクトの対象外。
- **AI サポート(11)**: 機能カタログに「プロジェクト」の説明を追記する(現在のプロジェクト名・`lastParams` の有無は送らない。送信内容の規則は 11 のまま)。

## 7. IPC(04 への追記案)

```ts
interface Project {
  id: string;
  name: string;
  color: string | null;
  sortOrder: number;
  imageCount: number;
  coverImageId: string | null;     // 最新の画像(サムネイル用。無ければ null)
  hasLastParams: boolean;          // 前回の設定があるか(本体は project_get で取る)
  createdAt: number; updatedAt: number;
}
```

| コマンド | 引数 | 戻り値 | 説明 |
|---|---|---|---|
| `project_list` | – | `{ projects: Project[]; totalImages: number; favoriteImages: number; unassignedImages: number }` | スコープパネル用。件数を一括取得 |
| `project_get` | `{ id }` | `{ project: Project; lastParams: GenerationParams \| null }` | 切り替え時にフォームへ適用する設定を含む |
| `project_create` | `{ name; color?: string }` | `Project` | 末尾へ追加。`name` の重複・長さ違反は `VALIDATION` |
| `project_update` | `{ id; name?; color?: string \| null }` | `Project` | |
| `project_reorder` | `{ ids: string[] }` | `void` | 全プロジェクトの新しい並び(過不足があれば `VALIDATION`) |
| `project_delete` | `{ id }` | `number` | 画像・ジョブは未分類へ戻す。戻り値は未分類へ戻った画像数 |
| `image_move` | `{ ids: string[]; projectId: string \| null }` | `void` | `images.project_id` のみ更新(最大 500 件。超過は `VALIDATION`)。存在しない `projectId` は `PROJECT_NOT_FOUND` |

既存コマンドの変更(いずれも省略時は従来どおり = 互換):

- `job_enqueue`: `projectId?: string | null` を追加(存在しなければ `PROJECT_NOT_FOUND`)。
- `image_list`: **`scope?: "all" | "unassigned" | { projectId: string }`** を追加(省略 = `all`。既存の `query`・`favoritesOnly` と併用)。お気に入りのスコープは `scope` 省略 + `favoritesOnly: true`。
- `ImageItem`: `projectId: string | null` を追加。`Job`: `projectId` を追加。
- イベント: `project://changed`(作成・更新・削除・並べ替え・件数が変わる移動。ペイロードなし。受けたら `project_list` を取り直す)。画像の移動は `image://moved`(`{ ids: string[]; projectId: string | null }`)を発火し、グリッド・ビューアが表示中の一覧を更新する。

エラーコード: 名前の重複・長さ違反は `VALIDATION`(`details.field = "name"`。プリセットと同じ)。存在しないプロジェクトの指定は新設の `PROJECT_NOT_FOUND`(`project_get` / `project_update` / `project_delete` / `image_move` / `job_enqueue` / `image_list`)。存在しない画像は既存の `IMAGE_NOT_FOUND`。

## 10. 実装との差異

- **色**は `#rrggbb` ではなく、ユーザーカラー(36)と同じ 8 色のパレット名(`red` … `pink`)で保存する(表示色はアクセントの定義を共有)。
- **`project_update` は名前と色を置き換える**(`{ id, name, color }`。部分更新ではない。色を残すときは現在値を渡す)。
- **ドラッグ & ドロップは実装しない**(画像のスコープパネルへの移動・プロジェクトの並べ替え)。Tauri のウィンドウの既定(`dragDropEnabled`)が、Windows でページ内の HTML5 ドラッグ & ドロップを横取りするため。代わりに、画像の移動はメニュー([プロジェクトへ移動])、並べ替えは [上へ / 下へ] で行う(キーボードでも操作できる)。設定を変えて DnD を有効にする場合は、ファイルのドロップ機能との兼ね合いを含めて別途設計する。
- **新しいプロジェクトの作成直後**は、そのプロジェクトに切り替える(生成ページの [+]。ギャラリーのパネルでは作成したプロジェクトのスコープへ移る)。
- 件数・プロジェクト一覧は、`project://changed`・`image://created`・`image://deleted` を 200ms にまとめて取り直す。
- AI サポートの機能カタログ(11)に「プロジェクト」の説明を 1 項目追加した(`FEATURE_NAMES` は 11 件)。現在のプロジェクト名・設定は送らない。
- 旧バックアップ(`projects` テーブル・`project_id` 列なし)の復元は、既存の「両方に存在する列・テーブルのみ」の規則で、すべて未分類になる(専用のテストは追加していない。09 の手動確認項目に入れた)。
- 帯(28)の [このプロジェクト / すべて] は `settings.uiState.panels["strip.allProjects"]` に保存する(既定 = このプロジェクト)。

## 11. 追補: スコープパネル(ギャラリーのナビ)の改善(v0.38、M38)

> ステータス: 🟢 承認済み・実装済み(2026-11-23。Q-A〜D は推奨どおり。差異は §11.7)。現状の §5.1 のパネルに対する操作性・見た目・構成の改善。新しい IPC・DB 変更はなし(フロントエンドのみ)。

### 11.1 課題

- マウス操作のみで、キーボードでスコープを移動できない。
- プロジェクトが増えると長い一覧から探しにくい(検索・折りたたみがない)。
- 折りたたむとアイコン 1 つだけになり、現在のスコープも件数も分からない。
- 現在のスコープ名・件数が一覧側(右の領域)に出ておらず、検索・表示切り替えとの位置関係が分かりにくい。
- 並べ替えは [上へ / 下へ] を 1 つずつ押す必要がある。

### 11.2 操作性

- **キーボード**: パネル内で ↑ / ↓(Home / End)で項目間を移動、Enter / Space で選択。フォーカスは項目 1 つのみがタブ停止(roving tabindex)。項目上の `F2` で名前変更、`Delete` で削除確認(既存ダイアログ)。メニューボタンは `Shift+F10` / ContextMenu キーでも開く。
- **右クリック**: プロジェクト行の右クリックで既存の [⋯] メニュー(名前・色の変更 / 上へ / 下へ / 削除)を開く。
- **絞り込み**: プロジェクトが 8 件を超えたとき、「プロジェクト」見出しの下に小さな検索欄を出す(名前の部分一致。一致しない項目は隠す。固定項目の「すべて」「お気に入り」「未分類」は常に表示)。選択中のプロジェクトは絞り込みで隠れても選択は維持する。
- **セクションの折りたたみ**: 「プロジェクト」見出しを開閉でき、状態は 29 §6 の画面状態(`settings.uiState.panels["gallery.scope.projects"]`、既定 = 開)に保存する。
- 並べ替えのドラッグ & ドロップは、§10 の理由(Tauri の `dragDropEnabled`)により **引き続き実装しない**。[上へ / 下へ] を維持し、メニューを開いたままで連続して押せるようにする(押しても閉じない)。

### 11.3 見た目・情報量

- **折りたたみ時のミニ表示**: アイコン 1 つではなく、幅 48px の縦レールに「すべて」「お気に入り」「未分類」+ 各プロジェクトの色ドットを並べる(件数はツールチップ。現在のスコープは強調)。クリックでスコープ切り替え。[展開] ボタンは先頭に置く。
- **件数**: 1,000 以上は `1,240` のように桁区切り、10,000 以上は `1.2万`(ja)/ `12k`(en)に短縮(幅の安定のため。ツールチップに正確な値)。
- **選択中の強調**: 背景(secondary)に加え、左端に 2px のアクセント線を出す(色覚に依存しないよう、`aria-current` を維持)。プロジェクトはその色の線。
- **現在のスコープ名の表示**: 一覧上部のツールバー左に、スコープ名と件数を見出しとして出す(例:「キャラA ・ 210 枚」)。検索語またはお気に入りスイッチで絞っているときは「(絞り込み中: n 枚)」を併記する。
- 件数 0 のプロジェクトは名前を `text-muted-foreground` にする。長い名前は省略し、ツールチップで全文を出す(現状どおり truncate + `title`)。

### 11.5 実装方針(承認後)

- `gallery-scope-panel.tsx` を、`ScopeRail`(折りたたみ)・`ScopeList`(展開)・`ProjectRow` に分割する。キー移動と絞り込みの判定は純関数として `src/lib/projects/scope-nav.ts` に置く(Vitest: 次/前/先頭/末尾の移動、絞り込み(選択中は残す)、件数の短縮表記)。
- `gallery-view.tsx` のツールバーにスコープ名・件数の見出しを追加(絞り込み中の件数は既存の一覧件数を使用)。
- i18n(ja / en)に、見出し・絞り込み欄・件数表記・ツールチップを追加。
- 09 の手動確認項目に、キーボード操作・右クリック・折りたたみ時のレール・狭い幅での既定を追加。

### 11.6 未決事項(推奨で進める。承認時に変更可)

- Q-B: 折りたたみ時の表示(推奨 = 色ドットのレール。代案 = 従来のアイコンのみ)。
