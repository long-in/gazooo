# 21. 生成フォームの初期化と項目の説明表示(v0.13)

> ステータス: 🟢 承認済み(2026-11-19。07 Q-100〜103 は推奨どおり)・実装済み

## 1. 目的とスコープ

生成画面のフォームに、次の 2 つを足す。

- **A. 初期化**: 入力したプロンプトや設定を、ワンクリックで空・初期値に戻す。
- **B. 項目の説明**: プロンプト・ネガティブプロンプトなど各項目の横に「?」アイコンを置き、押す(またはホバー・フォーカスする)と、その項目の意味と書き方の説明を表示する。

スコープ外: 説明文の AI による自動生成、説明文のユーザー編集、プリセット(08 F-08)の仕様変更。バックエンド(Rust)・IPC・DB の変更は **なし**(フロントエンドのみ)。

## 2. A. 初期化

### 2.1 ボタンの種類

| 場所 | ボタン | 動作 |
|---|---|---|
| プロンプト欄のラベル横 | [クリア] | `prompt` を空にする |
| ネガティブ欄のラベル横 | [初期値に戻す] | `negativePrompt` を、**現在のモデル種別・選択中モデルの既定値**(Anima の品質タグ、アニメ用プリセットの推奨など。17・18 の既定)に戻す。既定が無い種別では空にする |
| フォーム上部(プリセット欄の並び) | [すべて初期化] | 下記 §2.2 |

### 2.2 [すべて初期化] の範囲

- 戻す: プロンプト、ネガティブ、サイズ、ステップ、CFG / Guidance、サンプラー、スケジューラ、シード(ランダムに戻す)、枚数。サイズ・ステップ等は **現在のモデル種別の推奨値**(17・18)に戻す。
- **戻さない(保持する)**: モデル種別とモデルの選択、CLIP / VAE の選択(毎回選び直す手間が大きいため)。
- 拡張機能(画像から生成・Inpaint・ControlNet・顔補正)は **無効にして参照画像も外す**(Q-100 で切り替え可)。
- 誤操作の防止: 内容が空でない場合は確認ダイアログ(shadcn の `AlertDialog`)を出す。プロンプト欄の [クリア] は確認なしで、**直前の内容を「元に戻す」トースト(約 8 秒)で復元できる**。
- 実行中・待機中のジョブには影響しない(投入済みの設定は変わらない)。
- フォームの下書き保存(設定の下書きと同じ保存先)にも、初期化後の値が反映される。

### 2.3 実装方針(参考)

- 既定値の定義は、フォームの初期値を作る既存の関数(`defaultParams` 相当)と、モデル種別ごとの推奨値の既存テーブルを **再利用** する。新しい既定値の二重管理は作らない。
- 実装箇所: `src/components/generate/generation-form.tsx`(ボタン)、フォームの状態ストアに `resetPrompt` / `resetNegative` / `resetAll` を追加。

## 3. B. 項目の説明表示

### 3.1 UI

- 共通部品 `Field`(`src/components/generate/fields.tsx`)に、任意の `help` プロパティ(i18n キー)を追加する。指定があるとラベルの右に「?」アイコン(`lucide-react` の `CircleHelp`)を表示する。
- 「?」を押す・フォーカスすると、shadcn の `Popover` に説明を表示する(キーボード操作可。`aria-label` は「{項目名}の説明」)。ホバーのみの `Tooltip` は、タッチ・キーボードで使えないため使わない。
- 説明は短く(3〜5 行)。**意味・目安の値・よくある失敗**の順で書く。外部リンクは置かない。

### 3.2 説明を付ける項目と内容(日本語の草案。英語は `en.ts` に同内容を訳す)

| 項目 | 説明の草案 |
|---|---|
| プロンプト | 描きたい内容を言葉で書く欄。被写体・場所・雰囲気・画風の順に、具体的に書くと安定する。SD 1.5 / SDXL は英単語をカンマ区切りで、Flux / Qwen-Image 等は文章でも可。アニメ系は Danbooru タグ形式(モデルの説明に従う) |
| ネガティブプロンプト | 「描いてほしくないもの」を書く欄(例: `lowres, blurry, extra fingers`)。入れすぎると絵が崩れるので、まずは短く。Flux・Krea 2 では使われない |
| モデル種別 / モデル | 種別はモデルの系統(SD 1.5・SDXL・Flux 等)。種別ごとに使える機能と推奨設定が違う。モデルは種別に合うファイルだけ選べる |
| サイズ | 生成する画像の幅×高さ(px)。モデルが学習した大きさ(SD 1.5: 512、SDXL・Flux: 1024 前後)から離れると破綻しやすい。大きいほど時間とメモリを使う |
| ステップ | 画像を整える反復回数。多いほど細かくなるが、一定を超えると変わらず遅くなるだけ。20〜30 が目安(種別の推奨値に従う) |
| CFG | プロンプトにどれだけ忠実かの強さ。高すぎると色が濃く不自然に、低すぎるとプロンプトを無視する。SD 系は 5〜8 が目安 |
| Guidance(Flux) | Flux 用の CFG 相当。3.5 前後が目安 |
| サンプラー / スケジューラ | 画像を整える計算方法。迷ったら種別の推奨値のまま。変えると絵の雰囲気が少し変わる |
| シード | 乱数の元。同じシード・同じ設定なら、ほぼ同じ絵になる。固定すると、他の設定だけを変えて比較できる |
| 枚数 | 1 回の投入で作る枚数(シードは枚数分ずつ変わる) |
| 拡張機能 | 画像から生成の強さ(変化量)、Inpaint のマスク、ControlNet の強さ、顔補正の効果など、各セクションの主要項目にも同じ形式で付ける |

説明文は `src/lib/i18n/ja.ts` / `en.ts` に `help.*` として置く(コードに直書きしない)。

### 3.3 AI サポートとの関係

AI サポートの「現在のフォーム」文脈(11 §4)・提案の適用には変更なし。説明文は静的な文言で、Anthropic には送らない。

## 4. テスト

- Vitest: `resetAll` が「モデル選択を保持し、他を推奨値に戻す」こと、ネガティブの既定が種別ごとに正しいこと、[クリア] の取り消しで元の内容に戻ること、拡張機能が無効になること。
- コンポーネント: `help` 指定の `Field` が「?」を出し、キーボードで開閉できること。`help` を指定しない `Field` は従来どおりの見た目。
- 手動(09 に追加): 各項目の「?」の表示・開閉、[クリア] と元に戻す、[すべて初期化] の確認ダイアログと保持される項目、Windows の狭い画面での表示崩れが無いこと。

## 4.1 実装時の判断(設計との差異)

- **ネガティブの [初期値に戻す]** は、種別の既定値(`defaultParams(kind).negativePrompt`。現状は Anima のみ品質タグ、他は空)に戻す。アニメ用組み込みプリセット(16 §5)のネガティブは対象にしない(プリセット欄で再適用できる)。
- **[すべて初期化]** は常に確認ダイアログを出す(内容が空かどうかは見ない)。枚数も 1 に戻す。
- 説明の文言は、`Field` の `help` プロパティに **翻訳済みの文** を渡す(キーは `help.*`)。`Popover` は `@base-ui/react/popover` を使う `ui/popover.tsx` を追加。
- 拡張機能の説明は主要項目(画像から生成・Inpaint・顔補正の強さ、ControlNet の強さ)に付けた。

## 5. 実装の分割(マイルストーン M17)

1. 状態ストアの `reset*` と、既定値の再利用(Vitest 付き)。
2. 生成フォームのボタンと確認ダイアログ・取り消しトースト。
3. `Field` の `help` と `Popover`、`help.*` の文言(ja / en)。
4. 09 のチェックリスト追加。

## 6. リスク

- 説明文が実際の挙動とずれる。→ 数値の目安は 17・18 の推奨値と同じ出典に揃え、種別ごとに違う値は「種別の推奨値に従う」と書いて数値を直書きしない。
- [すべて初期化] の誤操作。→ 確認ダイアログと、保持する項目(モデル選択)の明示で軽減する。
