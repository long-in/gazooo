# 29. 「プロ向け制作アプリ」の見た目への刷新(Photoshop 風のワークスペース)(v0.21)

> ステータス: 🟢 承認済み(2026-11-20。07 の Q-146〜153 は推奨どおり)。**段階 A は実装済み**(型チェック・ESLint・Vitest 220・Rust の設定のテスト・ビルドまで確認。ヘッドレスブラウザで生成ページの見た目を確認。実機の画面は未確認)。B〜D は未着手。
> 経緯: ユーザーから「各ページがシンプル過ぎる。デザインをかっこよくしてほしい。イメージは Photoshop のような管理アプリ」との指示があった。画像を主役にした、**暗い・高密度・パネル構成**の制作アプリの見た目にする。機能(IPC・DB・Rust)は変えない。

## 0. 段階 A の実装時の判断(設計との差異)

- 既定テーマは Rust の `Theme::default()` を `Dark` にした(新規インストール・未保存の設定のみ。保存済みの値は変わらない)。`next-themes` の `defaultTheme` も `dark`。
- パネルの開閉・幅・密度は、Q-152 のとおり `settings.uiState`(03 の `ui.state`)に保存する。Rust は `ui_state`(オブジェクトのみ許可)を `Settings` / `SettingsPatch` に追加(04 に追記)。フロントは `stores/ui-store.ts`(600ms のデバウンスで自動保存)と `lib/ui-state.ts`(検証)。
- 密度は CSS 変数 `--ctl-h` 系で切り替える(`data-density`)。設定の「表示」タブで即時に切り替わり、[保存] を待たない。
- コンテキストバーは、現時点ではページ名だけ(各ページの操作列は、段階 B 以降でページごとに移す)。各ページの見出し(`h1`)は読み上げ用に `sr-only` にした。
- ツールバーのテーマ切替は、表示だけの切り替え(設定の「テーマ」は変えない)。
- ステータスバーに実行状況(旧ヘッダの細い帯)とエンジンの接続状態(旧ナビ下部)を移した。保存先の空き・バージョンは、新しい IPC が要るため入れていない。
- `Panel`(`components/ui/panel.tsx`)は追加済みだが、使い始めるのは段階 B 以降。

## 1. 目的とスコープ

**やること**
- 見た目の土台(**配色・密度・タイポグラフィ・部品**)を、制作アプリ風に統一する(§2〜3)。
- **アプリの外枠(シェル)**を、左の細いツールバー + 上のコンテキストバー + 下のステータスバーにする(§4)。
- 画面ごとに、**パネル(見出しバーつきの区画)**で構成し直す(§5)。生成ページは、中央に画像を大きく見せる**キャンバス**を置く。
- ライト / ダーク / システム連動は維持する(**既定はダーク**。Q-146)。

**やらないこと**
- 機能の追加・削除、IPC・DB・Rust の変更(`ステータスバー` に出す情報は、既存のストア・イベントの範囲)。
- 新しい依存ライブラリの追加(AGENTS.md §2 のバージョン固定の方針)。shadcn/ui・Tailwind CSS 4・lucide を使う。ドッキングやパネルのリサイズは自前の最小実装(§6)。
- フォントの同梱(OS 標準のフォントを使う。macOS / Windows 双方で崩れない)。
- カスタムタイトルバー(OS 標準のまま。05 §1)。

## 2. デザイン原則

1. **画像が主役、UI は黒子**: UI は無彩色(ニュートラルグレー)で、アクセントは 1 色だけ。画像の色を邪魔しない。
2. **高密度**: 文字は 12〜13px、コントロールの高さは 28px(現行は 32〜36px)。余白は詰めるが、区切りは線と明度差ではっきりさせる。
3. **パネル構成**: 設定・情報は「見出しバー + 内容」のパネルにまとめ、折りたたみ・並べ替え(§6)で整理する。
4. **状態が常に見える**: エンジン接続・実行中のジョブ・保存先などをステータスバーに常時表示する。
5. **一貫性**: 全ページで同じパネル・ツールバー・ボタンの規則を使う。

## 3. デザイントークン(`globals.css`)

ダーク(既定)を Photoshop の UI に近い、**わずかに青みのない中性グレー**の段階で作る。数値は目安(実装時に目視で調整する)。

| 役割 | トークン | ダーク | ライト |
|---|---|---|---|
| キャンバス(画像の背景) | `--canvas` | `oklch(0.20 0 0)` | `oklch(0.93 0 0)` |
| 通常の面(パネル本体) | `--background` / `--card` | `oklch(0.26 0 0)` | `oklch(0.985 0 0)` |
| パネル見出し・ツールバー | `--panel-header` | `oklch(0.22 0 0)` | `oklch(0.95 0 0)` |
| 入力欄の面 | `--input` | `oklch(0.19 0 0)` | `oklch(1 0 0)` |
| 境界線 | `--border` | `oklch(0.33 0 0)` | `oklch(0.88 0 0)` |
| 文字 | `--foreground` / `--muted-foreground` | `oklch(0.92 0 0)` / `oklch(0.68 0 0)` | `oklch(0.2 0 0)` / `oklch(0.5 0 0)` |
| アクセント | `--primary` | `oklch(0.62 0.17 255)`(青) | `oklch(0.55 0.18 255)` |
| 選択の枠 | `--ring` | アクセントと同じ | 同じ |
| 警告 / 失敗 / 成功 | `--warning` / `--destructive` / `--success` | 彩度を抑えた琥珀 / 赤 / 緑 | 同左 |

- 角丸は小さく(`--radius: 0.25rem` 前後。現行の 0.625rem より角張らせる)。影は使わず、**線と明度差**で面を分ける。
- 文字: 本文 13px・補助 11〜12px・見出しバーは 11px の大文字気味の字間(`tracking-wide`)。フォントは現行の OS 標準のまま。
- スクロールバーを細く(8px)・暗めにする(`::-webkit-scrollbar`)。
- フォーカスはアクセント色の 1px リング。選択中の画像・カードも同じ色の枠。

### 3.1 部品の調整(shadcn/ui の見た目だけ)

`button` / `input` / `select` / `tabs` / `switch` / `slider` / `badge` / `popover` / `sheet` を、高さ 28px・角丸小・枠線 1px・アクセントの使い方(主ボタンのみ塗り、他は枠線または透明)に揃える。新規部品は **`Panel`(見出しバー + 折りたたみ + 本体)** と **`Toolbar` / `ToolButton`(アイコンだけのボタン + ツールチップ)** と **`StatusBar`** のみ。

## 4. アプリの外枠(シェル)

```
┌──┬──────────────────────────────────────────────────┐
│  │ コンテキストバー: ページ名 · モデル · [AI に相談]… │
│ツ├──────────────────────────────────────────────────┤
│ー│                                                    │
│ル│              ページごとのワークスペース             │
│バ│                                                    │
│ー│                                                    │
├──┴──────────────────────────────────────────────────┤
│ ステータスバー: ● ComfyUI 接続中 · 生成中 3/20 · 保存先… │
└──────────────────────────────────────────────────────┘
```

- **ツールバー(左・幅 48px)**: 現行のサイドナビ(幅 208px)を、アイコンだけの縦のバーにする(生成 / ギャラリー / プリセット / モデル / 設定)。ホバーでツールチップ(ラベル + ショートカット)。現在のページはアクセント色の左線 + 明るい面。下部にテーマ切替。
- **コンテキストバー(上・高さ 36px)**: ページ名と、そのページの主要な操作(生成ページ: プリセット・[AI に相談]・初期化 / ギャラリー: 検索・表示切替 など)。現在の各ページの見出しとトップの操作列を、ここへ集約する。
- **ステータスバー(下・高さ 24px)**: エンジンの接続状態(現行のバッジ)・実行中ジョブの進捗(現行のヘッダの実行状況)・一時停止中・保存先の空き・アプリのバージョン。クリックで該当の設定やキューへ。現在の `JobStatusBar`(ヘッダの細い帯)と `EngineStatusBadge`(ナビ下部)は、ここに移す。

## 5. ページごとの構成

### 5.1 生成ページ(キャンバス + ドック)

```
┌──┬────────────────────────────────┬──────────────────┐
│  │            キャンバス            │ ドック(右)       │
│ツ│  ・選択した画像 / 参照画像 /     │ ▾ プロンプト      │
│ー│    マスクを大きく表示            │ ▾ モデル          │
│ル│  ・ズーム(フィット / 100%)     │ ▾ サイズ・サンプリング│
│  │  ・縦横比と生成サイズの重ね表示  │ ▸ 拡張機能(img2img…)│
│  ├────────────────────────────────┤ ▸ モデルの説明    │
│  │ 帯: [キュー][キュー]│[画像][画像]→│ ▸ 目安・履歴      │
└──┴────────────────────────────────┴──────────────────┘
```

- **中央 = キャンバス**: 帯で選択した画像(なければ最新の生成結果)を大きく表示する。参照画像・Inpaint のマスク(現在の「補助」の参照画像ワークスペース)も、キャンバスのタブ([結果][参照][マスク])で見る。ズーム(フィット・100%・ホイール)・パン(ドラッグ)に対応。
- **右 = ドック(パネルの縦積み)**: 現在のフォームを、パネル(折りたたみ可)に分ける: プロンプト / モデル / サイズ・サンプリング / 拡張機能(画像から生成・Inpaint・ControlNet・顔補正・参照画像)/ モデルの説明 / 目安・履歴。[生成] ボタンはドックの最下部に固定。
- **下 = 帯**: 28 のとおり(キューのカード + 画像)。帯で選んだ画像がキャンバスに出るため、「プロンプトを見ながら調整」がさらにしやすくなる。
- 幅が狭い(`lg` 未満)ときは、ドックをキャンバスの下に積む。

### 5.2 ギャラリー

- **左パネル**: 検索・お気に入り・モデル別・日付別などの絞り込み(現在の検索 + お気に入りのみを、パネルに置く)。絞り込みの種類は、現在ある情報(プロンプト・お気に入り)のみ。モデル別・日付別は、追加の設計が必要なので**今回は入れない**(Q-151)。
- **中央**: 仮想グリッド(現行)。サムネイルの大きさを変えるスライダー(コンテキストバー)。
- **右パネル = インスペクタ**: 選択した画像の大きなプレビュー・パラメータ・操作(現在の詳細シートを、ページ内の固定パネルにする。シートは廃止)。複数選択時は一括操作。

### 5.3 プリセット

- 左: 一覧(名前・モデル・サイズ・プロンプト冒頭)。右: 選択したプリセットの内容(設定の一覧)と操作(生成画面で使う・名前変更・削除)。現在の縦リストを、2 ペイン(リスト + インスペクタ)にする。

### 5.4 モデル取得

- 左パネル: カテゴリ・用途フィルタ・ベースモデル(現在の上部の選択群)。中央: カタログのカード(現行の `family-card`)。右(または下)のドック: ダウンロードの進捗(現行の `downloads-panel`)。

### 5.5 設定

- 左: カテゴリ一覧(エンジン / 保存先 / AI サポート / 表示。現在のタブを縦のリストにする。`?tab=` はそのまま)。右: 内容を、パネル(見出しバーつきの区画)で構成する。[保存] はコンテキストバーに固定。

## 6. パネルの共通動作

- 見出しバーのクリックで折りたたみ・展開。状態は**アプリ内に保持**(再起動では戻る。保存は 03 の `settings`(UI 状態)に入れるか、実装時に判断。Q-152)。
- パネルの並べ替え・ドッキングの自由な移動は**やらない**(複雑さに見合わない。Q-149)。ドック・左右ペインの**幅はドラッグで変えられる**(自前の細いリサイズバー。最小・最大幅あり。幅も保持)。
- キーボード: パネル見出しはボタン(`aria-expanded`)。`Tab` 順序は左 → 中央 → 右。コントラスト比は WCAG AA(本文 4.5:1)を保つ(ダークのグレーの段階を、実装時に確認する)。

## 7. 実装の分割(承認後、段階ごとに確認しながら進める)

| 段階 | 内容 | 影響 |
|---|---|---|
| A | デザイントークン・部品の調整・`Panel` / `Toolbar` / `StatusBar` の追加・シェル(ツールバー・コンテキストバー・ステータスバー) | 全ページの見た目(機能は同じ) |
| B | 生成ページ: キャンバス + ドック(フォームをパネルに分割。帯はそのまま) | `generation-form.tsx` の分割が大きい(機能は同じ) |
| C | ギャラリー(左パネル・インスペクタ)・プリセット(2 ペイン) | 詳細シートをインスペクタへ |
| D | モデル取得・設定の再構成 | 配置のみ |

- A → B → C → D の順に、各段階で目視確認(`npm run tauri dev` またはブラウザ)してから次へ進む。各段階は別のブランチ・PR とする(AGENTS.md §4)。
- テスト: 純粋なロジックは変えないため、既存の Vitest が通ること。新規は、パネルの折りたたみ状態・リサイズの境界値のロジックのみ。見た目は 09 に手動確認項目を追加し、スクリーンショットで比較する。

## 8. リスク

- **見た目は主観**: 数値のトークンは目安。段階 A の後に、実際の画面を見てトークンを調整する余地を持つ(§3 の値は承認対象でなく、方向性のみ)。
- **段階 B の変更が大きい**: フォームの分割とキャンバスの追加。→ 機能は変えず、見た目と配置だけ。段階 A の後に必要性を再確認できる。
- **高密度による可読性の低下**(文字 13px・コントロール 28px)。→ 設定で「表示の密度(標準 / ゆったり)」を選べるようにする案(Q-150)。
- **画面の狭さ**(最小 960×640。ツールバー 48px・ステータスバー 24px・コンテキストバー 36px で縦が約 60px 減る)。→ 帯は折りたため、ドックは `lg` 未満で積む。
- **ダーク既定が好みでない**。→ ライトも同じトークン体系で作り、設定で切替(現行の機能)。
