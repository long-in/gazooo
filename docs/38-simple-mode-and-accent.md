# 38. 生成ページの「かんたん / 詳細」モードと、ユーザーカラーの後から変更(v0.33、M33)

ステータス: 🟢 承認済み・実装済み(2026-11-22。07 B35 Q-273〜286 は推奨どおり。Rust・Vitest 296・型チェック・ESLint・ビルドまで確認。画面の目視確認は未実施)。

実装時の差異: 下書きモード(33)は未実装のため、かんたんの項目から除いた(33 の承認・実装後に追加)。かんたんではプリセットバー(PresetBar)も隠す。

## 1. 目的

1. 生成ページ(27・28・29・33)は項目が多くフォームが長いため、初級者が迷う。**かんたん(初級者向け)と詳細(上級者向け)の 2 モードを切り替え**られるようにする。
2. ユーザー作成時に選んだ色(36 §3 `users.color`、アバターのパレット 8 色)を、**後から変更**できるようにする。さらにその色を **アプリ全体のアクセント色(`--primary` / `--ring` / `--sidebar-primary`)に連動**させる。

どちらも **フロントエンド中心**。色の変更のみ Rust に小さなコマンドを 1 つ追加する。

## 2. 生成ページのモード

### 2.1 切り替え

- 生成フォームの最上部に **セグメント切り替え [かんたん | 詳細]**(既存の「初期化」「AI サポート」行と同じ段)。
- **ユーザーごとの設定として保存**(`ui.state`。36 §4 のユーザーごとの設定)。既定は **かんたん**。
- 切り替えても **フォームの値は保持**する(かんたんで隠れた項目は、詳細へ戻したときに元の値のまま)。

### 2.2 かんたんモードで見せるもの

上から次の順(スクロールせず 1 画面に収まることを目標):

| # | 項目 | 備考 |
|---|---|---|
| 1 | モデル(種別 + モデル) | 種別は選択済みモデルから決まる場合は出さず、モデルの 1 つの選択に統合(20 のモデル選択の整合に従う) |
| 2 | プロンプト(+ 翻訳ボタン 34) | ネガティブは出さない |
| 3 | 画像サイズ | **プリセットのボタン**(正方形 / 縦長 / 横長 × 小・中・大)。数値入力は詳細のみ |
| 4 | 枚数 | 1〜4 の数値(バッチではなく `count`) |
| 5 | 下書きモード(33)・[生成] | 生成ボタンは常に画面内に固定表示(`sticky` で下端) |
| 6 | AI サポート・初期化 | 既存の位置のまま |

隠した項目(ステップ・CFG / ガイダンス・サンプラー・スケジューラ・シード・バッチ・ネガティブ・CLIP / VAE の選択・各補助機能)の値は、**モデルのプロファイル(18)の推奨値 → なければ現在のフォームの値** を使う。値は変更しない(隠すだけ)。

### 2.3 かんたんモードでも出す補助機能

補助機能(img2img・Inpaint・ControlNet・顔補正・参照画像)は **「追加機能」として折りたたみ(`<details>`)で 1 か所にまとめ、既定は閉じる**。ただし **有効にしている機能がある場合は、閉じていても件数のバッジ(例: 「追加機能 2」)を出す**。参照画像が必要なモデル(Qwen-Image 2.1 の編集)では、参照画像の項目を必須としてかんたんでも常に表示する。

### 2.4 詳細モードで見せるもの

現在のフォームすべて(挙動の変更なし)。ただし長さの改善として次を行う:

- 項目を **折りたたみセクション**(基本 / サンプリング / モデル詳細 / 追加機能)に分け、開閉状態をユーザーごとに記憶する。
- 生成ボタンは詳細でも画面下端に固定する。

### 2.5 バリデーション

隠した項目にエラーがある場合(例: 必須の VAE 未選択)は、**そのエラーを含むセクションを自動で開く**か、かんたんでは **「詳細モードで設定してください」のメッセージ + [詳細に切り替え] ボタン** を出す。

## 3. ユーザーカラーの変更とアクセント連動

### 3.1 色の変更

- ナビ上部のユーザーのポップオーバー(36 §5.2)に **[色を変更…]**。クリックで 8 色のパレット(作成時と同じ)を出し、選ぶと **即時反映・保存**。
- 変更はログイン中の本人のみ(自分自身の変更なのでロックの入力は不要。名前変更の「ログイン中の自分自身は不要」(36 §5.5)と同じ)。
- ユーザー選択画面の「…」メニューには追加しない(ログイン前に他のユーザーの色は変えない)。

### 3.2 IPC(04 に追記)

| コマンド | 入力 | 出力 |
|---|---|---|
| `user_set_color` | `{ id: string; color: string }`(`color` は `PALETTE` のキー。範囲外は `VALIDATION`) | `UserSummary` |

- **ログイン中のユーザー自身の `id` のみ許可**(他人の `id` は `FORBIDDEN`)。`app.db` の `users.color` を更新するだけ。スキーマ変更・マイグレーションなし。

### 3.3 アクセント色への連動

- 色キー(red / orange / amber / green / teal / blue / violet / pink)ごとに、**ライト用・ダーク用の `oklch` を定義**し、ログイン時と色変更時に `document.documentElement` の CSS 変数 `--primary`、`--ring`、`--sidebar-primary`(と前景色 `*-foreground`)を上書きする(`globals.css` の既定は blue のまま)。
- 前景色は、明るい色(amber 等)で十分なコントラスト(WCAG AA 4.5:1 以上)になるよう色ごとに決める(アバターの `text-black` / `text-white` の使い分けと同じ考え方)。
- **ログアウト・ユーザー選択画面では既定の青に戻す**。
- 影響するのはボタン・フォーカスリング・選択状態・スライダー等、`primary` を使う UI 全般。ステータス色(成功 / エラー / 警告)は **連動させない**。
