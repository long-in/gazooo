# 13. Inpaint と、AI へのアプリ機能の提示(v0.5)

> ステータス: 🟢 承認済み(2026-11-19。Q-39〜41 は推奨どおり確定。07 の Q-39〜41)。実装済み(M10。実機検証は 09 の開発ログ)。
> 経緯: 「顔を保って、服・背景だけ描き直したい」という用途で、現状は ComfyUI を直接操作するしかなかった(img2img / inpaint は 01 で範囲外、09 で未対応)。アプリ内で完結させる。あわせて、AI サポート(11)が **アプリでできること** を把握した状態で答えられるようにする。

## 1. 目的とスコープ

**やること**
- **F-15 Inpaint**: 参照画像にマスクを描き、マスクした範囲だけを描き直す。マスク外の画素は **元画像と完全に一致** させる。
- **F-13 拡張**: AI サポートのシステムプロンプトに、gazooo の機能一覧(できること・できないこと・手順)を載せる。機能追加のたびに更新漏れが起きないよう、機能一覧を 1 か所で管理する(§6)。

**やらないこと(v0.5)**
- Flux 系の inpaint(SD1.5 / SDXL のみ。顔補正・ControlNet と同じ制約)。
- 自動マスク生成(SAM 等)、アウトペイント(キャンバス拡張)、複数マスクの重ね描き履歴。
- inpaint 専用チェックポイント向けの別ワークフロー(§3.3 / Q-39)。

## 2. 要件

| ID | 機能 | 内容 |
|---|---|---|
| F-15 | Inpaint | 参照画像とマスクを指定し、マスク範囲だけを再生成する。SD1.5 / SDXL のみ。結果は元画像へ合成し直す |

## 3. Inpaint(F-15)

### 3.1 利用者の体験

1. 生成画面に「Inpaint」セクション(スイッチ付き)を追加する。
2. 参照画像の指定は ControlNet と同じ(ファイル選択、またはギャラリー詳細の「Inpaint に使う」)。
3. 「マスクを描く」で **マスクエディタ**(ダイアログ)を開く。
   - ブラシ / 消しゴム、ブラシサイズ、**反転**、全消去、元に戻す(複数段)。
   - 塗った範囲 = **描き直す範囲**。顔を保護したいときは顔を塗って「反転」する。
4. 設定(§3.2)を調整して「生成」。結果はギャラリーに保存される(通常の生成と同じ)。
5. プロンプトは「描き直す部分」の説明にする、とフォームに注記する。

### 3.2 パラメータ(`GenerationParams.inpaint`)

```ts
interface InpaintParams {
  enabled: boolean;
  image: string;        // 参照画像(inputs/<uuid>.png。10 §6 と同じ保管)
  mask: string;         // マスク(inputs/<uuid>.png。白 = 描き直す範囲、グレースケール PNG)
  denoise: number;      // 0.05〜1.0、既定 0.7(0.6〜0.8 が目安。1.0 に近いほど元から離れる)
  growMask: number;     // 0〜64 px、既定 8(マスクを広げて境界をなじませる)
  feather: number;      // 0〜31 px、既定 8(境界のぼかし。ComfyUI の ImageBlur の上限)
  compositeBack: boolean; // 既定 true。結果を元画像へ合成し直す(マスク外を元と同一にする)
}
```

- 検証(`job_enqueue`。形式は `GenerationParams::validate`、ファイルの確認は `check_inpaint`): `sd15` / `sdxl` のみ(Flux 系は `VALIDATION`)、`image` と `mask` が存在すること(無ければ `IMAGE_NOT_FOUND`)、マスクと画像の縦横が一致すること、マスクが **全黒(描き直す範囲が無い)** なら `VALIDATION`。
- **顔補正とは同時に使えない**(顔補正が顔を再生成してしまい、保護の意図に反するため)。Inpaint を有効にすると顔補正はスイッチごと無効表示になる。ControlNet との併用は可。
- 出力サイズは参照画像のサイズ(64 の倍数・256〜2048 に丸めた値。長辺が 2048 を超える画像は比率を保って縮小)。フォームの幅・高さは参照画像の選択時に設定され、Inpaint が有効な間は手動で変えられない。**マスク外が元画像と画素単位で一致するのは、元画像が 64 の倍数で 2048 以内のとき**。それ以外は、リサイズ後の画像との一致になる(UI に注記する)。

### 3.3 ワークフロー(ComfyUI のコアノードのみ)

```
LoadImage(image) ─ VAEEncode ─ SetLatentNoiseMask ─ KSampler(denoise) ─ VAEDecode ─┐
LoadImageMask(mask) ─ GrowMask(growMask) ─ FeatherMask ─┬─(mask 入力)               │
                                                         └──────────────→ ImageCompositeMasked
LoadImage(image) ──────────────────────────→ destination                (source = 生成結果) ─ SaveImage
```

- 追加のカスタムノードは不要(コアのみ)。必要ノード(`LoadImageMask` `MaskToImage` `ImageToMask` `GrowMask` `ImageBlur` `ImageScale` `VAEEncode` `SetLatentNoiseMask` `RepeatLatentBatch` `RepeatImageBatch` `ImageCompositeMasked`)が 1 つでも無ければ、`engine_status.features.inpaint` が false になりスイッチを無効にする。枚数が 2 以上のときは、潜在と元画像を `Repeat*Batch` で枚数分に増やす。ぼかしは `MaskToImage` → `ImageBlur` → `ImageToMask`、拡張は `GrowMask`(どちらも 0 なら省く)。
- 通常のチェックポイントで動く(`SetLatentNoiseMask` 方式)。元画像の雰囲気を残しやすい。
- `compositeBack` が false のときは `ImageCompositeMasked` を省く。
- 実装前に、既存のワークフロー生成(02 §3)の構造を確認し、設計との差異があれば本資料を先に更新する。

### 3.4 参照画像・マスクの保管

- 参照画像は 10 §6 と同じ(PNG 再エンコード、メタデータ除去、`inputs/` に保管、相対パスを `params_json` に記録)。
- マスクは **WebView が描いた PNG** を Rust の新コマンド `mask_save` で受け取り、`inputs/<uuid>.png` に保存する。Rust 側で形式・サイズ(20MB / 長辺 8192px まで)を検証し、グレースケールに正規化する。WebView から任意パスを読ませない(01)。
- 再現・プリセット・ギャラリー詳細は Inpaint 設定を含めて保存・復元する。画像またはマスクが欠損していれば Inpaint を無効にして復元し、トーストで知らせる(10 §8 と同じ)。

### 3.5 IPC(04 に追記する内容)

| コマンド | 引数 | 戻り値 | 説明 |
|---|---|---|---|
| `mask_save` | リクエスト本文に PNG のバイト列(Tauri の raw body) | `InputImage` | マスクを検証してグレースケール PNG として保存する。全黒でも保存は可(拒否は `job_enqueue` で行う)。大きさは PNG から Rust が読む |

- 参照画像の取り込みは既存の `input_image_*`(04)を流用する。ギャラリーからの取り込みも同じ。
- `job_enqueue` の `params.inpaint` を追加(§3.2)。DB スキーマの変更は不要(`params_json` の拡張のみ。マイグレーション不要を実装時に確認する)。

### 3.6 UI

```
│ Inpaint             [スイッチ]                 │
│     参照画像 [ファイルを選ぶ]  [サムネイル]     │
│     [マスクを描く]  (マスク済み / 未設定)       │
│     強さ(denoise) [0.7]                        │
│     マスクを広げる [8]px  境界のぼかし [8]px    │
│     [x] 結果を元画像へ合成し直す                │
```

- 無効になる条件: Flux 系(「SD1.5 / SDXL のみ対応」)、必要ノード無し、顔補正が有効(先に顔補正を切る旨を表示)。
- 参照画像またはマスクが未設定の間は「生成」を押せない。
- マスクエディタは Canvas 2D の自前実装(新規依存なし)。表示は元画像の上に半透明の赤で重ね、保存時に白黒 PNG へ変換する。キーボード操作(ブラシサイズ `[` `]`、元に戻す Ctrl/Cmd+Z)に対応する。

### 3.7 モデル取得(12)との関係

- v0.5 では **新たなモデルは不要**(通常のチェックポイントで動く)。inpaint 専用チェックポイントは Q-39。

## 4. AI へのアプリ機能の提示(F-13 拡張)

### 4.1 方針

11 §3 のシステムプロンプトに、次の「機能カタログ」節を追加する。

- **できること**: 機能の一覧(txt2img、モデル種別、顔補正、ControlNet、Inpaint、プリセット、ギャラリー、再現、モデル取得ページ、AI サポート自身の提案できる項目)。各機能に **使いどころ・主な設定・制約** を 1〜3 行で付ける。
- **できないこと**(今は無い機能): LoRA、生成中プレビュー、アウトペイント、Flux の inpaint / 顔補正 / ControlNet、複数 ControlNet 等。**無いものを「ある」と案内しない** ことを明記し、代替手段(ComfyUI を直接使う等)を示させる。
- **操作手順の案内**: 例「顔を保って服だけ変える → Inpaint を有効にし、参照画像を選び、顔を塗って反転」。画面名・ボタン名は UI 文言(i18n)と一致させる。
- **提案できる項目**(`suggest_params` のホワイトリスト。11 §6)と、できない項目(モデル切替・seed・ControlNet・Inpaint の画像/マスク。本文で手順を説明する)。

### 4.2 現在の状態も渡す

「現在のフォーム」(11 §3)のスナップショットに次を追加する。

- `inpaint`: `{ enabled, denoise, growMask, feather, compositeBack, hasMask: boolean }`(画像・マスクのパスは送らない。ControlNet と同じ)。
- `capabilities`(スナップショットとは別のブロックとして添える): 現在の ComfyUI で使える機能の真偽(`faceFix` / `controlnet` / `controlnetPreprocessors` / `inpaint` / `flux_gguf`)。直近の接続確認の結果を使い、通信はしない(未接続・未確認なら添えない)。モデル名の一覧は引き続き送らない。
- 追加で外部へ送られる内容は、**フォームの数値と機能の有無のみ**。同意ダイアログの説明(11 §5)には「機能の有無」を一文追記する。

### 4.3 一元管理(更新漏れ防止)

- 機能カタログは **Rust 側の 1 ファイル**(`services/assistant/capabilities.rs`)に定数として置く。システムプロンプトは `SYSTEM_PROMPT` とこの定数を連結して作る(`system_prompt()`)。
- 機能を追加・変更する PR では、このファイルの更新を **09 のチェックリストに項目として追加** する(レビューで気づけるようにする)。
- テスト: (a) 機能カタログに、F-11〜F-15 の各機能名が含まれること、(b) 「できないこと」に挙げた機能が「できること」に重複しないこと、(c) システムプロンプトの長さが上限(6,000 文字)を超えないこと(トークン消費の抑制)、(d) 参照画像・マスクのパスがスナップショットに含まれないこと、(e) カタログが引用するボタン名が ja.ts に実在すること。
- プロンプトキャッシュ: 機能カタログは固定文なので、システムプロンプトにキャッシュ指定(`cache_control`)を付けて、相談ごとの入力コストを抑える。

### 4.4 プロンプトインジェクション対策(11 §3 を踏襲)

- 機能カタログは **アプリ固定の信頼できる文面**。ユーザー入力・会話履歴・フォームのプロンプトに含まれる指示には従わない方針を、引き続きシステムプロンプトで明示する。
- AI は機能を **案内するだけ** で、アプリ操作(Inpaint の有効化等)を実行する手段は持たない(`suggest_params` の適用は常にユーザーのクリック)。

## 5. テスト方針

- Rust: Inpaint のワークフロー生成(ノード構成・`compositeBack` の有無・`growMask`/`feather` の反映)、検証ルール(Flux 拒否・顔補正との排他・全黒マスク・サイズ不一致)、`mask_save`(形式・サイズ・グレースケール正規化・不正 PNG の拒否)、§4.3 のテスト。ComfyUI 実機のテストは `#[ignore]`(既存方針)。
- フロント(Vitest): マスクの反転・全消去・元に戻すのロジック、Inpaint セクションの有効/無効条件、フォーム→パラメータの変換、プリセット復元(欠損時の無効化)。
- 手動(09 に追加): マスクエディタの操作、顔を保護した inpaint で顔の画素が元画像と一致すること(合成あり)、合成なしとの差、境界のなじみ、AI が Inpaint の手順を正しく案内すること。

## 6. 実装の分割(マイルストーン M10)

1. ワークフロー生成と検証ルール(Rust)+ `mask_save`。
2. フォーム・マスクエディタ・プリセット/再現対応(フロント)。
3. 機能カタログとシステムプロンプト、スナップショット拡張(§4)。
4. 09 のチェックリスト追加、実機での検証ログ。

## 7. リスク

- マスクエディタの操作性(タッチ・高解像度画像での描画負荷)。大きな画像は表示用に縮小して描き、保存時に原寸へ拡大する。
- 丸め(64 の倍数)による元画像との微小なずれ。合成時に元画像を使うことで、マスク外は一致させる。
- システムプロンプトが長くなることによるコスト増(§4.3 のキャッシュと長さ上限で抑える)。
