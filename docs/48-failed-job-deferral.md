# 48. 失敗したジョブの自動再試行と後回し(v0.48)

ステータス: 🟡 レビュー待ち(2026-11-25)。

## 1. 背景と目的

生成に失敗したジョブは、いまは 1 回で「失敗」になり、キューは次のジョブへ進む。一時的な失敗(VRAM 不足の直後・ComfyUI の不調など)でも利用者が手動で再試行する必要がある。
**失敗したジョブを自動で再試行し、3 回続けて失敗したら待機の末尾へ回して、他のジョブを先に進める。**(ユーザーの依頼。方式は「自動再試行 → 3 回失敗で末尾へ」を選択)

## 2. 動き

1. ジョブが失敗したら、**失敗にせず `queued` の先頭へ戻し**、同じ設定で実行し直す(1 回目の失敗 → 2 回目の実行)。
2. 同じジョブが **3 回続けて失敗**したら、**待機の末尾へ回す**(後回し)。回数は 0 に戻る。他の待機ジョブが先に実行される。
3. 後回しにしたあと、**さらに 3 回続けて失敗**したら、そこで初めて **「失敗」** にする(エラーの内容は最後の失敗)。後回しは 1 ジョブにつき 1 回まで(無限に回り続けない)。
4. 途中で成功したら、そのジョブは完了(回数は破棄)。
5. 利用者のキャンセルは再試行しない。

## 3. 対象外(再試行せず、すぐ「失敗」にする)

再試行しても直らない失敗: 入力の不正(`VALIDATION` 系)、参照画像・モデルの欠落、`ENGINE_UNREACHABLE`(接続断。47 の自動復旧、または従来どおりの扱いに任せる)。具体的なエラーコードの一覧は実装時に `domain` のエラー型から確定し、このドキュメントに追記する。

## 4. 表示

- 再試行中・後回し中のジョブは `queued` のまま。キューのカードに「再試行 n/3」のように回数を小さく表示する(日本語・英語)。
- 後回しにしたとき、トースト等の通知は出さない(静かに末尾へ移す)。最終的な失敗は従来どおり 28 §9 の通知。

## 5. 実装方針(承認後)

| 場所 | 内容 |
|---|---|
| `services/jobs.rs` | ジョブ ID ごとの連続失敗数と後回し済みフラグをメモリ上に持つ(47 の `requeue_counts` と同じ作り。再起動で消えてよい)。失敗時の分岐に「再試行 / 末尾へ / 失敗」を追加 |
| `db/jobs.rs` | 先頭へ戻す `requeue_front` に加え、末尾へ回す `requeue_back` を追加。**DB のマイグレーションは不要** |
| IPC | `Job` に任意の `attempts?: number` を追加(04 に追記)。イベントは既存の `job://updated` |
| フロント | `queue-card.tsx` に回数の表示 |

## 6. テスト

- Rust: 1・2 回の失敗では先頭へ戻る / 3 回目で末尾へ回り他のジョブが先に走る / 後回し後の 3 回で失敗になる / 途中の成功で完了 / 対象外のエラーとキャンセルは再試行しない。
- フロント(Vitest): 回数の表示。
