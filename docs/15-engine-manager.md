# 15. ComfyUI の起動管理(v0.7)

> ステータス: 🟢 承認済み(2026-11-19。07 Q-45〜51 は推奨どおり)・実装済み。実装時の差異は §12 に記載。

## 1. 目的とスコープ

アプリの画面から、**この PC の ComfyUI を起動・停止・再起動**できるようにする(F-16)。きっかけは、モデルの保存先を ComfyUI に反映(08 §6.2)しても、再起動が手作業になること。再起動の手間のほか、「ComfyUI の起動を忘れて接続エラー」「アプリを閉じても ComfyUI が残る」も解消する。

これは 01 の「ComfyUI の自動起動管理(v0.2 候補)」、07 Q-01 の (b) にあたる。**MVP の方針(既に動いている ComfyUI に接続)は既定のまま残し、起動管理は明示的に有効にしたときだけ働く**(オプトイン。§11 Q-45)。

### やること
- ComfyUI の起動・停止・再起動(アプリが起動したプロセスだけを対象にする)。
- 起動に必要なパス(ComfyUI の `main.py`、Python、`--base-directory`)とポートの設定、入力の検証、候補の自動入力。
- 状態(停止中 / 起動中 / 稼働中 / 停止処理中 / 異常終了)の表示、ログの表示。
- アプリ起動時の自動起動(任意)、アプリ終了時の確実な停止。
- 08 §6.2 の [ComfyUI に反映] のあとの「今すぐ再起動」。

### やらないこと
- ComfyUI・Python・PyTorch・カスタムノードのインストールと更新(08 のスクリプトの役割のまま)。
- **アプリが起動していない ComfyUI(自分で起動したもの・リモート)の停止・再起動**。他のプロセスを終了させない。
- 異常終了時の自動再起動(§11 Q-49)。
- GPU の選択、任意の起動引数の入力(§8)。

## 3. モードと設定

接続モードは 2 つ。

| モード | 動作 |
|---|---|
| `external`(既定) | 従来どおり。ComfyUI は別途起動され、アプリは URL に接続するだけ。起動・停止ボタンは無効 |
| `managed` | アプリが ComfyUI を子プロセスとして起動・管理する。接続先は `http://127.0.0.1:<port>` に固定(設定の URL も同期) |

設定キー `engine.comfyui.managed`(JSON。03 の設定テーブルにキーを追加するだけで、マイグレーションは不要):

```ts
interface ManagedEngineConfig {
  enabled: boolean;            // false = external
  mainPy: string;              // ComfyUI の main.py(絶対パス)
  python: string;              // Python 実行ファイル(venv のもの。絶対パス)
  baseDirectory: string | null;// --base-directory(null なら指定しない)
  port: number;                // 既定 8188
  autoStart: boolean;          // アプリ起動時に自動で起動する(既定 false)
  autoRecover: boolean;        // 接続が 90 秒以上切れたら自動で再起動し、キューを実行し直す(既定 false。47)
}
```

### 3.1 パスの決め方(§11 Q-46)
- **設定で明示指定**が正。設定画面の「ComfyUI の起動管理」に、`main.py`・Python・`--base-directory` のフォルダ選択を置く。
- **自動入力の候補**(ユーザーが確認して確定する。勝手に有効にしない):
  1. 起動中の ComfyUI があれば、`/system_stats` の `argv` から `main.py` と `--base-directory` を取る(12 §3 と同じ情報源。ローカルのみ)。
  2. `main.py` が決まれば、Python は `<main.py の親>/../venv/Scripts/python.exe`(Windows)/ `bin/python`(macOS)を候補にする(08 のレイアウト)。見つからなければ空欄のまま。
- 保存時の検証: すべて絶対パス・存在・Python は実行可能なファイル・ポートは 1024〜65535。通らなければ保存しない。

## 4. 状態

```
stopped ──start──▶ starting ──ready──▶ running ──stop──▶ stopping ──▶ stopped
                      │                    │
                      └──exit/timeout──▶ crashed ◀──予期しない終了──┘
```

- `starting` → `running`: `GET /system_stats` が成功したら(60 秒でタイムアウト。初回は PyTorch の読み込みで遅い)。タイムアウトは `crashed` 扱いで、ログの末尾を表示する。
- `crashed`: 予期しない終了・起動失敗。終了コードとログ末尾を保持し、**自動再起動はしない**(例外: `autoRecover` が ON のとき、接続が 90 秒以上切れたら再起動する。47)。
- 状態は 1 つのサービスが持ち、変更のたびにイベントで通知する(§7)。

## 5. 操作

| 操作 | 動作 |
|---|---|
| 起動 | 設定を再検証 → **ポートが使用中なら起動せず**エラー `ENGINE_PORT_IN_USE`(別の ComfyUI が動いている可能性。他のプロセスは終了させず、「そのまま接続する(external)」への案内を出す)→ 子プロセスを起動 → `running` まで待つ |
| 停止 | 子プロセス(ツリーごと)を終了。Windows は即時終了、macOS は `SIGTERM` → 5 秒待って `SIGKILL`。完了まで `stopping` |
| 再起動 | 停止 → ポートの解放を待つ → 起動。**実行中のジョブがある場合は確認ダイアログ**(§11 Q-47)。「中断して再起動」を選ぶと、実行中のジョブは失敗として記録される(02 §3.5 の接続断の扱い)。待機中のジョブは待機のまま残り、再接続後に続行する(実装時に挙動を確認し、違えば本書を更新) |
| アプリ終了 | 子プロセスを停止してから終了(§6)。ジョブの実行中は、既存の終了時確認に従う |
| 自動復旧 | `autoRecover` が真で `managed` のとき、接続が 90 秒以上切れたら確認なしで再起動し、残りのジョブを実行し直す(47)。利用者が停止した状態は対象外 |
| 自動起動 | `autoStart` が真で `managed` のとき、アプリ起動時に起動する。失敗してもアプリの起動は妨げず、状態は `crashed` |

「他の ComfyUI が既に動いている」場合の起動は、上記のとおり拒否する。**アプリが起動した子プロセス以外は、停止・再起動の対象にしない**(UI でもボタンを出さない)。

## 6. プロセス管理(Rust)

- **起動**: `tokio::process::Command` 等で、`python main.py --listen 127.0.0.1 --port <port> [--base-directory <dir>] --disable-auto-launch`(08 の `start` と同じ)。**シェルを経由しない**。引数は検証済みの設定値だけで組み立て、任意の追加引数は受け付けない(§8)。
  - 追加の固定引数: ComfyUI が対応している場合だけ `--disable-dynamic-vram` を付ける(`main.py` と同じ場所の `comfy/cli_args.py` に引数名があるかで判定。46 §14。動的 VRAM ロードが有効だと、生成の繰り返しで ComfyUI が応答しなくなったため)。
  - 環境変数: `PYTHONUNBUFFERED=1`(ログの即時取得)。macOS は `PYTORCH_ENABLE_MPS_FALLBACK=1`。他の環境変数は引き継ぐ。
  - Windows ではコンソールウィンドウを出さない(`CREATE_NO_WINDOW`)。
- **後始末(確実に)**:
  - Windows: **Job Object**(`KILL_ON_JOB_CLOSE`)に子プロセスを入れる。アプリが異常終了しても OS が子を終了する。
  - macOS: 子を新しいプロセスグループにし、終了時にグループ全体へシグナルを送る。アプリの異常終了時の取りこぼしは、次回起動時に「前回の子プロセス(PID を記録)が残っていれば、同じ実行ファイルの場合に限り終了する」で補う。
  - これらは `command-group` クレート等の既製品を第一候補にする(§11 Q-50。固定バージョン・ライセンスは実装時に確認し、02 の依存方針に従う)。
- **終了検知**: 子の終了を監視し、想定外なら `crashed`。
- **ログ**: 子の標準出力・標準エラーを行単位で読み、(a) アプリのログフォルダの `comfyui.log`(上書き。サイズ上限付き)に書き、(b) 直近 500 行をメモリに保持して UI に出す。ログには生成のプロンプトが含まれる場合があるが、**ローカルにのみ保存し、外部へ送らない**。
- 状態・子プロセスの保持は 1 つの `EngineProcess` サービス(`services/engine_process.rs`)に集約する。`EngineService`(接続・API 呼び出し)とは別にし、`managed` のときだけ後者へ接続先を同期する。

## 7. IPC(04 に追記する内容)

| コマンド | 引数 | 戻り値 |
|---|---|---|
| `engine_managed_get` | – | `{ config: ManagedEngineConfig; state: EngineProcState; suggestions?: { mainPy?; python?; baseDirectory? } }` |
| `engine_managed_set` | `{ config: ManagedEngineConfig }` | `{ config }`(§3.1 の検証つき。`enabled` を真にすると接続先 URL を同期) |
| `engine_process_start` | – | `EngineProcState` |
| `engine_process_stop` | – | `EngineProcState` |
| `engine_process_restart` | `{ force?: boolean }` | `EngineProcState`(実行中のジョブがあり `force` でなければ `ENGINE_BUSY`) |
| `engine_process_logs` | `{ lines?: number }` | `{ lines: string[] }` |

```ts
type EngineProcStatus = "stopped" | "starting" | "running" | "stopping" | "crashed";
interface EngineProcState {
  status: EngineProcStatus;
  pid?: number;
  exitCode?: number;       // crashed のとき
  message?: string;        // 失敗理由(短文)
  managedByApp: boolean;   // アプリが起動した子プロセスか
}
```

- イベント: `engine://proc-state`(`EngineProcState`)、`engine://log`(`{ line: string }`。UI が購読している間だけ送る)。
- 新エラーコード: `ENGINE_PORT_IN_USE` / `ENGINE_LAUNCH_FAILED`(実行ファイルが無い・起動できない。`details` は終了コードと短いメッセージ)/ `ENGINE_START_TIMEOUT` / `ENGINE_BUSY`(実行中のジョブあり)/ `ENGINE_NOT_MANAGED`(アプリが起動していないプロセスの操作)。

## 8. セキュリティ

- 起動するのは**設定で指定された Python と `main.py` だけ**。設定は WebView から渡るため、絶対パス・存在・通常ファイルであることを Rust 側で再検証し、引数はこちらで固定の形に組み立てる。**任意の追加引数・環境変数は受け付けない**(任意コマンド実行の経路にしない)。
- `--listen` は `127.0.0.1` 固定(LAN に公開しない)。
- 他のプロセスは終了させない(§5)。PID の記録による取りこぼし対策も、記録した PID と**実行ファイルのパスが一致する場合に限る**。
- CSP の `connect-src` は変更しない(通信は Rust から)。

## 9. 画面(05 に追記する内容)

- **設定 > ComfyUI の起動管理**(新設セクション): モード切替(アプリで管理する)、`main.py` / Python / base-directory のフォルダ・ファイル選択と「候補を入れる」、ポート、自動起動、状態バッジと [起動] [停止] [再起動]、ログ(最新 500 行・折りたたみ・コピー)。`external` のときは、操作ボタンは無効で「別途起動した ComfyUI に接続しています」と表示する。
- **サイドバーの接続バッジ**: 状態(起動中・停止中・異常終了)を表示。`managed` で停止中のとき、バッジから起動できる。
- **モデルページ**(08 §6.2): [ComfyUI に反映] が成功したとき、`managed` かつ稼働中なら **[今すぐ再起動]** を出す(実行中のジョブがあれば §5 の確認)。`external` なら従来の「再起動してください」。
- ジョブの実行中は、再起動・停止の確認ダイアログに、実行中・待機中の件数を出す。
- すべて日本語・英語。

## 10. 実装方針(承認後)・テスト・受け入れ基準

実装は次の順で行う(各段で `cargo clippy -- -D warnings` / テスト)。

1. 設定・検証・引数の組み立て(純粋関数)と、候補の自動入力。
2. `EngineProcess`(起動・停止・状態・ログ・後始末)。
3. IPC・イベント。接続先 URL の同期。
4. 画面(設定セクション、バッジ、モデルページの再起動)。

テスト:
- Rust(ネットワーク・実 ComfyUI なし): 設定の検証(相対パス・存在しない・ポート範囲)、起動引数の組み立て(`--listen 127.0.0.1` 固定、追加引数なし)、状態遷移(短命の子プロセスとして小さなスクリプト/テスト用バイナリを使い、起動・正常終了・異常終了・タイムアウト・ポート使用中)、ログのリングバッファと上限、停止後に子が残らないこと、他プロセスを終了させないこと。
- フロント: 状態に応じたボタンの有効/無効、確認ダイアログ、エラーコードの表示。
- 実機(09 に追加): 実際の ComfyUI での起動・停止・再起動、アプリを強制終了したときの子プロセスの後始末(Windows / macOS)、起動中に保存先を反映 → 再起動 → モデルが見える。

受け入れ基準:
1. `managed` に設定して [起動] を押すと、ComfyUI が起動し、バッジが稼働中になる。
2. [再起動] で ComfyUI が入れ替わり、再接続後に生成できる。実行中のジョブがあれば確認が出る。
3. アプリを閉じる(強制終了を含む)と、ComfyUI のプロセスが残らない。
4. ポートが使用中のとき、他のプロセスを終了させずに、理由を表示して起動を拒否する。
5. `external` のままなら、従来と挙動が変わらない。
6. Windows / macOS の両方で動作する。

## 11. 決定してほしい点(07 B6 にも記載)

| ID | 論点 | 推奨 |
|---|---|---|
| Q-45 | 既定のモード | **`external`(従来どおり)。起動管理はオプトイン**。設定で明示的に有効にしたときだけ、アプリが ComfyUI を起動する |
| Q-46 | パスの決め方 | **設定で明示指定 + 起動中の ComfyUI / 08 のレイアウトからの候補自動入力**(確定はユーザー)。パスの自動探索はしない |
| Q-47 | 再起動時に実行中のジョブがあるとき | **確認ダイアログ**。「中断して再起動」で実行中のジョブは失敗として記録、待機中は残す |
| Q-48 | アプリ終了時の ComfyUI | **停止する**(アプリが起動したもの)。「アプリ終了後も動かし続ける」は v0.7 では作らない |
| Q-49 | 異常終了時の自動再起動 | **しない**(状態とログ末尾を表示するだけ)。ループ再起動を避け、原因の把握を優先 |
| Q-50 | 子プロセスの後始末の実装 | **`command-group` 等の既製クレート**を使い、Windows は Job Object、macOS はプロセスグループ。採用時に固定バージョン・ライセンス・メンテ状況を確認して 02 を更新する |
| Q-51 | アプリが起動していない ComfyUI の扱い | **停止・再起動しない**(ポート使用中なら起動を拒否し、external での接続を案内)。他プロセスの強制終了は行わない |

## 12. 実装時の差異・補足(実装済み)

- **macOS の「前回の取りこぼしの回収」(PID 記録)は未実装**: アプリの異常終了時の後始末は、Windows は Job Object(`KILL_ON_JOB_CLOSE`、実機で確認)、macOS はプロセスグループによる通常終了時の停止まで。異常終了で子が残った場合は、ポート使用中として起動が拒否され(§5)、手動で終了する。必要になれば後続で追加する。
- `engine_managed_set` / `engine_managed_get` の戻り値は `{ config, state, suggestions }`(§7 の `{ config }` の上位互換)。`ENGINE_BUSY` は「停止処理中」「管理を無効にする前に停止が必要」「実行中のジョブあり(`details.running` / `details.queued`)」に共通で使う。
- 後始末は `command-group` 5.0.1(固定)を採用(Q-50)。Windows で `CREATE_NO_WINDOW` を指定して起動する。
- 起動確認(`/system_stats`)は外部クレートを使わない最小の HTTP で行う。ログの ANSI 色指定は取り除いて保持する。
- 起動の途中で停止が要求された場合は、起動した直後に終了させる(競合対策)。
- 検証: Rust のユニットテスト(設定・引数・状態遷移・ポート使用中・タイムアウト・再起動・競合・ログ)、実機の ComfyUI での起動 → 再起動 → 停止(`cargo test -- --ignored real_comfyui_process`。停止後にポートが解放されることまで確認)。画面の目視確認と macOS は未実施(09)。
- **初期値の自動入力(追加)**: 設定値がわからないユーザー向けに、未設定の `main.py` / Python / base-directory は、候補(§3)を初期値として画面に入れて返す(保存はユーザーが有効化して「保存」したとき)。起動中の ComfyUI がない場合は、実行ファイルの場所とカレントディレクトリから親方向に最大 8 階層、`comfyui/ComfyUI/main.py` または `ComfyUI/main.py`(08 のレイアウト)を探す。Python は `venv`、base-directory は `data` があるときだけ入れる。見つからなければ空欄のまま(従来どおり手入力)。ポートの既定は 8188。
