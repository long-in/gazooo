# 33. 下書きモード(v0.27、M29)

> ステータス: 🟡 レビュー待ち(07 Q-190〜198)。実装は承認後。生成フォーム(05)・ジョブ(03・04)・ワークフロー(02)への追記を伴う。

## 1. 目的

構図やプロンプトを試す段階では、1 枚に 3〜12 分かかる本番設定(大きい解像度・多いステップ)は重い。**同じ設定のまま、スイッチ 1 つで「小さく・速く」生成できる下書きモード** を追加し、気に入った結果だけを **[本番で生成]** で本番品質にする。

スコープ外: モデルの量子化・ComfyUI の起動引数の変更(別設計)。AI サポート(11)からの下書きの切り替え。

## 2. 挙動

- 生成フォームに **「下書き」スイッチ** を追加する(生成ボタンの上)。ON のときのボタンは「下書きを生成」。
- ON のジョブは、**ジョブ作成時のパラメータ(元の設定)をそのまま保存し、`draft: true` を付ける**。実際に ComfyUI へ送るワークフローを作るときだけ、Rust 側で次の縮小を適用する(§3)。
- したがって「本番で生成」は、**`draft` を外して同じ設定で再投入するだけ**(シード・プロンプトも同じ)。
- 下書きの画像は通常のジョブと同じくギャラリーに保存し、**「下書き」バッジ** を付ける。ギャラリーとキューのカードに表示し、詳細シートに **[本番で生成]** ボタンを出す。
- **下書きと本番は同じシードでも同じ構図にならない**(解像度が違うとノイズの形が変わるため)。UI の説明(スイッチの「?」Popover)にこれを明記する。構図を保ちたい場合は、本番の前に画像から生成(img2img)や ControlNet を使う。

## 3. 縮小の規則(Rust。`draft = true` のときだけ)

| 項目 | 規則 |
|---|---|
| 解像度 | 縦横とも **0.5 倍**(64 の倍数に丸め、最小 256)。生成画像の縦横比は保つ |
| ステップ数 | **0.5 倍**(切り上げ。最小 4)。蒸留モデルなど元が少ないものも同じ規則 |
| 顔補正(FaceDetailer) | **無効**(下書きでは実行しない) |
| ControlNet | そのまま(ユニットの設定は変えない)。参照画像は生成サイズに合わせて縮小される(既存の挙動) |
| 画像から生成(img2img) | 縮小したサイズで実行(元画像は ImageScale で合わせる。既存の挙動) |
| Inpaint | **下書き非対応**(マスク外を元画像と一致させる合成のため、サイズを変えられない)。Inpaint が有効なとき、スイッチは無効にして理由を表示する |
| 参照画像つき生成(Qwen-Image 2.1 の編集) | 解像度のみ縮小(`resolution` は変更しない) |
| 枚数(`count`)・バッチ(`batchSize`)・サンプラー・CFG・シード・モデル | 変更しない |

縮小後の値は検証(03 の範囲)を通す。通らない組み合わせ(最小値を下回るなど)は、最小値に丸める。

## 4. データ(03 に追記)

- `GenerationParams` に **`draft: bool`**(`#[serde(default)]` = false)を追加する。`params_json` の項目追加のみで、**DB のマイグレーションは不要**(既存のジョブは `draft` が無く false 扱い)。
- 画像の実サイズはファイルから取る既存の経路を使う(詳細シートの「サイズ」は、パラメータではなく実際の画像サイズを表示する。下書きではパラメータと一致しないため)。
- 再現・プリセット: `draft` はプリセットに **保存しない**(プリセットは本番設定)。「設定を読み込む」(27)では `draft` も読み込み、下書きの画像から読み込むとスイッチが ON になる。

## 5. IPC(04 に追記)

- `job_enqueue` の `GenerationParams` に任意の `draft?: boolean` が加わる(後方互換: 無ければ false)。コマンドの追加・変更はない。
- `Job` / `ImageRecord` の `params` にも `draft` が含まれる(表示用)。

## 6. UI(05・28 に追記)

- 生成フォーム: 「下書き」スイッチ + 「?」Popover(縮小の内容・構図が変わること)。状態は **フォームの下書き保存(form-store)に含める**(次回起動後も維持)。
- キューのカード・ギャラリーの画像: 「下書き」バッジ(小さい表示)。
- ギャラリー: 絞り込みに「下書きを含む/除く」を追加する(既定は **含む**。Q-195)。
- 詳細シート・画像のコンテキスト操作: **[本番で生成]**(`draft = false` で再投入。同じシード)。複数選択からの一括は対象外。
- 失敗の通知(28 §9)・再試行(28 §8)は、`draft` をそのまま引き継ぐ。

## 7. テスト

- Rust: 縮小の規則(解像度の丸め・最小値、ステップの切り上げ・最小値、顔補正の無効化、Inpaint では下書きを拒否 `VALIDATION`)。`draft` の有無でワークフローの `KSampler` の steps・`EmptyLatentImage` のサイズが変わること。`draft` が無い既存の `params_json` が false として読めること。
- Vitest: スイッチの状態の保存・復元、Inpaint 有効時の無効化、[本番で生成] が `draft = false` で投入すること、プリセット保存で `draft` が落ちること。
- 手動: 実機の ComfyUI で、同じ設定の下書き(所要時間の短縮)と本番を比べる(09 の検証ログに追加)。

## 8. リスク

- 下書きと本番で構図が変わるため、「下書きで選んだものが本番で別物になる」と感じる可能性がある(§2 の説明と、img2img・ControlNet の案内で緩和)。
- モデルによっては小さい解像度で品質が極端に落ちる(例: 1024 前提のモデルで 512)。0.5 倍の規則が不適切なモデルがあれば、種別ごとの係数に分ける(実機で確認後。Q-192)。
