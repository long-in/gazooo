# 27. 生成ページの作業台化(キュー右サイド + 下部ギャラリー帯)(v0.19)

> 注(2026-11-20): §2(レイアウト)・§3(帯)・§4(キュー)・§5 は、28 の提案(キューとギャラリーの統合)が承認された場合に置き換わる(28 は承認済み・実装済み。右サイドは廃止された)。
> ステータス: 🟢 承認済み(2026-11-20。Q-133〜138 は推奨どおり確定。07 の Q-133〜138)。
> 経緯: 生成のプロンプトなどを、ギャラリーの生成物を見ながら調整したい。ギャラリーの画像を選んで、そのまま次の生成のベースにしたい。そのため、生成ページにキューとギャラリーを同居させる(ユーザー指示)。**ギャラリーページ(`/gallery`)は画像管理の機能が必要なので残す**。**キューページ(`/queue`)は不要(ユーザー指示)のため廃止し、キューの機能はすべて右サイドに移す**。

## 0. 実装時の判断(設計との差異)

- 右サイドのキューは `queue/queue-view.tsx` を `generate/queue-sidebar.tsx` に移して作った(`job-row.tsx`・`running-summary.tsx` は `queue/` に残し、`compact` プロパティは作らず常に狭い幅向けのレイアウトにした)。
- 帯のサムネイルのホバーのツールチップは、`image_get` を初回のホバー(またはフォーカス)で取得してキャッシュする(`ImageItem` にプロンプトが無いため)。
- 帯の折りたたみ状態・選択は、アプリ内(zustand。画面を移っても保持)で、再起動では戻らない。選択は生成ページを離れると解除する。
- `Ctrl/Cmd + 1..` は 6 → 5 項目に詰め直した。

## 1. 目的とスコープ

**やること**
- 生成ページを「**メイン = 生成フォーム**、**右サイド = キュー**、**画面下全体 = ギャラリー帯(横スクロール)**」の構成にする。
- ギャラリー帯で画像を選ぶと、そのプロンプト・設定を見ながら、**設定の読み込み・プロンプトだけの読み込み・img2img / ControlNet / Inpaint / Qwen 参照の元画像への設定**ができる。
- 生成したものが、ギャラリー帯に自動で現れる(結果の確認のため画面を移動しなくてよい)。

**やらないこと**
- `/gallery`(検索・複数選択・一括削除・エクスポート等の画像管理)の廃止・縮小。残す。

**やめること**
- `/queue` ページ。ナビの項目・ルート・ショートカット(`Ctrl/Cmd + 3`)を削除し、機能は右サイドのキューへ移す(§4)。
- IPC・DB スキーマの変更(既存の `image_list` / `job_*` / イベントのみで足りる。§7)。
- キュー・ギャラリー帯の並び順のドラッグ操作、帯の中での削除・一括操作(管理は `/gallery` で行う)。

## 2. レイアウト

```
┌────┬──────────────────────────────────────┬─────────────────┐
│Nav │ [エンジンバナー]                      │ キュー           │
│    │ ┌────────────────┬─────────────────┐ │ 実行中 12/25 ▓▓░ │
│    │ │ 生成フォーム    │ 補助            │ │ ─────────────── │
│    │ │ (プロンプト,   │ モデルの説明    │ │ [▢] 待機 …  ↑↓ ✕ │
│    │ │  モデル,サイズ, │ 参照画像        │ │ [▢] 待機 …       │
│    │ │  拡張機能…)    │ 目安・履歴      │ │ ─────────────── │
│    │ │                │                 │ │ 完了 [thumb] …   │
│    │ └────────────────┴─────────────────┘ │ [すべて見る →]   │
│    ├──────────────────────────────────────┴─────────────────┤
│    │ ギャラリー  [☆のみ] [検索…]    選択中: 「prompt…」 [読込▾]│
│    │ [thumb][thumb][thumb][thumb][thumb][thumb][thumb] → …   │
└────┴────────────────────────────────────────────────────────┘
```

- **メイン(中央)**: 現行の 2 カラム(左: フォーム、右: 補助 = モデルの説明・参照画像ワークスペース・目安・プロンプト履歴。20 §4.2)をそのまま置く。ページの見出し「生成」は省き、縦の領域を確保する。
- **右サイド(キュー)**: 幅は固定(約 20rem)。§4。
- **下部(ギャラリー帯)**: 画面下の全幅(ナビを除く)。高さは固定(サムネイル約 7rem + ヘッダ)。**横スクロール**(ホイールの縦回転も横に変換する)。§3。
- メインだけが縦スクロールする(キューとギャラリー帯は画面に固定)。帯はヘッダの [▾] で折りたため、折りたたむとヘッダ 1 行になる(状態はアプリ内に保持。Q-137)。

### 2.1 幅が狭いとき(Q-138)

最小ウィンドウは 960×640(05 §1)。

| 幅 | 配置 |
|---|---|
| `xl`(1280px)以上 | 上記の 3 領域(フォーム・補助・キューの 3 列) |
| `xl` 未満 | フォームと、右サイド(**タブ [キュー] [補助]**)の 2 列。補助(モデルの説明・参照画像・目安・履歴)は右サイドのタブに移る |
| `lg`(1024px)未満 | 1 カラム(フォーム → 補助 → キュー)。ギャラリー帯は下部固定のまま |

## 3. ギャラリー帯

### 3.1 一覧

- 既存の `image_list`(`(created_at, id)` のキーセット方式。03)を使い、**新しい順に左から**サムネイル(384px の既存サムネイル)を並べる。右端に近づいたら続きを読み込む(無限スクロール)。
- 帯は `/gallery` のフィルタとは**独立**に動く(`/gallery` で検索しても帯は変わらない)。帯自身のヘッダに、[お気に入りのみ] と検索(プロンプト。300ms のデバウンス)だけを持つ(Q-135)。
- 生成が完了して画像が保存されたら(既存の `job://*` イベント)、**帯の先頭に追加**する。フィルタ中は条件に合うものだけ。
- 表示範囲外のサムネイルは読み込まない(`loading="lazy"`)。横方向の仮想化は、件数が数千を超えて重くなった場合に限り検討する(初版は遅延ロードのみ)。

### 3.2 操作(Q-134)

| 操作 | 動作 |
|---|---|
| ホバー | ツールチップにプロンプトの先頭(約 120 文字)・モデル・サイズ |
| クリック | **選択**(1 枚)。帯のヘッダに「選択中」の情報(プロンプト・ネガティブ・モデル・シード等)と操作ボタンを出す。同じ画像を再クリックで選択解除 |
| ダブルクリック / [詳細] | 既存の詳細シート(`ImageDetailSheet`。原寸・全パラメータ・コピー・エクスポート・削除等)を、**生成ページの上に**開く(ページ遷移しない) |

選択中の画像に対する操作(ヘッダのボタン。有効にできないものは無効化し、理由をツールチップで示す):

| ボタン | 動作 |
|---|---|
| **設定を読み込む** | 「この設定で生成」と同じ(`loadParams`、シードは画像のシードに固定)。フォームがその設定に置き換わる |
| **プロンプトだけ** | プロンプトとネガティブだけをフォームへ入れる(モデル・サイズ等は変えない)。[置き換え] / [追加] を選べる(20 §4.2 のプロンプト履歴と同じ操作) |
| **ベースにする ▾** | 元画像として設定する(画面は移動しない)。選択肢: img2img の元 / ControlNet の参照 / Inpaint の元 / Qwen の参照(Qwen-Image 2.1 のとき)。既存の取り込み(`input_image_from_gallery`)と、各機能のスイッチの有効化を使う |
| ☆ | お気に入りの切り替え |
| 詳細 | 詳細シートを開く |

- 既存の詳細シートの同名ボタン([参照画像に使う]・[img2img に使う]・[Inpaint に使う]・[Qwen の参照に使う])は(Q-344 で [画像からアニメ調に] を削除)、現在「生成画面へ移動」を伴う。**生成ページ上では移動せず、その場で適用**する(ギャラリーページからは従来どおり移動)。処理を共通の関数(`lib/gallery/use-image-as.ts`、新規)へ切り出し、詳細シートとギャラリー帯の両方から使う。
- 設定を読み込む際、フォームに未保存の入力がある場合の確認は**しない**(従来の「この設定で生成」と同じ。戻したいときは 21 の「初期値に戻す」や、プロンプト履歴を使う)。

## 4. キュー(右サイド)

`/queue` を廃止するため、キューの機能(20 §3)をすべてここに置く。幅が狭いので、1 列の縦リストにして、詳細は行内で展開する。

- **上部**: 実行中ジョブの進捗(ステップ・経過・残りの目安。既存の `RunningSummary` を再利用)と、[一時停止 / 再開]。一時停止中は常に表示する。
- **フィルタ・検索**: タブ(すべて / 実行中・待機 / 完了 / 失敗・キャンセル。件数つき。幅に収まらない場合はアイコン + 件数)と、プロンプト・モデルの検索(クライアント側)。
- **行**: サムネイル(完了は最大 4 枚。クリックでギャラリー帯のその画像を選択)・プロンプトの先頭・モデル・状態。行を開くと設定一覧・所要時間・エラーを展開する。
  - 待機中: 上へ・下へ・先頭へ・末尾へ・キャンセル。実行中: キャンセル。
  - 完了・失敗・キャンセル: もう一度生成(新しいシード)/ 再試行 / 設定を読み込む / 履歴から削除。
- **一括操作**: 行のチェックボックスで複数選択し、選択をキャンセル / 再試行 / 履歴から削除。ほかに「待機中をすべてキャンセル」「失敗をすべて再試行」「履歴クリア」(確認ダイアログあり)。これらはキューのヘッダのメニュー([⋯])にまとめる。
- **履歴**: 最初は直近の分を表示し、「さらに読み込む」で `cursor` により続きを取得する(20 §3.1)。
- `queue/job-row.tsx` と `queue/queue-view.tsx` のロジックを、右サイドの `QueueSidebar` に移して再構成する(`queue-view` と `/queue` のルートは削除)。状態・操作のロジックは既存の `job-store` と `lib/queue` をそのまま使う。

## 5. 画面共通ヘッダとの関係

- 画面共通ヘッダの実行状況(20 §4.1「生成中 n/m · 待機 k」)は、**生成ページでは表示しない**(キューが同じ画面にあるため)。他のページでは表示し、クリックで**生成ページ**(`/`)へ移る。
- 生成投入時のトースト「キューに追加しました」の [キューを開く] ボタンは、生成ページでは出さない(同じ画面にあるため)。他のページでは生成ページへ移る。

## 6. ショートカット・フォーカス

- `Ctrl/Cmd + 1..6` の画面切替、`Ctrl/Cmd + Enter`(生成)、`Esc`(実行中のキャンセル。ダイアログ非表示のとき)は変更しない。
- ギャラリー帯: 帯にフォーカスがあるとき `←` / `→` で選択を移動、`Enter` で詳細シート、`Space` で選択の切り替え。帯のサムネイルは `button` とし、`aria-label` にプロンプトの先頭を入れる。
- 詳細シートを閉じたとき、フォーカスは帯のサムネイルへ戻す。

## 7. 実装方針(承認後)

- 変更は**フロントエンドのみ**。IPC(04)・DB(03)・Rust は変更しない。
- 新規・変更するもの:
  - `components/generate/generate-view.tsx`: 3 領域(中央・右サイド・下部)のグリッドに再構成。
  - `components/generate/gallery-strip.tsx`(新規): ギャラリー帯。`stores/strip-store.ts`(新規。`image_list` のページング・帯専用のフィルタ。生成完了イベントで先頭追加)。
  - `components/generate/queue-sidebar.tsx`(新規): キュー(右サイド)。`queue/queue-view.tsx`・`queue/job-row.tsx` を移して再構成し、`app/queue/` を削除する。
  - `components/layout/app-shell.tsx`・`use-global-shortcuts.ts`: ナビの「キュー」を削除し、`Ctrl/Cmd + 1..` を詰め直す(画面切替は生成 / ギャラリー / プリセット / モデル / 設定の 5 つ)。
  - i18n の `nav.queue` と、`/queue` へのリンク(ヘッダ・トースト・ギャラリー等)を生成ページへの導線に変更する。
  - `lib/gallery/use-image-as.ts`(新規): 「ベースにする」系の処理の共通化。`gallery/image-detail-sheet.tsx` を利用側に切り替える(ギャラリーページでの挙動は従来どおり)。
  - `components/layout/job-status-bar.tsx`: 生成ページでは非表示。
  - i18n メッセージの追加。
- 詳細シートは現在、URL の `?id=`(`/gallery`)で開閉する。生成ページでは状態(`openId`)で開閉できるよう、`id` と `onClose` を受け取る形に整理する(`/gallery` は従来どおり URL に連動)。
- 既存の `GalleryGrid`(縦の仮想グリッド)は変更しない(`/gallery` で使用)。

## 9. リスク

- **縦の領域が足りない**(最小 960×640 では帯 + ヘッダで約 10rem を取る)。→ 帯を折りたためる(§2)。見出しを省く。メインだけをスクロールさせる。
- **右サイド(約 20rem)にキューの全機能を入れると窮屈**。→ 1 列の縦リスト・行内展開・[⋯] メニューで収める。実機で窮屈なら幅の変更(リサイズ可能に)を再提案する。
- **3 列で横が狭い**。→ §2.1 の段階的な配置。
- **帯と `/gallery` のストアの二重管理**。→ 帯は専用のストア(読み込みは同じ IPC)とし、状態を共有しない。詳細シートでの削除・お気に入りの変更は帯にも反映する(ストアの購読)。
- **「ベースにする」でスイッチが暗黙に有効になる**。→ 適用時にトーストで知らせる(既存の挙動と同じ)。
