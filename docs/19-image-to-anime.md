# 19. 画像からアニメ調への変換(img2img、v0.11)

> ステータス: 🟢 承認済み(2026-11-19。Q-81〜88 は推奨どおり確定。07 の Q-81〜88)。実装済み(M15。実機検証は 09 の検証ログ)。
> 経緯: 「手持ちの画像(写真・イラスト)をもとに、アニメ調の画像を作りたい」という要望。アニメ特化モデルの取得・選択(16・17・18)は整ったが、**元画像から出発する生成**(img2img)は 01 で範囲外としていた。Inpaint(13)の参照画像の仕組みと ControlNet(10)を流用して、最小の UI で提供する。

## 1. 目的とスコープ

**やること**
- **F-18 画像からアニメ調へ**: 元画像を出発点にして、アニメ系モデルで描き直す(img2img)。変換の強さ(denoise)を調整できる。
- **構図の固定**: 元画像の輪郭を ControlNet(既存の F-12)に渡し、形を保ったまま画風だけを変える。スイッチ 1 つで、ControlNet の設定を自動で組む。
- ~~**かんたん開始**: 「画像からアニメ調に」ボタン~~ → **廃止(§3.1。2026-11-23、ユーザー指示。07 Q-344)**。

**やらないこと(v0.11)**
- 画像編集モデル(Qwen-Image 2.1 の参照画像入力など)による「指示だけの変換」(方式 C。Q-82)。**v0.16 の [24](24-qwen-reference-image.md) で別途設計**(本資料の img2img とは別経路として両方残す)。
- 元画像からのプロンプトの自動生成(画像解析。Claude の画像入力や、ローカルのタガー。Q-86)。**→ v0.34 で [39](39-image-to-prompt.md)(F-20)としてローカルのタガー(WD14 Tagger)を設計。**
- `sd15` / `sdxl` 以外のモデル種別(Anima・Qwen-Image 2.1・Krea 2・Flux 系。Q-81)。
- 動画・複数画像の一括変換(バッチ)、LoRA、IP-Adapter(参照画像の画風・人物の転写)。

## 2. 要件

| ID | 機能 | 内容 |
|---|---|---|
| F-18 | 画像からアニメ調へ | 元画像と変換の強さを指定し、元画像を出発点に再生成する。`sd15` / `sdxl` のみ。Inpaint とは排他。ControlNet・顔補正とは併用できる |

## 3. 利用者の体験

1. 生成画面に「画像から生成(img2img)」セクション(スイッチ付き)を追加する。
2. 元画像の指定は Inpaint・ControlNet と同じ(ファイル選択、またはギャラリー詳細の「img2img に使う」)。
3. 強さ(denoise)を「弱 / 中 / 強」のボタンか、スライダーで選ぶ。
   - 弱(0.45): 元の見た目を強く残す。写真の質感が残りやすい。
   - 中(0.6、既定): 構図を保ちつつ、アニメ調に変わる。
   - 強(0.75): 画風はしっかり変わる。形が崩れやすい(ControlNet で補う)。
4. 「構図を固定する(ControlNet)」を入れると、元画像の輪郭(Canny)を条件に加える。
5. プロンプトは「何が写っているか」をタグで書く、とフォームに注記する(例: `1girl, long hair, school uniform, outdoors`)。元画像からの自動入力はしない(Q-86)。
6. 「生成」で、元画像と同じ縦横比の画像が、通常の生成と同じようにギャラリーへ保存される。

### 3.1 かんたん開始(「画像からアニメ調に」)【廃止(07 Q-344)】

> **2026-11-23 の変更**: 「画像からアニメ調に」ボタンは不要との指示により、**生成画面・ギャラリー詳細・ギャラリー帯のボタンを削除する**。img2img の機能本体(スイッチ・元画像・強さ・構図固定)と [img2img に使う] は残す。以下は旧仕様(履歴として残す)。

- (旧)生成画面の元画像の欄と、ギャラリー詳細の操作に **[画像からアニメ調に]** を置く。押すと次を一度に設定する(ユーザーが後から変更できる)。
  1. 元画像を img2img に設定する(ギャラリーの画像なら、その画像)。
  2. モデル: 導入済みの **アニメ系の `sdxl` ファミリー**(カタログの `tags` に `anime` を持つチェックポイント。`recommended` を優先)を選ぶ。無ければ、ダイアログで「アニメ系モデルがありません」と案内し、モデル取得(`/models?purpose=anime`)へ誘導する(自動取得はしない)。
  3. denoise 0.6、ステップ・CFG・サンプラーは、そのモデルの推奨(`profile.recommended`。18)。
  4. 「構図を固定する」: ControlNet のモデルと前処理(Canny)が使えるときだけオン。使えないときはオフにし、理由を表示する。
  5. プロンプトは空のまま(ユーザーが入力する)。ネガティブは、モデルの推奨があればそれを入れる。
- 実体は 16 §の組み込みプリセットと同じ仕組み(コード定数)で、**新しい保存形式は作らない**。

## 4. パラメータ(`GenerationParams.img2img`)

```ts
interface Img2imgParams {
  enabled: boolean;
  image: string;    // 元画像(inputs/<uuid>.png。10 §6・13 §3.4 と同じ保管)
  denoise: number;  // 0.05〜1.0、既定 0.6
}
```

- 「構図を固定する」は **新しいパラメータを持たない**。スイッチを入れたとき、UI が既存の `controlnet`(10 §5)を設定する(`units[0].image` を元画像と同じパスにし、`preprocessor: canny`、`strength: 0.8`、`endPercent: 0.8` を既定にする。モデルは候補の先頭)。スイッチを切ると、`controlnet.enabled` を false にする。ControlNet のセクションで個別に調整もできる(その場合、スイッチの表示は「ControlNet の画像が元画像と同じで有効」かどうかで決める)。
- **検証**(`job_enqueue`): `sd15` / `sdxl` 以外は `VALIDATION`。`image` が存在すること(無ければ `IMAGE_NOT_FOUND`)。**Inpaint が有効なら `VALIDATION`**(どちらも元画像から潜在を作るため排他。13 の `inpaint` と同時に enabled にできない)。`denoise` は 0.05〜1.0。
- **出力サイズ**: Inpaint(13 §3.2)と同じ規則。元画像のサイズを 64 の倍数・256〜2048 に丸め、長辺が 2048 を超える画像は縦横比を保って縮小する。フォームの幅・高さは元画像の選択時に設定し、img2img が有効な間は手動で変えられない(Q-88)。
- 枚数(`batchSize`)は 1 以上。2 以上のときは、潜在を枚数分に増やす(`RepeatLatentBatch`)。
- スキーマ: `GenerationParams` に任意項目を足すだけ(`inpaint` を足したときと同じ)。DB のマイグレーションは不要(実装時に `schema_version` の扱いを確認する)。

## 5. ワークフロー(ComfyUI のコアノードのみ)

```
LoadImage(image) ─ ImageScale(生成サイズへ) ─ VAEEncode(チェックポイントの VAE) ─ [RepeatLatentBatch] ─┐
                                                                                                        ↓
CLIPTextEncode(+ControlNet 適用後) ──────────────────────────────→ KSampler(latent_image, denoise) ─ VAEDecode ─ SaveImage
```

- 通常の txt2img の `EmptyLatentImage` を、`LoadImage` → `ImageScale` → `VAEEncode`(→ `RepeatLatentBatch`)の出力に置き換え、`KSampler.denoise` に `img2img.denoise` を渡すだけ。追加のカスタムノードは不要。
- ControlNet(10 §5)・顔補正(10 §4)は、既存のパスのまま重ねる(順序: ControlNet は positive / negative の conditioning、顔補正は最後の仕上げ)。ControlNet の元画像が img2img と同じファイルでも、実装では **それぞれアップロードする**(`LoadImage` は共有しない。単純さを優先。画像の並びは ControlNet のユニット、img2img の元画像の順)。
- ノード ID(実装で確定): LoadImage 80、ImageScale 81、VAEEncode 82、RepeatLatentBatch 83(枚数 2 以上のときのみ)。既存の 20〜22(顔補正)、30〜(ControlNet)、60〜(Inpaint)と重ならない。`KSampler`(5)の `latent_image` を置き換え、`denoise` を設定する。`EmptyLatentImage`(4)は残るが、出力につながらないため実行されない(Inpaint と同じ)。
- 必要ノード(`LoadImage` `ImageScale` `VAEEncode` `RepeatLatentBatch`)が 1 つでも無ければ、`engine_status.features.img2img` が false になりスイッチを無効にする(`ENGINE_NODE_MISSING`。10 §7 と同じ)。
- 実装前に、既存のワークフロー生成(02 §3、`workflow.rs`)の構造を確認し、設計との差異があれば本資料を先に更新する。

## 6. 参照画像・再現・履歴

- 元画像の取り込み・保管は 10 §6 と同じ(PNG 再エンコード、メタデータ除去、`inputs/` に保管、相対パスを `params_json` に記録)。**新しい IPC は不要**(既存の `input_image_*` を流用)。
- 「この設定で生成」・プリセット・ギャラリー詳細は、img2img の設定を保存・復元する。画像が欠損していれば img2img を無効にして復元し、トーストで知らせる(10 §8)。
- ギャラリー詳細に、元画像の小さなサムネイルを併記する(ControlNet の参照画像と同じ扱い)。
- 組み込みプリセット(16)は **元画像のパスを含められない** ため、(旧)「画像からアニメ調に」は §3.1 のとおり、プリセットではなくボタンの処理(フォームへの一括設定)とした(ボタンは廃止)。ユーザーが保存するプリセットには、画像が欠損していても復元できる形(欠損時に無効化)で保存される。

## 8. AI サポート(11・13 §4)への反映

- 機能カタログ(`services/assistant/capabilities.rs`)に F-18 の使いどころ(アニメ調への変換、denoise の目安、構図の固定、Inpaint とは併用不可)を追記する。「できないこと」には、元画像からのプロンプト自動生成・画像編集モデルによる指示変換を挙げる。
- 現在のフォームのスナップショットに `img2img: { enabled, denoise, hasImage }` を追加する(画像のパスは送らない)。`capabilities` に `img2img` を加える。
- `suggest_params` のホワイトリストには **加えない**(2026-11-19、実装時の判断)。強さ(denoise)は、画像の有無や構図の固定と合わせて調整するものなので、提案ではなく本文で目安(弱 0.45 / 中 0.6 / 強 0.75)と手順を説明させる。必要になれば別途追加する。
- 追加で外部へ送られるのは、数値(denoise)と有無のみ。**画像そのものは送らない**。

## 9. テスト方針

- Rust: ワークフロー生成(`EmptyLatentImage` が `VAEEncode` 経路に置き換わる、`denoise` の反映、枚数 2 以上の `RepeatLatentBatch`、ControlNet・顔補正との併用でノード ID が衝突しない)、検証ルール(Flux・分割モデルの拒否、Inpaint との排他、画像の欠損、denoise の範囲)、`engine_status.features.img2img` の判定、AI のスナップショットに画像パスが含まれないこと。ComfyUI 実機のテストは `#[ignore]`(既存方針)。
- フロント(Vitest): 構図固定スイッチと ControlNet パラメータの相互変換、強さのボタン(弱・中・強)と数値の対応、有効/無効条件、フォーム→パラメータの変換、(~~「画像からアニメ調に」の一括設定~~ は廃止)、プリセット復元(欠損時の無効化)。
- 手動(09 に追加): 実際の写真・イラストでの変換の質(弱・中・強の違い、構図固定の有無)、サイズの丸め、Inpaint との排他表示、アニメ系モデルが無いときの導線、AI が F-18 の手順を正しく案内すること。

## 11. リスク

- 人物の特徴(顔・髪色)が denoise を上げると変わりやすい → 既定を 0.6 とし、構図固定と強さの目安を UI に表示する。完全な人物の保持(IP-Adapter・顔の転写)は対象外。
- 大きな画像での VRAM 不足 → 出力サイズを 2048 以内に丸める(Inpaint と同じ)。生成時の OOM は既存のエラー表示(`ENGINE_OOM` 相当)に従う。
- アニメ系モデルの種類による変換結果の差 → モデルの説明(18)で用途を示す。`sd15` 系のアニメモデルは、解像度が低い(512 系)ため、アニメ系の `sdxl` を優先する。
