# 28. キューとギャラリーの統合(画面下部の 1 本の帯)(v0.20)

> ステータス: 🟢 承認済み・実装済み(2026-11-20。07 の Q-139〜145 は推奨どおり。型チェック・ESLint・Vitest まで確認。画面の目視確認は未実施)。
> 経緯: 27 で「右サイド = キュー、画面下 = ギャラリー帯」とした。ユーザーから「キューとギャラリーを一緒にして、画面下部のギャラリーに寄せたらどうか」との提案があった。キューも「これから生成される画像の並び」と見なせるので、**1 本の横スクロールの帯**にまとめる。27 の §2(レイアウト)・§3(帯)・§4(キュー)・§5 を置き換える。それ以外(`/gallery` を残す、`/queue` を廃止、「ベースにする」の共通化 など)は 27 のまま。

## 0. 実装時の判断(設計との差異)

- 帯は `generate/library-strip.tsx`(旧 `gallery-strip.tsx`)。キューのカードは `queue-card.tsx`、サマリは `queue-summary.tsx`、ジョブの詳細は `job-detail-sheet.tsx`。`queue-sidebar.tsx`・`queue/job-row.tsx`・`queue/running-summary.tsx` は削除した(計算は `lib/queue.ts` のまま)。
- 帯の選択は `strip-store` の `selectedId`(画像)と `selectedJobId`(カード)で、同時には選べない。フィルタ(`all` / `queue` / `images`)も同ストア。
- 「もう一度生成」は、画像・失敗/キャンセルのカードの両方に置いた(新しいシードで 1 件投入)。
- (2026-11-20 追加の調整)生成フォームの「拡張機能」(参照画像・画像から生成・Inpaint・ControlNet・顔補正)を、右側のワークスペースの先頭へ移した(`extras-panel.tsx`)。投入時の入力エラーは `stores/form-error-store.ts` で、フォームと拡張機能のパネルの両方に出す。
- 履歴クリア(`job_clear_finished`)の操作は、[⋯] から外した(「失敗・キャンセルをすべて削除」で代替)。

## 1. 目的

- 右サイドをなくし、**メイン(フォーム + 補助)に横幅をすべて使う**。幅が狭いときのタブ切り替え(27 §2.1)も不要になる。
- 「これから生成されるもの」と「生成されたもの」を、**同じ場所・同じ操作**(選択 → 下のボタン)で扱う。
- 生成の流れ(投入 → 待機 → 実行 → 完成)が、帯の中で左から右へ時間順に見える。

## 2. レイアウト

```
┌────┬──────────────────────────────────────────────────────┐
│Nav │ [エンジンバナー]                                      │
│    │ ┌──────────────────┬───────────────────────────────┐ │
│    │ │ 生成フォーム      │ 補助(モデルの説明・参照画像・ │ │
│    │ │                  │  目安・プロンプト履歴)         │ │
│    │ └──────────────────┴───────────────────────────────┘ │
│    ├──────────────────────────────────────────────────────┤
│    │ ● 生成中 12/25 · 残り約 1:20 · 待機 2  [⏸][⋯]         │
│    │ [すべて|キュー|画像] [☆] [検索…]   選択中: … [操作…]   │
│    │ [▓実行中][待機1][待機2] │ [img][img][img][img] → …    │
└────┴──────────────────────────────────────────────────────┘
```

- メインは **2 カラム(フォーム | 補助)** のみ。`lg`(1024px)未満は 1 カラム(フォーム → 補助)。
- 帯は画面下の全幅。**左側がキュー(実行中 → 待機中の順)、区切り線を挟んで右側が生成済みの画像**(新しい順)。横スクロールは 27 と同じ。
- 帯の上部に、実行状況の 1 行(**サマリ**)、フィルタ・検索・選択中の操作を置く。帯は折りたためる(27 Q-137 のまま)。

## 3. 帯の内容

### 3.1 キューのカード(左側)

| 状態 | 表示 |
|---|---|
| 実行中 | サムネイルと同じ大きさ(約 7rem)のカード。プロンプトの先頭・進捗バー(ステップ)。最左 |
| 待機中 | 同じ大きさのカード。プロンプトの先頭・「待機 n」。実行順に左から右 |
| 失敗・キャンセル | 赤 / 灰のカード(理由の要約)。**履歴から削除するまで残る**(§3.3) |

- ジョブが完了したら、そのカードは消え、**生成された画像が画像の先頭に現れる**(既存の `job://*` と画像追加イベント)。完了済みのジョブはカードにしない(画像がその役目を持つ)。
- カードは画像と同じく、クリックで選択、`←` `→` で移動、ダブルクリック / Enter で詳細。

### 3.2 画像(右側)

27 §3 と同じ(新しい順・無限スクロール・お気に入り・ホバーのツールチップ・選択 → 設定の読み込み / プロンプトだけ / ベースにする / お気に入り / 詳細)。

### 3.3 選択中の操作(帯ヘッダ)

選択したものに応じて、ヘッダに出す操作が変わる。

| 選択 | 操作 |
|---|---|
| 画像 | 27 §3.2 のとおり(設定を読み込む・プロンプトだけ・ベースにする・お気に入り・詳細)。**もう一度生成**(同じ設定・新しいシード)を加える |
| 実行中のカード | キャンセル、詳細 |
| 待機中のカード | **◀ 前へ・▶ 後へ・先頭へ・末尾へ**(`job_reorder`)、キャンセル、設定を読み込む、詳細 |
| 失敗・キャンセルのカード | 再試行、もう一度生成、設定を読み込む、履歴から削除、詳細(エラーの全文) |

- **詳細**: ジョブの詳細シート(新規 `JobDetailSheet`。プロンプト・ネガティブ・モデル・サンプラー・サイズ・枚数・シード・有効な拡張・所要時間・エラー。現在の `JobRow` の展開部分を移す)。画像の詳細は既存の `ImageDetailSheet`。

### 3.4 サマリとフィルタ

- **サマリ(1 行)**: 実行中の進捗(ステップ・経過・残りの目安。既存の `RunningSummary` の計算を使う)と待機件数。右に [一時停止 / 再開] と [⋯] メニュー。一時停止中は常に表示する。
- **[⋯] メニュー**: 待機中をすべてキャンセル、失敗をすべて再試行、失敗・キャンセルのカードをすべて履歴から削除(確認ダイアログあり)。
- **フィルタ**(チップ): [すべて](既定)/ [キュー](カードのみ)/ [画像](画像のみ)。件数つき。
- **検索・お気に入りのみ**: 画像に対して(27 と同じ)。キューのカードは、フィルタが [すべて] / [キュー] のとき、検索語があればプロンプトで絞る。

### 3.5 なくす機能(現在のキュー画面からの差分)

| 機能 | 扱い |
|---|---|
| 完了ジョブの行・詳細の展開 | 画像の詳細シート(パラメータ一覧を表示する)で代替。所要時間は画像の詳細に表示を足す(Q-142) |
| 複数選択による一括キャンセル・再試行・削除 | **なくす**。[⋯] メニューの一括操作(待機中 / 失敗)で代替(Q-141) |
| 履歴の「さらに読み込む」 | 画像の無限スクロールに統一。失敗・キャンセルのジョブは、直近分(読み込み済みの履歴)だけをカードにする |
| 先頭へ・末尾へ・上へ・下へ | 残す(待機中の選択時のボタン。◀ ▶ はカードの並びと同じ向き) |
| 一時停止・再開、履歴クリア | 残す(サマリ・[⋯]) |

## 4. 実装方針(承認後)

- 変更は**フロントエンドのみ**。IPC・DB・Rust は変更しない(`job_*`・`queue_*`・`image_list` とイベントを使う)。
- 変更するもの:
  - `components/generate/generate-view.tsx`: 2 カラム + 下部の帯に単純化(`useMinWidth(1280)` とタブは不要になる。`lib/use-min-width.ts` は `lg` の判定だけに使う)。
  - `components/generate/gallery-strip.tsx` → `library-strip.tsx`(名称変更): キューのカード・サマリ・フィルタ・選択中の操作を持つ。`stores/strip-store.ts` に、選択対象を「画像 id またはジョブ id」にする拡張を加える。
  - `components/generate/queue-card.tsx`(新規): キューのカード。`job-detail-sheet.tsx`(新規): ジョブの詳細。
  - `components/generate/queue-sidebar.tsx`・`components/queue/job-row.tsx`: 削除(必要な計算は `lib/queue.ts` のまま使う)。`running-summary.tsx` は計算部分(`useNow`・`runningTiming`)を再利用してサマリに組み込む。
  - 画像の詳細(`ImageDetailSheet`)に、所要時間と「もう一度生成」を足す。
- i18n の整理(`queue.*` のうち不要になったキーを削除)。

## 5. テスト

- Vitest: 帯の並び(実行中 → 待機 → 失敗 → 画像)、完了時にカードが消えて画像が先頭に出ること、選択対象に応じた操作の出し分け、フィルタ・検索、待機中の並べ替え(前へ・後へ・先頭へ・末尾へ)の境界、一括操作の対象。
- 手動(09 に追加): 投入 → 待機カード → 実行中(進捗)→ 完了で画像に変わる流れ、待機中の並べ替え・キャンセル、失敗カードの再試行・削除、一時停止、帯の折りたたみ、`lg` 未満での配置、画像の詳細の所要時間。

## 6. リスク

- **帯が縦に高くなる**(サマリ + フィルタ + 選択操作 + サムネイルで 27 より約 2.5rem 増える)。→ 折りたためる。選択中の操作は、選択したときだけ出す。
- **キューが多いと、画像が右へ押し出される**(待機が数十件など)。→ 待機カードは同じ幅で並ぶため、`枚数` を多く投入した場合に影響する。フィルタ [画像] で切り替えられる。必要ならカードを「待機 +n」に畳む案を再提案する。
- **一括選択をなくす**ことで、失敗を個別に消す手間が増える。→ 失敗・キャンセルの一括削除を [⋯] に置く。
- **履歴の閲覧性が下がる**(完了ジョブの一覧がなくなる)。→ 画像の詳細で代替。ジョブ単位の履歴が必要なら再提案する。

## 8. 生成ページの機能整理(v0.24。承認済み・実装済み 2026-11-21)

> 経緯: ユーザーから「プロンプト履歴は下部のギャラリーで同じことができているので不要では」「失敗したカードを再実行したときに、失敗カードが残って新しいキューが増えるので、失敗したほうは削除してほしい」との指示。07 Q-179・180。

### 8.1 プロンプト履歴パネルの廃止

- 右側のワークスペース(20 §4.2)から **プロンプト履歴**(`PromptHistoryPanel`)を外す。画像を選んで [プロンプトだけ](置き換え / 追加)を使えば同じことができ、失敗・待機のカードにも [設定を読み込む] がある。
- 併せて、不要になる `lib/queue.ts` の `promptHistory` とそのテスト、i18n のキーを削除する。IPC・DB・Rust は変更しない。
- 影響する記述(20 §4.2・§4.3・Q-96・Q-99、27 の各所、29 のドックの「目安・履歴」)は、「プロンプト履歴」を除いたものに読み替える(本節が優先)。27 §2 の「戻したいときは…プロンプト履歴を使う」は、「ギャラリーの [プロンプトだけ] を使う」に読み替える。

### 8.2 失敗・キャンセルのカードの再実行

現状は `job_retry`(Rust)が元ジョブを複製して新規投入するため、失敗カードが残り、新しいカードが増える。次のように変える。

| 操作 | 新しい挙動 |
|---|---|
| 失敗・キャンセルのカードの **再試行**(同じシード) | 新しいジョブを投入し、**成功したら元のカードを履歴から外す**(`job_remove`) |
| 失敗・キャンセルのカードの **もう一度生成**(新しいシード) | **変更なし**(元のカードは残し、新しいキューを 1 件追加する) |
| [⋯] の **失敗をすべて再試行** | 対象の各カードについて同上 |
| 画像(完了ジョブ)の **もう一度生成** | 変更なし(元は画像として残る) |

- 新規投入に失敗した場合は元のカードを消さない(エラーを表示するだけ)。
- 外す操作は既存の `job_remove`(画像を持たないジョブは削除、持つものはキューから隠す。03)をそのまま使う。**変更はフロントエンドのみ**(`job-store` の `retry` と、`library-strip.tsx` の「失敗をすべて再試行」)。Rust の `job_retry` は変更しない。
- 選択中のカードが消えるため、選択は解除する。

### 8.3 テスト

- Vitest: 再試行(一括含む)で、新規投入のあとに元のジョブが `jobs` から外れること。もう一度生成では外れないこと。投入が失敗したら外れないこと。`promptHistory` のテストは削除。
- 手動(09 の生成画面の項目から「プロンプト履歴」を外し、失敗カードの再試行で元カードが消え、もう一度生成では残ることを追加)。

## 9. 生成の失敗の通知(v0.26。レビュー待ち)

### 9.1 問題

生成ジョブが失敗しても、**その場で気づける通知がない**。`job://updated` で帯のカードが赤くなり、理由が小さい文字(約 112px 四方・最大 4 行)で出るだけで、帯が縮んでいる・スクロールしている・別のページにいるときは気づけない。さらに「再試行」(§8.2)は元の失敗カードを外すため、失敗の理由が履歴にも残らない。連続生成中の接続断など、原因の調査も難しくなる。

### 9.2 方針(フロントエンドのみ。Rust・IPC・DB は変更しない)

- `job://updated` で、**ジョブの状態が `failed` に変わった瞬間に 1 回**、エラーの toast(sonner)を出す。
  - 判定は `job-store` が持つ直前の状態との比較(`running` / `queued` → `failed`)。アプリ起動時・再読み込み時に、すでに `failed` のジョブを読み込んでも通知しない。
  - キャンセル(`cancelled`)は通知しない(ユーザーの操作のため)。
- 文言: 「生成に失敗しました: <エラーの説明>」。エラーの説明は既存の `useErrorMessage`(`error.<CODE>` の i18n)を使い、コードも併記する(例: `ComfyUI に接続できません (ENGINE_UNREACHABLE)`)。
- **[詳細を見る]** アクション付き。押すと、そのジョブの詳細(`job-detail-sheet`)を開く(帯のカードのダブルクリックと同じ)。
- 表示時間は **10 秒**(自動で消える。手動でも閉じられる)。
- **連続して失敗したとき**は、同じ toast を **1 件にまとめる**(toast の `id` を固定し、「生成に失敗しました(N 件)」と件数を更新する)。通知が溢れないようにする。
- 失敗の理由が分かる詳細を、詳細シートにも出す(エラーコード・メッセージ。現状の表示に不足があれば補う)。

### 9.3 テスト

- Vitest: `running` → `failed` で 1 回だけ通知されること。起動時にすでに `failed` のジョブでは通知されないこと。`cancelled` では通知されないこと。連続の失敗で 1 件にまとまり、件数が増えること。
- 手動: 生成中に ComfyUI を停止して、toast と [詳細を見る] が動くこと(09 の生成画面の項目に追加)。
