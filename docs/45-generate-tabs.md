# 45. 生成ページの整理: 機能ごと・モデルごとのタブ分け(提案、v0.41)

> ステータス: 🟢 承認済み(2026-11-24。案 A。07 Q-381〜388 は推奨どおり)。**段階 1〜3 は実装済み**(型チェック・ESLint・Vitest・ビルドまで確認。画面の目視確認は未実施。差異は §7)。
> **経緯**: ユーザー要望「生成ページの UI が、機能が多く複雑化してきた。機能ごと・モデルごとにタブで分けるなどの方法を提案してほしい」(2026-11-24)。

## 1. 現状の問題

生成フォームは、共通項目(モデル・プロンプト・サイズ・サンプリング)の下に、**拡張機能 6 つ**(顔の入れ替え・参照画像・画像から生成・Inpaint・ControlNet・顔補正)が **1 つの折りたたみに縦積み**されている(`extras-panel.tsx`)。

- 使えない機能も常に並ぶ(種別ごとに使える機能は決まっている。18 §3・17 §3)。
  | モデル種別 | 使える機能 |
  |---|---|
  | SD 1.5 / SDXL | 画像から生成・Inpaint・ControlNet・顔補正・ネガティブ |
  | Qwen-Image 2.1 | 参照画像・顔の入れ替え・ネガティブ |
  | Flux / Anima / Krea 2 | 文章から生成のみ(Anima はネガティブも) |
- 機能どうしが **排他**(参照画像 ↔ 顔の入れ替え など)なのに、同時に開けて分かりにくい。
- 「かんたん / 詳細」(38)は項目の多さを **隠す** 対処で、機能の **選び方** は変わっていない。

## 2. 案

### 案 A: 機能ごとの「作業タブ」(**推奨**。モデルで出し分け)

フォームの共通部分(モデル・プロンプト・[生成])はそのまま上に置き、**「何をしたいか」のタブ** を共通部分の下に 1 段入れる。

```
 モデル [Qwen-Image 2.1 ▾]      プロンプト [………]
 ┌ 作業 ──────────────────────────────────────────┐
 │ [文章から] [参照画像] [顔の入れ替え]              │  ← モデルで使えるものだけ出る
 ├──────────────────────────────────────────────┤
 │ (選んだタブの設定だけを表示)                     │
 └──────────────────────────────────────────────┘
 ▸ サイズ・サンプリング   ▸ 後処理(顔補正)        [生成]
```

- タブ: **文章から / 画像から(img2img) / 部分修正(Inpaint) / 構図指定(ControlNet) / 参照画像 / 顔の入れ替え**。
- **モデル種別で出し分ける**: 使えないタブは出さない(SD 系 = 文章から・画像から・部分修正・構図指定 / Qwen = 文章から・参照画像・顔の入れ替え / それ以外 = タブ自体を出さない)。モデルを切り替えて今のタブが使えなくなったら「文章から」へ戻し、直前の設定は **保持**(戻すと復活)。
- タブの選択 = 機能の ON/OFF(排他)。内部の `enabled` フラグはタブの選択から決める(今のスイッチは廃止)。**「画像から」と「構図指定」など併用したい組み合わせ**は、§5 の Q-383 で決める。
- **顔補正**は生成後の仕上げなので、タブではなく「後処理」の折りたたみに置く(SD 系のみ)。
- 利点: 画面に出る設定が **今やりたいことだけ** になり、排他も UI で自然に表現できる。モデルで使えない機能は最初から見えない。欠点: 併用(画像から + 構図指定)の扱いに設計が要る。

### 案 B: モデル種別のタブ(非推奨)

「SD / Flux / Qwen …」のタブでモデルごとに画面を切り替える案。**モデルは「選ぶ値」であって「作業」ではない**うえ、タブを切り替えるたびにモデルが変わり、プロンプトや設定の持ち越しが分かりにくい。案 A の「モデルで出し分け」で同じ効果(使えない機能が見えない)が得られるので採らない。

### 案 C: 設定の種類のタブ [基本 | 詳細 | 拡張](最小の変更)

今のセクションを 3 タブに並べ替えるだけ。実装は軽いが、**機能の選び方が複雑なままで、排他も分かりにくい**。案 A の第一段階として先にやる手もある(§4)。

## 3. 推奨する構成(案 A)の詳細

- **かんたん / 詳細(38)との関係**: かんたんは「文章から」のみを出す(従来どおり、追加機能は折りたたみ)。詳細で作業タブを出す。
- **既存の設定の復元**: ジョブ・プリセットから設定を読み込むとき、有効な機能に合わせてタブを選ぶ(複数有効なら §5 の優先順)。
- **キャンバス(29)**: 参照・マスクのタブ(結果 / 参照 / マスク)は、作業タブの選択に連動して切り替える。
- **AI サポート(13)**: 「この機能を使いたい」という提案は、該当する作業タブを開く操作として扱う(`suggest_params` の対象はそのまま)。
- 保存する設定(DB・プリセット)の形式は **変更しない**(`enabled` フラグを持つ従来のまま)。DB マイグレーションなし。

## 4. 実装の段階

1. **段階 1**: 作業タブの骨組みと、モデル種別による出し分け(排他の機能だけ。参照画像 ↔ 顔の入れ替え、画像から ↔ 部分修正)。
2. **段階 2**: 併用できる組み合わせの扱い(§5 Q-383)と、プリセット・ジョブからの復元。
3. **段階 3**: 顔補正を後処理へ移動、キャンバスのタブ連動、AI サポートの連動、09 の確認項目。

## 5. 影響範囲とテスト

- 05(生成画面の構成)、09(確認項目)、38(かんたん / 詳細の関係)、29(キャンバスのタブ連動)に追記。IPC・DB の変更なし。
- Vitest: モデル種別ごとに出るタブ、タブの切り替えで `enabled` が排他になること、モデル変更でタブが戻って設定が保持されること、保存済み設定からのタブ復元。
- 実機: 各モデルでタブの出し分け、排他、既存プリセット・ジョブの読み込み。

## 7. 段階 1 の実装と差異

- 実装: `lib/generation/work-tab.ts`(タブの出し分け・復元・有効化の可否)、`form-store` の `setWorkTab`、`extras-panel.tsx`(タブ行)。
- **タブの選択はオンにできるときだけ機能をオンにする**(ノード・モデルが未導入なら、他の排他機能を切るだけで、セクションの理由メッセージを見せる。各セクションのスイッチは残した)。
- **機能がオンならそのタブを示す**ので、プリセット・ジョブの読み込みに自然に追従する(§3 の復元)。
- ControlNet・顔補正は、**使えるモデル(SD 系)のときだけ** タブ行の下に並べる(従来の「使えません」表示は出さなくした)。タブ化(構図指定・併用の折りたたみ)は段階 2。
- 使える機能が 1 つも無いモデル(Flux・Anima・Krea 2)では、拡張機能のパネルごと出さない。
- かんたんモードも、折りたたみの中に同じタブを出す(§3 の「文章から のみ」ではなく、従来の折りたたみのまま)。

### 段階 2・3(2026-11-24)

- **構図指定のタブ**を追加(ControlNet 単独。SD 系)。**画像から・部分修正のタブの中に「構図指定を併用」の折りたたみ**を置いた(中の機能がオンなら自動で開く)。「構図指定」のタブでは画像から・部分修正を切り、画像から・部分修正のタブでは ControlNet を **そのまま残す**(併用の可否は従来どおり)。それ以外のタブ(文章から・参照画像・顔の入れ替え)へ移ると ControlNet は切れる。
- **顔補正は「後処理」の折りたたみ**(SD 系のみ。オンなら開いて「オン」のバッジ)。
- **キャンバス(ワークスペースの参照画像)** は、作業タブの選択に連動して表示を切り替える(手動の切り替えは、作業タブが変わるまで有効)。
- **AI サポート**: `suggest_params` が変えられる機能は顔補正だけで、顔補正は後処理の折りたたみに残るため、追加の連動処理は不要(提案の適用で顔補正がオンになると、折りたたみの「オン」のバッジに反映される)。
- 選んだタブは表示用の状態で、設定の保存形式・下書きには含めない(Q-387)。
