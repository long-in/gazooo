# 52. 全体設定と個別設定の分離、画像の全体移行(v0.53)

> ステータス: 🟢 承認済み・実装済み(2026-11-26。07 Q-445〜450 は推奨どおり。**画面の目視確認・実機での引き継ぎと移行・macOS は未実施**。差異は §9)。
> **経緯**: ユーザー指示(2026-11-26)「移行はユーザーごとではなく全体で必要。全体設定と個別設定に分けたい。全ユーザーが共通で使う値は全体設定、個別に変えられるものは個別設定。個別設定がある場合は全体設定を上書きする。全体設定には標準値がセットされている」。
> 本書は、[36](36-users.md) §4(設定の区分)と [51](51-storage-migration.md) の画像の移行を改める。51 の実装(移行の手順・進捗・中止・モデルの移行)は土台として使う。

## 1. 考え方

使う値は、次の順に決まる。

**個別設定(あれば) → 全体設定**

- **全体設定**: 全ユーザーに共通。最初から **標準値** が入っている。
- **個別設定**: ログイン中のユーザーが、全体設定を上書きする。上書きしていない項目は、全体設定の変更がそのまま反映される。
- 個別設定を消す([全体設定に戻す])と、全体設定の値になる。
- 全体設定は、どのユーザーでも変更できる(管理者は設けない。36 Q-251 のまま)。

## 2. 項目の分類

### A. 全体設定のみ(PC に 1 つのもの。上書きできない)

| 項目 | キー |
|---|---|
| ComfyUI の接続先・起動管理(導入を含む) | `engine.comfyui.url` / `engine.comfyui.managed` |
| モデルの保存先 | `engine.comfyui.models_dir` |
| ローカル LLM・翻訳専用モデルの導入と、停止・解放の設定 | `llm.*` |
| デバッグログ | `debug.enabled` |

モデルの保存先を個別にできないのは、ComfyUI が全ユーザーで 1 つだから。

### B. 全体設定 + 個別で上書きできる

| 項目 | キー | 標準値 |
|---|---|---|
| テーマ | `ui.theme` | 今の既定(ダーク) |
| 言語 | `ui.language` | OS に合わせる |
| 画像の保存先 | §4 | アプリのデータ内 |
| AI サポートの送信先・モデル・外部サーバ | `assistant.provider` / `model` / `local_base_url` / `local_model` | 今の既定 |
| AI サポートの指示文・会話の自動削除 | `assistant.system_prompt` / `auto_delete` | 今の既定 |
| プロンプト翻訳の方式・モデル | `translate.provider` / `model` / `mt_model` | 今の既定 |
| 画像の形式変換の設定 | `convert.settings` | 今の既定 |

関連するキーは **組にして上書きする**(送信先とモデルが食い違わないように)。組は、AI サポートの接続(送信先・モデル・外部サーバ)、指示文、自動削除、翻訳、形式変換、テーマ、言語、画像の保存先。

### C. 個別のみ(本人の秘密・同意・作業の状態。全体設定を持たない)

| 項目 | キー |
|---|---|
| API キーと確認状態 | `assistant.api_key` / `key_verified` |
| 外部送信の同意、モデルの利用許諾への同意 | `assistant.consent` / `models.consents` |
| 画面の状態、生成フォームの下書き | `ui.state` / `generation.default_params` |
| 一括ダウンロードで前回選んだ場所 | `gallery.export_dir` |
| 名前・色・ロック | `app.db` の `users` |

ジョブ・画像・プリセット・会話などのデータは、従来どおりユーザーごと。

- 送信先を全体設定で外部サービスにしても、**同意と API キーは本人のものがなければ送信しない**(従来の条件を変えない)。

## 3. 画面(05 への追記)

- `/settings` の最上部で **[個別設定 | 全体設定]** を切り替える。その下にカテゴリのタブ(25)を置き、`?scope=user|global&tab=` で表す。省略時は個別設定。
- **全体設定**: A と B を表示する。「すべてのユーザーに影響します」と常に表示する。各項目に [標準値に戻す] を置く。
- **個別設定**: B と C を表示する。B の各組は次のどちらかを選ぶ。
  - **全体設定を使う**(既定): 現在の全体の値を読み取り専用で表示する。
  - **個別に設定する**: 値を入力する。選んだ直後は、全体の値が入っている。
- カテゴリ: エンジン(全体のみ)、保存先、AI サポート、表示、その他(デバッグは全体、ロックは個別、バックアップは個別)。中身のないタブは出さない。
- ナビのテーマ切り替えボタンは、今と同じく表示だけを一時的に切り替え、設定は変えない。
- ユーザー選択画面(ログイン前)は、全体設定のテーマと言語を使う。

## 4. 画像の保存先

### 4.1 場所の決まり方

| 状態 | そのユーザーの画像の場所 |
|---|---|
| 全体設定 = 標準値(アプリのデータ内) | `users/<ユーザーID>/images`(今の既定と同じ) |
| 全体設定 = フォルダ `R` を指定 | `R/<ユーザーID>/` |
| 個別設定 = フォルダ `P` を指定 | `P`(そのまま) |

- 全体のキーは `storage.images_root`(`app.db`。新設)。個別のキーは、今の `storage.images_dir` を使う。
- `R` の下は **ユーザー ID で分ける** ので、ユーザー同士のファイルは混ざらない。名前は変更できるので、フォルダ名には使わない(36 §3 と同じ)。
- 個別の `P` は、**ほかのユーザーの画像の場所、全体の保存先 `R`、アプリのデータ領域** と同じ・内側・外側にできない。ほかのユーザーの名前やパスは表示しない。

### 4.2 全体の移行(全体設定 > 保存先)

流れは 51 と同じ(移行先を選ぶ → 確認 → 実行 → 移行先が全体の保存先になる)。

- **対象は、全体設定を使っている全ユーザー**。ログインしていないユーザーと、ロックしているユーザーも含む(ファイルを移すだけで、内容は表示しない)。
- 個別設定のユーザーは対象外(個別設定が優先のため)。確認画面に「対象 N 人、個別設定のため対象外 M 人」と示す。
- 確認画面は、全員分の合計(ファイル数・容量・空き)と、ユーザーごとの内訳(名前と件数)を示す。
- **全員分のコピーが終わってから、全体の設定を 1 回で切り替える**。中止・失敗では、全員が移行前のままになる。切り替え後に、元のファイルをゴミ箱へ移す。
- 開始できない条件は 51 §5 に加え、対象ユーザーの DB が読めない、移行元が見つからない(画像の記録があるのにフォルダがない)。
- ほかのユーザーの DB は、移るファイルの一覧を得るために **読み取り専用** で開く。
- 移行先 `R` は、どの個別の `P` とも同じ・内側・外側にできない。`R/<ユーザーID>` の同名ファイルの扱いは 51 §4.1 のとおり。
- 標準値へ戻すときも、この移行を使う。
- 「移行せずに保存先だけ変更」は残す(全員に影響することを確認する)。

### 4.3 個別の移行(個別設定 > 保存先)

- [個別に設定する] でフォルダを選ぶとき、[全体設定に戻す] のとき、同じ移行の画面で **自分のデータだけ** を移せる(Q-445)。移さないと、それまでの画像が表示できなくなるため。
- すでに複数のユーザーが同じフォルダを使っている場合、参照画像・マスク(`inputs/`)は **コピーするだけで、元のファイルを残す**。`inputs/` はフォルダ単位で移すため、ほかのユーザーの分をゴミ箱へ移さないようにする。

### 4.4 モデルの移行

モデルの保存先は全体設定のみ。51 の移行をそのまま使い、画面を「全体設定 > 保存先」に置く。

### 4.5 ユーザーの追加・削除

- 追加したユーザーは、全体設定を使う(`R` を指定していれば `R/<ID>/`)。
- 削除では、作業スペースに加え、アプリが作った `R/<ID>/` も削除する(確認画面に場所を示す)。個別の `P` は今と同じく自動では削除せず、場所を知らせる(Q-446)。

## 5. 今の設定からの引き継ぎ

更新後の初回に行う。**画像のファイルは移さず、各ユーザーの見え方も変えない。**

- 全体設定は、すべて標準値から始める。
- B の項目で、ユーザーに保存されている値が **標準値と同じ** なら消す(全体設定を使う)。違えば個別設定として残す。今の [保存] は変更していないテーマや言語も書き込むため、そのまま残すと全員が個別設定になってしまう(Q-447)。
- **以前の版から引き継いだ画像の場所**(`{app_data}/images` に固定されたもの。36 §8): ユーザーが選んだものではないので、**全体設定を使うユーザー** として扱う。全体の保存先が標準値の間は、そのユーザーだけ場所が `{app_data}/images` のままになる。全体の移行を実行すると、ほかのユーザーと同じ場所に移り、この特例はなくなる(Q-448)。
- その他の `storage.images_dir` は、個別設定として残す。
- 言語の「OS に合わせる」を個別設定にできるよう、個別設定の「値がない」は **全体設定を使う**、値 `"auto"` は **OS に合わせる** とする。
- 引き継ぎは、ユーザーごとに一度だけ行う(そのユーザーの DB を最初に開くときか、全体の移行の確認で読むとき。読み取り専用で開く場合は、同じ規則で解釈だけする)。

## 6. 実装への影響

- **値の解決を 1 か所にまとめる**: 「個別 → 全体 → 標準値」を設定層で解決し、各サービスは解決後の値だけを使う。
- DB: スキーマの変更はない(`app.db` の `device_settings` と、ユーザーの `settings` にキーを置く)。引き継ぎの完了は、キーで記録する。
- IPC(04): 設定の取得は、解決後の値に加えて、B の組ごとの全体の値・個別設定の有無を返す。更新は `scope: "global" | "user"` を指定する。個別設定を消す操作を足す。AI サポート・翻訳・形式変換の各設定コマンドも同じ形にする。移行は `target: "imagesGlobal" | "imagesUser" | "models"` にする。
- 全体の移行中の排他は 51 §5 のまま(操作できるのはログイン中の 1 人だけ)。
- バックアップ(35・36): 「設定値」に含むのは、これまでどおりユーザーの値だけ(個別設定と C)。全体設定は含まない。復元しても、全体設定は変わらない。復元で個別の保存先が §4.1 の制限に当たる場合は、その項目だけを復元せず、全体設定を使う。
- 未コミットの 51 の実装は残し、この上に作る。

## 7. 実装の分割とテスト(M42)

1. A: 設定の解決層と引き継ぎ。
2. B: IPC と設定画面(個別 / 全体)。
3. C: 画像の全体移行・個別移行、場所の制限、ユーザー削除。
4. D: i18n、03・04・05・09・35・36、AI サポートの機能カタログ。

- Rust: 解決の優先順位、全体の変更が上書きのないユーザーだけに反映される、引き継ぎの各規則と一度だけの実行、全体の移行(複数ユーザー・個別設定の除外・特例の場所・中止で全員が元のまま・1 人の失敗で切り替えない)、場所の制限、共有時の `inputs/`、秘密と同意が全体設定に入らない。
- Vitest: 個別 / 全体の切り替えと、上書きの有無の状態。
- 手動(09): 2 人以上のユーザーで、全体の移行後にそれぞれの画像が表示される。

## 9. 実装時の差異・補足

- **個別設定の判定(§5・§6 を変更)**: キーの有無ではなく、組ごとの印(ユーザーの `settings` の `override.*`)で判定する。印がある組は、ユーザーの値だけを読む(無いキーは標準値)。このため、言語の「OS に合わせる」を表す `"auto"` は使わない。ある組のキーを 1 つ個別に書くと、その時点の全体の値を写して、組全体が個別設定になる。
- **引き継ぎの時期**: アプリの起動時に全ユーザー分を行う(ログイン時にも確認する。バックアップから戻した以前の版の設定のため)。完了は `scope.upgraded` で記録する。
- **以前の版の場所**: ユーザーの `storage.images_dir` を消し、`app.db` の `storage.legacy_images_user` に記録する。全体の移行で消える。「移行せずに保存先だけ変更」では残し、標準値に戻せば元の場所を使う。
- **古い版に戻す場合**: 引き継ぎ後のデータを古い版で開くと、「ユーザー 1」の画像の場所と、全体の保存先を使っていた場合の場所が分からなくなる。
- テーマ・言語は、[保存] を待たず選んだ時点で反映する。[保存] は ComfyUI の URL だけに残す。
- 形式変換の設定は、設定の「その他」タブに追加した。変換ページで値を変えると、個別設定になる。
- ローカル LLM と翻訳専用モデルの導入・管理は、全体設定の「AI サポート」タブに置く。
- 画像の保存先のフォルダが開けない場合(ドライブが外れているなど)も、ログインは続ける。
- IPC: 各設定コマンドの任意の引数 `scope`、`settings_scope_get` / `settings_scope_set` / `settings_scope_reset_global`、`user_delete_preview` を追加した。
- Vitest は、画面の場所の解釈(`scope-nav`)と切り替えの状態(`settings-scope-store`)を試験した。コンポーネントテストは追加していない。
