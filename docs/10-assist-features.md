# 10. 生成補助機能(顔補正・ControlNet)

Stable Diffusion WebUI 系の定番拡張である **ADetailer(顔補正)** と **ControlNet(構図・ポーズ指定)** に相当する機能を、ComfyUI のノードを使って gazooo に組み込む。

> ステータス: 🟢 承認済み(2026-11-19)
> 位置づけ: MVP(M0〜M5)の後に追加する **v0.2 の機能**。方針は 07 の Q-19〜Q-24 を参照。

## 1. 目的と方針

- **ワークフロー編集に慣れていないユーザー** を想定する。ノードグラフは見せず、生成画面のスイッチと数個のパラメータだけで使えるようにする。
- 実現方式は **組み込みプリセット**(02 §3.4 のとおり、ワークフロー JSON を Rust コードで組み立てる方式の延長)。ユーザー定義ワークフローのインポートは対象外(優先度を下げ、必要になった時点で別途設計する)。
- A1111 / Forge の拡張そのものの互換・移植は行わない。ComfyUI 側の対応ノードを呼び出すだけである。
- 対象モデル種別は **`sd15` / `sdxl` のみ**。Flux 系は両機能とも非対応とする(ControlNet / 検出器との組み合わせの検証コストが大きいため。将来拡張)。

## 2. 要件 ID

| ID | 機能 | 概要 |
|---|---|---|
| F-11 | 顔補正 | 生成した画像から顔(選択により手)を自動検出し、その部分だけを再生成して仕上げる |
| F-12 | ControlNet | 参照画像から輪郭・深度・ポーズを抽出し、生成の構図条件として与える |

## 3. 前提(ComfyUI 側の依存)

いずれもコアにないノード・モデルが必要で、ユーザー自身が ComfyUI に導入する。アプリは **導入の有無を検出し、無ければその機能のスイッチを無効化して導入手順を案内** する(GGUF ノードと同じ扱い。02 §3.4)。

| 機能 | 必要なカスタムノード | 必要なモデル | 検出方法(`/object_info`) |
|---|---|---|---|
| 顔補正 | ComfyUI-Impact-Pack、ComfyUI-Impact-Subpack(`UltralyticsDetectorProvider`) | 検出モデル(`models/ultralytics/bbox/` の `face_yolov8m.pt` など) | `FaceDetailer`、`UltralyticsDetectorProvider` の有無と、後者の `model_name` 候補 |
| ControlNet(Canny) | なし(コアの `Canny`、`ControlNetLoader`、`ControlNetApplyAdvanced`) | ControlNet モデル(`models/controlnet/`) | `ControlNetLoader.control_net_name` の候補 |
| ControlNet(Depth / OpenPose) | comfyui_controlnet_aux(前処理ノード) | 同上 | 前処理ノードの有無 |

- 前処理ノードの具体名は、固定した controlnet_aux のバージョン(08)で確認した次のものを使う(M7 で確定): Canny → コアの `Canny`、Depth → `DepthAnythingV2Preprocessor`(重みは `depth_anything_v2_vitl.pth`)、OpenPose → `OpenposePreprocessor`。
- Depth / OpenPose の重みは、controlnet_aux が **ComfyUI 側で初回実行時に取得する**(アプリではなく ComfyUI の通信。アプリ自身は、設定されたエンジン以外へ通信しない。例外は、ユーザーが明示的に使う AI サポート(11)とモデル取得(12)のみ)。オフライン環境では事前に ComfyUI 側へ配置する必要がある。
- ControlNet モデルは **ベースモデル(sd15 / sdxl)と一致するものを使う必要がある**。ファイル名からの自動判別は信頼できないため、アプリは種別でのフィルタをせず、フォームに注意書きを出す(不一致時は ComfyUI の実行エラーとして表示される)。
- ControlNet モデル・検出モデルの取得は、v0.4 のモデル取得ページ(12)から行える(それまでは手動で配置する)。
- 検出モデル(`.pt`)は Python の pickle 形式で、信頼できない配布元のものを読み込むとコード実行のリスクがある。導入手順の案内で「信頼できる配布元のみ使う」旨を注意喚起する。

## 4. 顔補正(F-11)

### 4.1 動作

1. 通常どおり生成(サンプリング → VAE デコード)する。
2. 検出モデルで顔を検出し、見つかった領域を切り出して拡大し、**同じモデル・プロンプトで再サンプリング(denoise 低め)** して元の位置へ貼り戻す(Impact Pack の `FaceDetailer`)。
3. **仕上げ後の画像だけ** をギャラリーに保存する(補正前の中間画像は保存しない。Q-22)。

顔が検出されなかった場合は、補正をスキップして元の画像をそのまま保存する(エラーにしない)。

### 4.2 パラメータ

| 項目 | キー | 既定 | 範囲 | 説明 |
|---|---|---|---|---|
| 有効 | `enabled` | false | – | |
| 検出モデル | `detector` | 候補の先頭(`face_yolov8m.pt` があればそれ) | `UltralyticsDetectorProvider` の `bbox/*` から選択 | `hand_yolov8s.pt` 等を選べば手の補正にも使える |
| 強さ | `denoise` | 0.4 | 0.05〜1.0 | 大きいほど顔が変わる |
| 補正用プロンプト | `prompt` | 空 | 任意 | 空なら本体のプロンプトを使う(例: 表情・目の描写を追加) |
| 検出しきい値 | `confidence` | 0.5 | 0.1〜1.0 | 詳細設定(折りたたみ) |

- ステップ数・CFG・サンプラー・スケジューラ・シードは本体の値を引き継ぐ(ユーザーに追加の項目を見せない)。
- `FaceDetailer` のその他の引数はアプリ内の固定値とし、公開しない(M6 で確定。Impact Pack は 08 §6.1 の固定コミットで確認):

| 引数 | 値 |
|---|---|
| `guide_size` / `max_size` | SD 1.5: 512 / 1024、SDXL: 1024 / 1536(切り出した顔領域を再サンプリングする目標サイズ) |
| `guide_size_for` | true(検出ボックス基準) |
| `feather` / `noise_mask` / `force_inpaint` | 5 / true / true |
| `bbox_dilation` / `bbox_crop_factor` / `drop_size` | 10 / 3.0 / 10 |
| `cycle` / `wildcard` | 1 / 空 |
| SAM 関連(`sam_detection_hint` ほか必須の 6 項目) | 使わない。既定値を渡す(`center-1`, 0, 0.93, 0, 0.7, `False`) |

- ノード ID は固定(検出モデル `20`、補正用プロンプト `21`、`FaceDetailer` `22`)。進捗の段階判定(§4.3)に使う。

### 4.3 ワークフロー上の位置

```
[ローダー] → [ConditioningSet(+ControlNet)] → KSampler → VAEDecode → FaceDetailer → SaveImage
                                                              ▲
                                       UltralyticsDetectorProvider ┘
```

- 進捗: サンプリングが 2 段階(本体 → 顔補正)になるため、`job://progress` の `phase`(`generate` / `face_detail`)で段階を示し、UI は「生成中」→「顔補正中」と表示する(04)。段階は、進捗を出したノードが `FaceDetailer` かどうかで判定する。

## 5. ControlNet(F-12)

### 5.1 動作

1. ユーザーが **参照画像** を選ぶ(ファイル選択、または「ギャラリーの画像を参照に使う」)。
2. 参照画像を生成サイズに合わせてリサイズ(アスペクト比が違う場合は **中央クロップ**)し、選んだ前処理(Canny / Depth / OpenPose / なし)で条件画像に変換する。
3. ControlNet モデルを通して、ポジティブ・ネガティブ両方の conditioning に適用し、サンプリングする。

「前処理: なし」は、既に線画・深度マップ・ポーズ画像として用意された画像をそのまま条件にする用途。

### 5.2 パラメータ

1 つの「ユニット」で表す。**v0.2 は 1 ユニットのみ**(配列形式にしておき、複数ユニットは将来拡張。Q-20)。

| 項目 | キー | 既定 | 範囲 | 説明 |
|---|---|---|---|---|
| 有効 | `enabled`(ControlNet 全体) | false | – | 顔補正と同様。無効でも設定は残る |
| 参照画像 | `image` | – | 必須 | アプリが保管する入力画像の相対パス(§6) |
| 前処理 | `preprocessor` | `canny` | `canny` / `depth` / `openpose` / `none` | 導入されているノードのものだけ選べる |
| モデル | `model` | 候補の先頭 | `ControlNetLoader` の候補 | ベースモデルと一致するものを選ぶ |
| 強さ | `strength` | 1.0 | 0〜2 | |
| 適用開始 | `startPercent` | 0.0 | 0〜1 | サンプリング全体に対する割合 |
| 適用終了 | `endPercent` | 1.0 | 0〜1(開始より大きい) | |

- ワークフロー(M7 で確定): `LoadImage`(30)→ `ImageScale`(31、生成サイズへ lanczos・中央クロップ)→ 前処理(32)→ `ControlNetLoader`(33)→ `ControlNetApplyAdvanced`(34)。ノード ID はユニットごとに 10 ずつずらす(30〜、顔補正の 20〜22 と重ならない)。`KSampler` の positive / negative は適用後の出力に付け替える。**顔補正のパスには ControlNet を適用しない**(構図条件は切り出した顔領域に合わないため、元の conditioning を使う)。
- 前処理の解像度は生成サイズの短辺(64 の倍数)。Canny のしきい値は固定(0.4 / 0.8)。
- **前処理結果のプレビュー** は v0.2 では提供しない(Q-23)。生成結果のギャラリー詳細に、参照画像を小さく併記する。

## 6. 参照画像(入力画像)の扱い

- 対象形式は PNG / JPEG(`image` クレートの有効な形式に合わせる。02 §3.2)。サイズ上限は 20MB、長辺 8192px まで(超過は `VALIDATION`)。
- 取り込み時に **画像保存先配下 `inputs/<uuid>.png` にコピー(PNG へ再エンコード)** する。メタデータは除去する。再現(「この設定で生成」)で同じ参照画像を使えるようにするため、元ファイルは参照しない。
- `params_json` には保存先からの **相対パス**(`inputs/<uuid>.png`、`/` 区切り)を記録する(03 の画像パスと同じ方針)。
- 生成時、Rust が ComfyUI の `POST /upload/image`(multipart、`type=input`)で画像を送り、`LoadImage` ノードで読み込む。送信するファイル名は uuid を含め、衝突・上書きを避ける。ComfyUI 側の `input/` に残るファイルは、アプリでは削除しない。
- ファイル選択ダイアログは **Rust 側** で開く(`tauri-plugin-dialog` の Rust API)。選ばれたパスをフロントエンドから受け取って読み込む設計にしないことで、「WebView から任意ファイルを読ませない」(01 セキュリティ要件)を保つ。
- `inputs/` の画像は、ギャラリー(`images` テーブル)には載せない。保存先の変更(04「保存先の変更」)では原寸・サムネイルと同様に移動の対象に含める。
- 孤立した参照画像(どのジョブからも参照されない)の自動削除は v0.2 では行わない(Q-24)。

## 7. 検証ルール(`job_enqueue`)

- `controlnet` / `faceDetailer` は **`sd15` / `sdxl` のときのみ** 指定可。Flux 系で指定されたら `VALIDATION`(`details.field`)。
- ControlNet: `units` は 0 または 1 件、`strength` は 0〜2、`0 ≤ startPercent < endPercent ≤ 1`、`image` が存在すること(無ければ `IMAGE_NOT_FOUND`)。
- 顔補正: `denoise` は 0.05〜1.0、`confidence` は 0.1〜1.0、`detector` は空でないこと。
- 必要なノードが ComfyUI に無い場合は `ENGINE_NODE_MISSING`(`details.node`)。フロントは事前に `engine_status.features` で無効化するが、投入時にも確認する。

## 8. UI

生成画面(05 §3)のパラメータパネルに、スイッチ付きの 2 つのセクションを追加する(スイッチを入れると設定が開く)。

```
│ 顔補正              [スイッチ]                │
│     検出  [face_yolov8m.pt ▾]  強さ [0.4]      │
│     補正用プロンプト(任意)[            ]      │
│ ControlNet          [スイッチ]                │
│     参照画像 [ファイルを選ぶ]                  │
│     [サムネイル]   前処理 [Canny ▾]            │
│     モデル [control_v11p_sd15_canny ▾]         │
│     強さ [1.0]  開始 [0.0]  終了 [1.0]         │
```

- スイッチが無効になる条件と表示:
  - モデル種別が Flux 系 → 「SD1.5 / SDXL のみ対応」
  - 必要なノードが無い → 「ComfyUI に ○○ が必要です」+ 導入手順へのリンク
  - 必要なモデル(検出モデル、ControlNet モデル)が 1 つも無い → モデルの置き場所を案内
- **ギャラリーの画像を参照にする**: 生成画面にピッカーは置かず、ギャラリーの詳細パネルの「参照画像に使う」から設定する(押すと取り込んで生成画面へ移動し、ControlNet を有効にする。Flux 系を選択中は取り込みだけ行い、有効にはしない旨を通知する)。生成画面には案内文を表示する。
- ControlNet を有効にしている間は、参照画像が未選択だと「生成」を押せない。参照画像の縦横比が生成サイズと 2% 以上違う場合は、中央を切り抜く旨を表示する。
- 前処理の選択肢は、導入されているノードのものと「なし」。選択中の前処理が使えなくなったら、使えるものへ自動で替える。前処理を変えると、名前に前処理名(canny / depth / pose)を含む ControlNet モデルへ自動で切り替える(モデルを直接選んだ場合は戻さない)。
- プリセット(F-08)、「この設定で生成」、ギャラリー詳細のパラメータ一覧は、これらの設定を含めて保存・復元・表示する。参照画像が欠損している場合は、ControlNet を無効にして復元し、トーストで知らせる。

## 9. 実装の分割(マイルストーン)

| M | 内容 | 前提 |
|---|---|---|
| M6 | 顔補正(F-11): ノード検出、`faceDetailer` パラメータ、ワークフロー拡張、UI、進捗の段階表示 | Impact Pack 系ノードと検出モデルが入った開発用 ComfyUI(08) |
| M7 | ControlNet(F-12): 入力画像の取り込み・保管・アップロード、`controlnet` パラメータ、ワークフロー拡張、UI | controlnet_aux と ControlNet モデルが入った開発用 ComfyUI(08) |

先に顔補正を実装する理由: 入力画像の取り込み・保管という新しい仕組みが要らず、変更範囲が小さいため。

## 10. テスト方針

- ワークフロー生成: 機能の有無(なし / 顔補正 / ControlNet / 両方)× モデル種別(`sd15` / `sdxl`)で JSON を組み立て、ノード間リンクの整合性をユニットテストで検証する(02 §3.4 の方針)。
- 検証ルール(§7)のユニットテスト。
- `/object_info` のパース(新ノードの候補・有無の検出)は、実機スモークテスト(08 §6)に追加する。
- 実機検証(Windows / macOS)の項目は、実装時に 09 へ追加する。

## 11. リスク

| リスク | 対策 |
|---|---|
| Impact Pack / controlnet_aux のノード仕様変更・依存パッケージの衝突 | 開発用環境ではコミットを固定(08)。`/object_info` で有無と入力を検証し、不整合は `ENGINE_NODE_MISSING` として案内 |
| Windows / Mac でカスタムノードの導入手順が異なる(特に ultralytics の依存) | 導入手順をアプリ内ヘルプと README に記載。Mac(MPS)での検出モデルの動作は実機で確認し、非対応ならその旨を表示 |
| 顔補正で VRAM / 時間が増える | 補正中の段階表示と、VRAM が少ない環境での警告(R-03 に準ずる) |
| ControlNet モデルとベースモデルの不一致 | 注意書き+ComfyUI のエラーの分かりやすい表示(06.1 の方針) |
