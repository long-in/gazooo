# 50. 生成フォームの 2 列化とスクロールの一本化(v0.51)

> ステータス: 🟡 レビュー待ち(2026-11-25)。承認後に実装する。

## 1. 現状の問題

- 生成ページのメインは「フォーム | 補助(右)」の 2 カラムで、**それぞれが別々に縦スクロール**していた。全画面にすると横の余白が大きく余るのに、フォームだけが縦に長く、縦スクロールが残る。
- フォームは 1 本の縦長の列(`generation-form.tsx`)で、広い画面でも幅を活かせない。

## 2. 方針

### 2.1 スクロールの一本化(軽微な修正として実施済み・未コミット)

- メイン領域のスクロールを **1 本** にする(左右で別々にスクロールさせない)。
- 右の補助(ワークスペース)は `sticky top-0` で上に固定。内容が画面高を超えるときだけ自身でスクロール。
- 全体は最大幅 110rem で中央寄せ。変更は `generate-view.tsx` のみ。

### 2.2 フォームの 2 列化(本設計の対象)

幅に余裕がある(`xl` = 1280px 以上)ときだけ、フォームを **2 列に分ける**。`xl` 未満は現行どおり 1 列。

| 列 | 内容 |
|---|---|
| 左(入力) | モード切替・プリセット・リセット/アシスタント・翻訳・プロンプト・ネガティブ・モデル種別/モデル・モデル詳細 |
| 右(調整) | サイズ・サンプリング(ステップ/CFG/シード等)・枚数・下書き・その他の詳細セクション |

- 生成ボタン(固定表示)はフォーム全幅の下部に残す。
- 右の補助(ワークスペース)は、`2xl`(1536px)以上でフォームの右の **3 列目** に置く。`xl`〜`2xl` 未満では、2 列化したフォームの **下** に回す(幅が足りないため)。
- 実装: フォーム内の既存ブロックを 2 つのラッパー `div`(`xl:grid xl:grid-cols-2 xl:gap-6`)に振り分けるだけで、状態・検証・送信処理は変えない。かんたんモードは項目が少ないので 1 列のまま。

### 2.3 レイアウトの全体像

| 幅 | 配置 |
|---|---|
| < 1024px | 1 列(フォーム → 補助) |
| 1024〜1279px | フォーム(1 列)| 補助 |
| 1280〜1535px | フォーム(2 列)、補助はその下 |
| ≥ 1536px | フォーム(2 列)| 補助(sticky) |

## 3. 影響範囲とテスト

- 変更: `generate-view.tsx`、`generation-form.tsx`(ブロックの並べ替えのみ)。IPC・DB・Rust に変更なし。
- 05(UI 設計)の生成ページの記述に、上記の配置を追記する。
- フォームの Tab 順は「左列 → 右列」になる(DOM 順 = 視覚順)。
- テスト: 既存の Vitest は変更なし。手動(09 に追加): 各幅での配置、スクロールが 1 本であること、Tab 順、かんたん / 詳細モード、Ctrl+Enter での生成。
